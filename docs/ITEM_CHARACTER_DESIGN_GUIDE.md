# R10.4：道具与人物设计

2026-10-19。在 [世界创作](WORLD_CREATION_GUIDE.md)之上接入独立设计草稿、局部补全、审阅确认和真实探索消费。与内置模板共用引擎、库存、人物请求及发布流程，不增加第二套游戏服务或Provider。

## 使用顺序

1. 娱乐 → 我的世界 → 所选世界，先填写或生成并保存世界草稿。R12工作台按目标分组，设计器仍为独立子页。
2. “物品规则与属性”声明装备槽；选择定性、轻数值或仅指定属性策略。指定属性例如 `durability / 耐久 / 格 / 0–5`，不隐式增加等级、血量或伤害。
3. 打开“道具设计”或“人物设计”。填写半成品描述，或选择示例创意；可新增，也可重新设计已有定义，玩家使用固定 `player` ID。点击“创建设计”后直接进入编辑，不调用AI。
4. 进入设计稿后选择当前字段，手动编辑，或选择生成范围，再确认当前模型、改写字段与可能费用；成功后自动保存设计，不自动加入世界。锁定按顶层字段生效，`profile`、`details`等复合字段整体锁定。一次只显示一个字段，私密 / 高级内容折叠。
5. 保存后切到“预览与确认”，审阅约束、属性、公开 / 本人 / 主持范围，勾选确认，点击“加入世界”。这一步只更改草稿，不发布、不发奖、不改旧局。
6. 道具纳入定义后，在世界的“道具定义与初始放置”单独选择实例、数量与归属（地点、NPC、玩家）。保存，再从“预览与发布”发布修订并创建新存档。地点物品要拾取，玩家初始物品不自动装备。
7. 已确认设计只读；继续改动请创建重新设计稿。没有当前存档热插入 / 世界原地升级，旧局仍固定旧修订。实际获取走独立的 [R10.4.1抽卡子页](ITEM_DRAW_GUIDE.md)，不是在设计确认时直接发奖。

## 世界绑定与确认边界

设计绑定的是**世界草稿版本及该版完整快照**，不是“永远使用最新版”。世界编辑版本与已发布修订是两个编号：设计→同版草稿确认→发布后形成不可变修订→新存档固定引用。

世界变化时，旧设计保留，生成与确认被拦截；明确“重新适配当前世界”会更新约束快照，保留设计内容与锁定，但不悄悄修复冲突，须重新审阅。不能通过客户端提交伪造快照、所属用户、稳定ID、已应用状态或库存指令。

确认在同一事务中锁定世界和设计、核对版本、编译校验合并后的世界，再更新草稿与应用回执。重复确认只返回已应用版本；两个设计竞争同一世界版本只有一个成功，另一稿需要重新适配，不覆盖较新设定。更改 / 生成已确认稿会拒绝。

## 道具、材料与真实可执行范围

设计包含名称、外观、类别、品质 / 等阶 / 评级、来源、工艺 / 历史背景、所属文化或势力、用途、限制、代价、交互对象、用途标签、允许的属性及装备 / 消耗配置。

- 定性：真实省略等级与数值属性，不只隐藏面板。
- 轻数值：有界等级及世界声明的可选属性；指定属性：只允许声明字段 / 单位 / 上下限，不强制等级。未声明或越界属性、无超自然政策冲突、无效装备槽均不能确认。
- 工具 / 装备 / 消耗品 / 材料共用定义与实例。材料支持标签与合法堆叠，不因此实现完整合成系统；唯一物品不允许堆叠，数量 / 所有权 / 槽位仍由原宿主校验。
- 确认设计只加入定义，零库存实例。初始放置是另一次明确配置，发布 / 新局后才生成实例；移动返回不会重复刷新已经拾取的初始物品。
- 本期可执行消耗规则只有地点 / 状态前置、消耗1份、增加 / 移除状态，前置失败不扣物品。装备、卸下、拾取、赠送沿用原动作。新增道具默认价格0，人物默认非商人，没有新增经济 / 战斗引擎。
- 自由描述的效果、用途、限制和代价是叙事资料，不自动执行任意承诺、攻击、数值增减或代码。属性目前是经校验的展示数据，不自动随使用递减；“耐久0–5”不等于已经实现耐久磨损系统。实际结算只能由明确支持的结构化动作产生。

## 人物的三类信息

| 范围 | 内容与消费者 |
|---|---|
| 公开卡 | 名称、身份、外观、公开背景、阵营、表达与公开近期目标；进入探索公开状态 / 卡片 |
| 人物本人 | 私密经历、价值观、边界、能力、需求、长期目标、本人理解的关系和明确授权资料；只进入该人物独立请求，有世界修订来源 |
| 仅主持 | 作者备注与未授权秘密；不会因为主持知道，就自动成为人物知道 |

NPC / 重要角色 / 玩家明确区分，重要角色须有价值观和需求。私密资料保留fact / rumor / legend / opinion；本人默认知道自己的资料，其他NPC仅在`knownBy`明确授权时获得。人物作者备注可以写“本人尚不知道的真相”，不应放进本人经历或本人秘密。

角色私密设定不进入公开卡、初始公开历史或其他人物请求；本人的合法知识保留类型与来源。关系描述只代表本人的理解，不改写对方认知或宿主关系值。玩家始终由用户控制，不调用人物AI替玩家决定思想 / 行动。设计者可以查看完整设计，不等于当前游玩人物全知。

运行时仍遵守R10.2的存档 / 修订 / 祖先分支 / 获知时刻 / 接收者过滤。主持只按当前地点 / 在场人物取相关私有资料，不把整份角色库每回合送入模型。超出上下文预算会报错，不回退成全知人物请求。规则不证明模型永不猜测；自然度与角色一致性需要人工语义验收。
