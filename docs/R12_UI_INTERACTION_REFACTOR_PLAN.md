# R12：以操作体验为中心的 UI 重构规划

2026-10-21。本文是待实施方案，不是已上线说明；阶段状态与优先级只维护在[产品主线](PRODUCT_MAINLINE_GUIDE.md)。本次只完成规划，不修改运行界面、不迁移数据、不调用收费模型。

## 1. 目的与问题判断

目标不是再次“统一圆角、加一些折叠”，而是让使用者不读开发文档，也知道：**现在在哪、下一步做什么、点击后会发生什么、结果到哪里找。**娱乐世界创作是首个试点，然后覆盖全模式。

R8已完成入口归属和独立子页，但“有层级、有折叠”不等于好用。当前问题包括：按钮缺少主次、文案过长、操作链断开、技术概念外露、说明代替交互设计。上一轮增加长说明与确认解决了部分歧义，却没有解决整体使用机制。本轮应减少需要用户记住的规则，而不是再加一层帮助面板。

以下是源码初查证据，不冒充已完成全站视觉审计或用户测试：

| 位置 | 当前表现 | 重构方向 |
|---|---|---|
| `web/components/ui/AppShell.tsx` | 全局导航之后还有用量区、模块导航，再进入功能内容 | 保留全局 / 局部两个明确层级；用量紧凑化，避免工具栏挤占工作区 |
| `web/components/game/WorldCreationWorkspace.tsx` | 创作起点保存后，还要另点链接进入；约18个同级分区链接 | 创建成功直接进入编辑；按用户目标分组，不平铺内部字段 |
| 同上 | 保存、重读、生成、发布等操作视觉权重接近；规则靠段落解释 | 明确当前主操作，次要动作归入上下文菜单，状态与按钮联动 |
| `web/components/game/WorldSectionEditor.tsx` | 单一 `worldButtonClass`；部分列表需高级JSON新增 | 语义化按钮；普通增删编辑用表单，JSON成为专家入口 |
| `web/components/game/AssetDesignWorkspace.tsx` | 世界版本、稳定ID、保存起点、确认纳入等概念集中出现 | 面向“设计→检查→加入世界”组织；技术信息按需查看 |
| `web/components/tasks/TaskWorkspace.tsx` | 已分子页，但目录首先要求用户理解多种功能分类 | 保留独立子页，以“今天做什么”为默认落点，管理 / 统计按需进入 |

## 2. 范围与不变项

- 覆盖七入口：对话、任务、学习、娱乐、内容、收件箱、设置。先完成娱乐关键流程，再迁移其他模块，不能只改娱乐后宣布“全站完成”。
- 保留 R8 模块归属：世界相关工具留在娱乐，打卡留在任务，记忆管理与学习宫殿按既有归属访问。允许上下文快捷链接，但链接到同一个正式页面，不复制第二套功能。
- 不增加新的世界引擎、任务系统、全局“万能工作台”或另一套移动业务；不借机重写数据库、API、Prompt或身份系统。
- 保留服务端数据、树形分支、固定世界版本、人物认知隔离、锁定、并发版本检查、草稿保护和生成请求标识。
- 不以UI简化为由自动发布、自动入库、自动重试收费请求；不恢复默认Token输出配额。显示实际用量，未知就说明未知。
- Web 与本地React / Capacitor共用业务和交互组件；按平台适配布局、返回键和导出，不双端各写一套。

## 3. 交互规范：先确定规则，再做页面

### 3.1 按钮、链接和状态

每个当前操作区只有一个主要动作。列表可以有逐行操作，但不能每行都用高强调按钮制造“按钮墙”。

| 类型 | 用途 | 表现 / 约束 |
|---|---|---|
| 主要按钮 | 当前最推荐的下一步，如创建世界、保存更改 | 实心强调色；同一操作区只保留一个 |
| 次要按钮 | 同步可做的其他动作，如预览 | 中性边框 / 弱强调；不与主操作争夺注意力 |
| 轻量动作 | 更多、复制、查看详情 | 文字 / 图标；重要含义不只靠图标和悬停 |
| 危险动作 | 删除、丢弃未保存修改 | 明确对象和后果，危险色只用于危险操作 |
| 导航链接 | 打开另一个页面或分区 | 使用链接语义，保留浏览器返回 / 新标签能力 |
| 状态标签 | 已保存、未发布、生成中 | 不伪装成可点击按钮；状态不只靠颜色 |

按钮采用“动词＋对象”，通常2–8个汉字；费用、解释和技术限定放在相邻说明，不塞进括号长按钮。图标只辅助识别，不能让用户猜测“这个符号是什么意思”。

禁用时必须在相邻区域解释原因，并给可执行解法，例如“还有2处未保存 → 保存更改”。不能只变灰、只用 `title` 或只在页面远处写说明。已保存且无改动时以状态为主，不要求反复点击保存。

### 3.2 确认按后果分级

- 浏览、切换已保存分区、查看预览：直接发生，不弹确认，不发AI请求。
- 普通保存：直接保存并显示结果，不再询问“是否确认保存”。
- AI生成：一次上下文确认，展示本次范围、哪些内容会被替换、使用的模型与可能费用；取消生成仍可能已有实际费用。不能为减少点击隐藏收费意图。
- 删除 / 放弃修改：确认对象、影响范围；可撤销的纯本地操作优先提供撤销，不能虚构服务端可恢复能力。
- 发布 / 加入世界 / 获取入包：结果预览中明确确认真实写入；不能把“生成建议”混成“已应用事实”。
- 替换分散的 `window.confirm` 为一致的对话框 / 手机底部面板。保留键盘焦点、Escape、返回键和取消路径；关闭弹层不等于取消已经发出的服务端操作。

### 3.3 状态与反馈

统一呈现：空白 → 编辑中 / 未保存 → 保存中 → 已保存；AI操作另有待确认 → 生成中 → 成功 / 失败 / 已取消。JSON未应用、版本冲突、锁定分别解释，不能都压成“不可操作”。这是现有状态的展示规则，不新建全局工作流引擎。

- 保存状态固定在操作区，成功不重复弹多个提示；失败保留输入，并提供明确的下一步。
- 生成中显示所选范围、可取消操作和紧凑用量状态，不用假进度百分比。没有供应商实际usage时显示“等待用量”，完成后更新真实数字。
- 字段错误贴近字段，并在汇总中提供“定位问题”；不能只显示英文JSON路径或一段“输出结构无效”。原始诊断保留在高级详情。
- 空状态告诉用户如何开始；只有主操作和一个必要说明，不显示所有未来阶段按钮。
- 不因收起面板销毁编辑，不因换分区自动丢弃修改；失败后不靠刷新页面恢复。

### 3.4 指引与视觉

- 指引分为：首次空状态、当前步骤一句提示、字段示例、异常处理。长篇技术手册从正常流程移出，帮助入口仍可访问。
- “服务端草稿”改为“我的世界”；内部版本号 / UUID / 请求号默认进入详情，发生冲突时再明确展示相关版本。
- 中性底色、克制强调色、明确标题 / 正文 / 辅助文字层级；减少卡片套卡片、边框套边框。不同模式可有轻量识别色，不各自发展组件系统。
- 统一间距、输入框、选中态、图标和圆角；先用关键页面桌面 / 手机原型比较，再冻结样式，不先做全站大规模换色。
- 手机常用触控目标按产品标准44–48px设计，输入字号通常不小于16px；焦点可见、状态不限颜色、不能依赖hover。以上是本项目标准，不声称等于某项认证。
- 折叠用于可选细节，不折叠必填项错误或当前阻塞原因；常规路径避免多层折叠嵌套。

## 4. 娱乐试点：从工程控制台变为创作工具

### 4.1 页面关系

```text
娱乐首页
├─ 我的世界 → 世界概览 → 创作工作台
│                         ├─ 世界设定 / 区域与地图 / 人物与社会
│                         ├─ 道具与事件（进入各自独立设计页）
│                         └─ 检查与发布
└─ 我的旅程 → 当前存档 → 探索主界面
                           └─ 地图 / 背包 / 人物 / 历史等上下文子页
```

创建世界、编辑设定、实际游玩是不同任务，不能混在一张长页面。世界概览显示最近进度和“继续编辑 / 继续旅程”，不强迫熟悉用户每次重走新手教程。地图等现有玩法不在本轮扩建。

工作台分组映射既有字段与正式查询路由，保留有效深链。作者备注、私密设定、结构编辑、修订历史属于高级区，不能误入公开预览或人物视角。

### 4.2 最短可理解的创建路径

1. **描述世界**：名称、粗略描述；提供少量题材中立示例，可选择AI补全或手动开始。创建成功直接进入新世界，不再“保存起点→另点进入”。
2. **完善设定**：显示可编辑草稿和缺项；默认打开当前相关部分。AI生成按明确范围确认，生成成功仍沿用现有自动保存语义，标注“已保存，待审阅”。手动修改显示“未保存”。
3. **检查与开始**：错误可定位，必需项与可选项分开；确认发布后提供“用此版本开始新旅程”的直接入口。不能要求用户记住修订号并到另一个列表寻找。

这三段是首次使用的方向提示，不是强制线性向导；已有世界可直接跳到任意可编辑部分。人物与初始事件保持可空，不能为了“进度100%”逼用户预写人物、谜案或主线。

“保存草稿 / 发布固定版本 / 创建存档 / 开始游玩”仍是不同业务事实。先通过连续页面与成功后主按钮连接；如后续合并为一次前端连续操作，必须先核对现有API幂等和恢复能力，逐步记录结果，失败后定位已完成步骤，不能承诺跨请求原子完成或重复建存档。需要新API时单列实施范围。

### 4.3 关键按钮与文字改造样例

| 当前文字 / 机制 | 计划显示 | 相邻说明或结果 |
|---|---|---|
| 保存创作起点（不调用AI）＋进入已保存草稿 | 创建世界 | 只保存描述；成功直接进入编辑器，不调用AI |
| AI生成完整草稿（需确认费用） | 生成草稿 | 点击打开一次范围 / 费用确认，不立即付费调用 |
| 确认调用AI并保存结果 | 开始生成 | 确认面板已列出改写范围；结果自动保存，尚未发布 |
| 从服务端重读 | 更多 → 重新加载 | 有未保存内容时才确认放弃，不清空数据库 |
| 锁定此部分，AI不得重生成 | 保护此部分 | 辅助说明“AI不改写，仍可手动编辑”；状态可见 |
| 确认发布当前草稿 | 发布版本 | 在检查页执行；成功后给“开始新旅程”入口 |
| 确认纳入世界草稿 | 加入世界 | 明确加入哪个世界；不会直接入背包或改旧存档 |
| 应用到表单（尚未保存） | 应用修改 | 仅在高级结构编辑中；明确仍需保存，正常流程不碰JSON |

“生成全部 / 生成当前部分”用范围选择器＋一个生成入口表达，不能把覆盖整稿藏进不显眼的默认项。已有内容、锁定和道具覆盖约束照常执行。

### 4.4 工作区布局草图

```text
桌面：全局侧栏 │ 娱乐 / 我的世界 / 世界名称                 更多
              │ [世界设定] [地图] [人物] [道具与事件] [检查]
              │ 局部目录 │ 当前表单与示例 │ 按需打开的预览
              │ 未保存更改       用量摘要        [保存更改]

手机：[菜单] 世界名称                          [更多]
     [当前分区：世界设定 ▾]        已保存
     当前表单：先内容，再可选细节
     ……
     用量摘要 / 当前阻塞原因         [当前主操作]
```

桌面预览不是强制三栏；小屏只留工作内容，分区索引用底部面板。底部操作区需适配软键盘、安全区和长错误提示，不能挡住字段 / 最后一条消息。最终像素与颜色由R12.1原型确定，此图只表达层级。

### 4.5 普通表单与高级能力

- 地点、公开人物、史料等常规列表提供新增、编辑、删除和引用选择，不再要求用户为常规任务手写JSON。
- 对象名称为主，稳定ID作为可查看信息；引用失效时提示具体对象，不偷偷删除关系。
- 表单仍消费同一领域契约 / 校验器，支持字段须完整往返；未提供图形编辑的高级字段要明确保留，不能一次保存静默丢失。
- 道具、人物、事件、抽卡设计共享“描述→编辑 / AI补全→检查→确认应用”的视觉与反馈模式，但不把不同业务强塞进一个万能表单。
- 游玩界面以行动和回复为主体，道具 / 地图 / 人物详情按需进入；普通NPC自然相遇与重要角色卡保持区别，不把作者全知资料展示成角色知识。

## 5. 其他模式的改造目标

| 模块 | 默认主要任务 | 本轮改造重点 |
|---|---|---|
| 对话 | 直接开始 / 继续对话 | 输入区与消息为主，模式切换有清楚选中态；历史、分支、引用、导出按上下文访问，不把所有工具铺在标题下 |
| 任务 | 看今天、执行、打卡 | 今日行动与创建入口优先；提醒、完成、请假 / 补卡、统计明确区分；管理配置进入子页，保留滚轮时间与通知状态 |
| 学习 | 选材料开始学习 | 背书 / 解题入口说明输入和产出；复习进度、检查结果、资料维护各自独立；不混淆学习宫殿与全局记忆管理 |
| 娱乐 | 继续旅程或创作世界 | 按第4节实施，再迁移存档、道具、人物、事件与抽卡流程 |
| 内容 | 阅读 / 收藏最新内容 | 阅读优先；订阅 / 推荐偏好为次级；生成明确收费意图，结果仍进入现有收件箱，不复制数据 |
| 收件箱 | 处理未读与查看来源 | 通知类型、时间、已读、跳转对象清楚；不把“提醒送达”显示成“任务完成” |
| 设置 | 找到需要调整的一类配置 | 按模型、记忆、声音、连接 / 设备等分组；配置页才展示技术细节；保存成功 / 连接失败 / 尚未配置明确区分 |

用量采用“操作附近的紧凑摘要＋可展开详情＋设置内汇总”。不能以界面简洁为由撤掉用户要求的现场用量，也不在未调用AI的每一页展开完整技术统计。后台任务用量归属对应结果，不冒充当前前台操作。

## 6. 技术实施与删旧规则

1. 沿用 Next.js / React / Tailwind、共享 `AppShell`、`Drawer`、`AppLink`、`appHref` 与 `useAppQuery`；不引入第二套路由或APK专用业务页面。
2. 小范围建立语义按钮、字段提示、状态反馈、操作栏、确认面板；优先在现有组件目录实现。重复使用或明确复杂交互才抽组件，不先造大组件库 / 动态表单平台。
3. 优先调整 `AppShell` 的层级与用量摆放，再对世界工作台做一个贯穿流程；局部布局不能依赖全局覆盖CSS。共用变量与语义组件替代分散的按钮类字符串。
4. 世界表单按分区拆视图，操作与服务端契约保持单一实现。可提取已有重复的请求 / 状态处理，不为了UI重构重新包装全部API或建立全局状态容器。
5. 替换一处、验证一处、移除被替换呈现与专用样式；不长期保留“旧UI / 新UI”切换、不新增旧版协议兼容层。短期未迁移模块可存在，但要有清单与结束条件。
6. 有效现用深链仍走正式路由；不为废弃别名恢复通用兜底。草稿、版本、生成请求、恢复诊断与导出功能不能在拆视图时丢失。
7. 默认无依赖 / 数据库变更。若现有弹层能力不足，再以实际问题评估最小依赖、许可证与React / WebView兼容；不直接整套安装组件框架。

## 8. 验收方式与具体场景

### 8.1 可用性门槛

以下是计划目标，不是已经测得的成绩：

- 创建描述提交后自动进入编辑，取消“保存后再找入口”的一步；找到某分区通常不超过两次局部导航操作。
- 每个页面能直接识别主要任务；每个关键按钮可回答“做什么、影响哪里、结果在哪里”。短文案由相邻说明补全，不靠猜测。
- 在360 / 390 / 768 / 1440px检查布局；正常首屏能开始处理内容，不先滚过重复导航、长警告和技术面板。200%缩放、长名称、空列表与百项列表不整页溢出。
- 键盘可以到达所有动作；焦点、错误关联、弹层关闭与恢复正确；触屏无需悬停得知禁用原因。
- 用真实操作前后对比评价，不以截图“无溢出”或单元测试全绿代替好用。由作者实际走一次关键旅程，记录卡点；尚未人工确认的视觉效果标注未签收。

### 8.2 必测旅程

1. 空白创建：粗描述→明确生成 / 手动选择→审阅→发布→开始探索；NPC与初始事件为空仍可继续。
2. 修改已有世界：保护一部分→改另一部分→保存；重生成范围正确，旧存档不升级。
3. 错误恢复：字段不合法 / 模型结构失败 / 请求超时；定位并修复，输入保留，不自动重复收费。
4. 未保存离开、版本冲突、生成中取消、重复点击、刷新与返回；不能丢稿、重复应用或把未知用量写成零。
5. 道具 / 人物 / 事件设计确认，以及固定池 / 关键词抽取→确认入包；清楚区分生成、保存、应用、获得。
6. 对话发送与分支、任务创建与打卡、学习材料→学习→结果、内容→收件箱结果、设置保存 / 连接失败。

逐阶段做受影响单元 / 组件 / 浏览器测试，优先按可访问角色和名称定位，修改旧长按钮断言但保留业务后果断言。模拟Provider使用合成数据；UI验收默认不花模型费用。跨层 / 封版再按风险运行全量、Web / React构建、Docker与APK检查，不给每次文案修改叠加全量流程。
