# ADR-065：PostgreSQL 知识资料生命周期与显式个人来源删除

- 状态：Accepted
- 日期：2026-10-16
- 阶段：R5.2

## 决策

- 复用模块化单体、PostgreSQL、Drizzle Repository、Zod、共享 React 页面和现有文件导出适配器。集合/文档/当前版本分段确有真实 CRUD 需求，新增三表而非把长文塞进 MemoryItem 或插件 64 KiB 存储。
- 资料按 owner 与固定模块归属；复合外键禁止集合与文档 owner 错配。管理读取先过滤 owner，列表只返回元数据，来源网址不触发网络。管理 API 不授予模型/插件读取权限。
- 导入使用显式 sourceKey，同内容/元数据重复返回原记录，变化须走 expectedVersion 更正。锁集合→文档，同一事务换正文/分段并更新集合版本。失败全部回滚，删除级联清理分段；当前无需异步索引清理器。
- 保留原文和 LF 行号、标题锚点、文档及分段 hash/version。长行按 Unicode 码点切分。源修订和处理策略分开记录，后续 RAG 必须重新校验权威根来源。
- 已确认个人事实与原始证据分离：清证据不等于忘记事实，忘记事实清对应候选副本，删除对话默认保留事实但清除证据；删除对话及关联事实必须显式选择。旧客户端可继续调用无 body DELETE。
- 本次不接模型/RAG、不调用外部 Embedding、不自动复制资料到学习/游戏状态。也不批量擦除历史孤立证据或自动做语义矛盾判定，避免未告知的数据变更与错误推断。
- 部署前真实备份在隔离 PostgreSQL 恢复并演练 up/down；不改旧迁移 checksum，不以删卷代替回退。新资料产生后不能盲目 down。

## 结果与取舍

用户现在能导入、查看、更正和删除自己的资料，为 R5.3 查询提供真实可版本化数据。纯文本/Markdown、小规模配额和确定性行定位先可用，富媒体、分词/语义切块和向量方案按后续评测决定。

物理删除当前分段保证没有在线旧段残留，不保证擦除 Provider 请求/用户导出/旧备份，也不会让已打开的其他客户端瞬间清屏。固定单用户部署不升级成未经验证的多用户体系。完整规范与保留项见 [使用指南](../KNOWLEDGE_LIBRARY_GUIDE.md)。
