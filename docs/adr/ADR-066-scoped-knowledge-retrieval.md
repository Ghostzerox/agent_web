# ADR-066：显式选域的词项检索与版本引用

- 日期：2026-10-16
- 状态：采用（R5.3 首期）；Embedding 待开发
- 承接：ADR-064 分域策略、ADR-065 资料生命周期

## 背景

R5.2 已有用户真实资料集合、当前版本文档/分段，缺少聊天选取与引用。个人 Memory 的中文二元组算法不能直接充当知识库 RAG；不能只改 Prompt 声称已读文档，也不能默认向外部 Embedding 发送私人全文。

## 决策

1. 复用 PostgreSQL 和现有 Model API/Prompt Envelope/Verifier，不增加向量服务、Agent 循环或新 npm 依赖。先实现内置分词+有限别名+SQL 词项粗筛+加权排序；最多五段，预算含引用元数据。
2. 前端 ID 仅表达选择，服务端从真实会话解析模式/问题，在正文查询前限制 owner/模块/集合。独立业务生成器不假装已全部接入；不给插件新增隐式读取能力。
3. 资料模式与网络搜索互斥。用户知道片段将发给其配置的模型，但私人问题不发送给网络搜索服务。无结果明确说明，超候选上限要求缩小范围。
4. PromptRun 事务锁集合并复核根版本/hash、片段 hash、会话模式/分支；现有资料更正/删除遵循集合锁顺序。无跨请求正文缓存，先检查权威源而非相信旧引用。
5. 引用沿用 `[S]`，增加严格知识元数据与版本化本地链接；历史引用不存第二份 excerpt。原版本不存在时明确失败，不返回新版正文冒充。历史回答/导出/备份可能保留原文，删除资料不等同删除这些副本。
6. 新审计列只存元数据，Composer 版本按是否实际有资料层区分；旧 Prompt 导出兼容，资料默认脱敏。新列迁移单独备份/恢复/up/down 演练，不改历史 checksum。

## 验证与权衡

固定 80 合成查询保留首轮失败和最终结果：通用问句处理及更严格粗筛提高召回并修复压力候选上限，不改金标。当前总体 90.91%，隐含改写仍漏四项。工程样例已被开发者查看，不能冒充冻结盲测或模型正确率。分别记录纯排序、PGlite SQL 与真实 Docker 接口验证，费用 0。

ILike 扫描适合当前个人规模，不保证大数据规模；泛查询超过 1,000 段拒绝，后续有证据再建设索引/语义召回。未评测向量方案，不得下结论“没有价值”。模型引用仍需人工核对，版本追踪不能证明原文真实性。事务提交后的并发删除不能撤回远端调用。
