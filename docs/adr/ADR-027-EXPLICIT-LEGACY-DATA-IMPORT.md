# ADR-027 显式导入浏览器旧会话并切换服务端事实源

## 状态

已被 R9.2 取代：旧浏览器导入退役，localStorage 不读取、不迁移、不清空。下文仅保留原决策背景，当前见 [R9.2报告](../reports/R9_2_REPORT.md)。

## 背景

Phase 0 会话保存在每个浏览器的 `agent_chat_sessions`。自动上传会违反用户预期，继续双写 localStorage 与 PostgreSQL 又会产生冲突、重复和不可解释的事实来源。树形消息还要求在 ID 改写后保持父子关系和活动分支。

## 决策

- Chat 运行时只使用 PostgreSQL Conversation API 作为会话事实来源。
- 浏览器启动时可以读取旧会话用于迁移提示，但必须由用户明确确认后才提交。
- 服务端对树结构和输入上限做完整校验，只允许展示角色。
- 旧 Message ID 映射为新 UUID；父节点与活动叶通过映射保持。
- 每个来源会话写入独立事务，并用唯一导入收据实现幂等。
- 客户端只在服务端确认成功后删除旧 localStorage 数据。

## 备选方案

### 自动迁移

操作更少，但会未经确认把浏览器历史上传到服务端，拒绝。

### 永久双写

短期兼容，但必须解决跨设备冲突、失败补偿和两个树版本，复杂度大且没有长期价值，拒绝。

### 复用旧 ID 作为数据库主键

旧数据不保证 UUID、唯一性或可信度，会把浏览器格式冻结进服务端 Schema，拒绝。

## 后果

- 数据归属清楚，刷新和连接同一服务端的设备可以读取同一会话树。
- 导入失败可安全重试，重复提交不会复制。
- 导入收据增加一张表和一条迁移。
- 当前没有增量同步；确认导入后，旧 localStorage 只作为已结束的迁移源。
