## 1. 现在能做什么

“记忆”页同时提供知识资料库、已确认个人记忆和候选审核。资料不是个人事实，也不是高优先级指令。R5.3 已接入手动检索与聊天显式选资料：导入本身不调用模型，选择集合并发送问题才把命中片段交给配置的 Provider。

### 知识资料库

1. 创建集合，选择专业问答、反思、新闻、阅读、任务、背书、解题或娱乐规则域。集合的模式不能直接修改，防止未来已有授权/索引随改名跨域。
2. 在集合中粘贴文本，或选择本地 UTF-8 `.txt`、`.md`、`.markdown`。选择文件只在本地读取；点击“保存导入”才上传。
3. 填写标题与来源标识，可记录来源网址。网址仅作元数据，不联网抓取，不接受账号密码或非 HTTP(S) 地址。
4. 保存后查看文档版本、来源修订 hash、分段标题与原文行号。原文按 BOM/换行规范化为 UTF-8/LF，HTML 作为文字展示，不执行。
5. 相同集合、相同来源标识与相同内容/元数据重复导入返回原文档；相同标识但内容不同提示冲突，不偷偷覆盖。请打开原文档后“保存文档更正”。
6. 更正带 expectedVersion，同一事务替换正文与全部旧分段。版本冲突保留本地编辑框，可先导出草稿，再重新打开最新版本合并；不会自动替用户选择版本。
7. 删除文档同时物理删除其全部分段；删除集合级联删除全部文档/分段，必须确认。集合版本随文档导入/更正/删除递增，旧删除对话框不能无意删掉新资料。

“导出当前正文”保存当前编辑内容，不是数据库完整备份，不包含全部来源/集合元数据。导出文件和旧备份不随在线删除自动擦除。

### 个人记忆与来源

| 操作 | 正式记忆 | 候选/证据副本 | 原对话 |
|---|---|---|---|
| 修改记忆/有效期/固定 | 新版本生效；仍按相关性和 TTL 检索 | 保留既有来源，除非显式清除 | 不变 |
| 保留记忆，清除来源证据 | 独立保留，版本递增、来源链接置空 | 清空 quote 和原候选正文/原因中的证据，保留非原文占位状态 | 不变 |
| 永久删除记忆 | 删除，不能再检索 | 同事务删除对应 candidate，不留下可在候选列表读出的旧副本 | 不变，原消息仍可被用户打开 |
| 聊天页删除对话（兼容旧客户端默认行为） | 已确认事实独立保留 | 删除未关联事实的候选，保留项的 quote/原候选内容与来源链接被清除 | 删除全部消息和对话 |
| 记忆页“删除原对话及关联记忆” | 删除仍关联该对话的全部事实 | 清理该对话候选/证据 | 删除全部消息和对话 |

来源操作都有确认提示；“打开来源对话”只跳到对应会话，不调用模型。记忆内容可筛选；同类记忆可能并存，候选的完全重复校验、乐观版本冲突与人工来源核对保留，**尚未提供自动语义矛盾判定或 AI 自动合并**。

已主动解除来源关联的记忆成为独立事实，不再属于“删除原对话及关联记忆”的关联集合，应在记忆页另行管理。原对话、已导出文件、数据库备份是不同副本，删除提示不能被理解为远端 Provider 已撤回数据。

## 2. 数据、预算与接口

新增 PostgreSQL 表，不在 localStorage 存持久资料：

```text
knowledge_collections (owner, module, version)
  └─ knowledge_documents (sourceKey, text, source metadata, revision hash/version)
       └─ knowledge_chunks (documentVersion, ordinal, heading, start/endLine, text/hash)
```

- 集合与文档通过 `(collectionId, userId)` 复合外键保持同 owner；分段依赖文档 `ON DELETE CASCADE`。
- 每次导入/编辑先锁定自己集合，再处理文档；管理读取按真实 owner 筛选。列表不返回文档正文；打开指定文档才返回正文与当前版本分段。
- 最多 50 集合，每集合 100 篇；每篇最多 100,000 UTF-16 字符、300,000 UTF-8 字节、256 分段。超限明确报错并回滚，不静默截断。
- 初始 `lines/r5.2-v1` 分段按标题和长度切分，无模型/向量/收费重排。普通段约 1,800 字符，超长行按 Unicode 码点切分，不断开代理对；长行的多个片段可以共用同一原文行号。这是定位预处理，不宣称语义最优切块。
- 文档修订 hash 为内容及标题/来源/格式/策略等语义元数据的稳定 JSON SHA-256；分段 hash 为片段文本 SHA-256。更正后的原文/片段 version 绑定，旧片段在事务提交后不存在。
- 管理 API 返回 `no-store` 与请求 ID，不记录私人正文；严格 Zod 拒绝伪造 userId、集合域改写、非法 URL/格式和缺失版本。
- 现有固定 `LOCAL_USER_ID` 保留；这不是新增多用户认证。管理权限不等于模型读取权限，插件 v1 没有因此获得知识集合或全局记忆能力。

路径（相对于 `/api/v1/knowledge`）：

| 路径 | 方法 | 行为 |
|---|---|---|
| 根路径 | GET / POST | 列集合 / 创建集合 |
| `/collections/:id` | PATCH / DELETE | 修改标题说明 / 删除集合，带 expectedVersion |
| `/collections/:id/documents` | GET / POST | 文档元数据列表 / 显式导入 |
| `/documents/:id` | GET / PATCH / DELETE | 原文与定位 / 版本更正 / 删除 |
| `/search` | POST | consumer/集合/查询，经 owner 与模式校验的词项检索，不调用模型 |

原文 GET 可带 `?version=N`；版本不存在时返回 404，不读取最新版正文冒充旧来源。

既有 `PATCH /memories/:id` 增加可选 `clearSourceEvidence`。既有 `DELETE /conversations/:id` 支持可选 JSON `{deleteRelatedMemories:true}`；无请求体继续兼容旧客户端，保留确认事实但清除该次来源的证据副本。

## 3. 迁移与回退

迁移 `0028_knowledge_library.sql` 增加三表，迁移数量由 28 变为 29。不改旧迁移字节和 checksum，不迁移/重写现有个人事实，不自动擦除过去已经失去来源的历史证据。

本次部署前已生成真实数据库逻辑备份，并在无端口/无持久卷的隔离 PostgreSQL 16 中实际恢复、执行 up/down 演练；测试容器随后移除，备份仅留本地忽略目录。验证结果见报告。备份包含私人数据，应保密保存。

`scripts/selfhost-backup.ps1` 新增可选 `-EnvFile`，支持工作树复用原部署环境文件，默认路径兼容原流程。示例：

```powershell
.\scripts\selfhost-backup.ps1 -EnvFile 'D:/Visual Studio Code/project/agent_web/.env.selfhost'
```

回退首选兼容应用版本，保留新表与备份；down 会删除新增知识资料，必须先导出/备份并明确批准。不能用 `docker compose down -v` 当回退，不自动将旧备份恢复覆盖现有数据。当前物理删除无需额外后台清理；未来新增索引/摘要时，必须按 R5.1 根来源有效性先禁读，再处理派生副本。

- 背书/解题知识集合目前不自动复制为插件材料；游戏规则集合也不自动进入剧情，后续通过明确宿主流程连接。
- 目前仅文本/Markdown；不支持 PDF/OCR、Office、自动网页下载、图片解析或任意文件。失败原因可见，不伪造导入成功。
- 历史已失去来源链接但仍保存的 candidate 证据未在迁移时批量清除，可用记忆页显式清除/删除；尚未引入语义冲突识别。
- 服务端删除不追溯清空其他客户端已经打开的正文、已导出文件、旧备份或已发到 Provider 的请求；这不能等同“所有副本已擦除”。华为文件选择/本地导出真机体验待用户验证。
