# R5.3：检索与来源引用

日期：2026-10-16。首期词项 RAG 已接入；不是向量检索，也不是全部 R5 已完成。实现与测量见 [交付报告](reports/R5_3_REPORT.md)、[ADR-066](adr/ADR-066-scoped-knowledge-retrieval.md)。

## 使用方法

1. 在“记忆 → 知识资料库”创建集合，导入文本或 UTF-8 Markdown。材料管理规则沿用 [资料库指南](KNOWLEDGE_LIBRARY_GUIDE.md)。
2. 可直接输入“检索本集合”，点击“检索资料（不调用模型）”：只请求本机后端，不请求搜索服务、模型或 Embedding。结果显示片段、版本、原文行号和本次耗时；点击结果打开该版本原文。
3. 在聊天中展开“本次使用资料库”，勾选同模式集合，再提问。自动/专业使用专业集合，反思使用反思集合，娱乐聊天使用娱乐规则集合；陪伴模式不读取知识集合。最多选 10 个，选择只留在本页对应会话中，刷新需重选。
4. 服务端用数据库保存的当前问题检索，选中片段会发送给你配置的模型服务。**本机检索不代表模型离线**。此请求不调用联网搜索，即使原搜索按钮是“自动/联网”，也不会把私人问题交给搜索服务；未选集合的原有流程不变。
5. 回答使用 `[S1]` 等引用，展开“参考来源”可跳回原文、指定版本和行号。刷新聊天仍保留引用。引用证明片段出处，不证明模型结论正确；没有依据时应明确说明，未知引用编号会触发现有 Verifier 提示。

独立 GameSession、新闻/书单生成器、任务执行器、学习插件本轮未自动绑定知识库；八类集合可在资料页手动检索，工作流特化留 R5.5。没有静默扩大 Plugin API v1 权限。

## 数据流与边界

```text
用户选择集合 → 真实会话模式/问题 → owner + 模块 + 集合过滤
  → 当前文档版本/片段 → 词项候选 → 排序/去重/预算
  → 调用前事务复核 → 资料上下文 → 模型回答 → 版本化引用
```

- `lib/repositories/knowledgeRetrievalRepository.ts`：在查询正文前解析真实 owner/模块/集合；当前固定单用户 `LOCAL_USER_ID`，不是新建多用户认证。聊天不相信客户端自报的查询或模式；原始其他分支消息不属于知识集合，不会跨分支做资料召回。
- `lib/knowledge/retrieval.ts`：内置 `Intl.Segmenter` 中文分词、NFKC 归一化、少量版本化中英别名、标题/段落/正文加权与词项稀有度。别名不是通用语义理解；SQL 粗筛使用 ILIKE，不是中文 FTS/pgvector。SQL 未建立归一化索引，全角等特殊书写仍可能粗筛漏检。
- 查询最多 500 字符、24 个有效词项；聊天从真实问题取前 500 字符。组合问句按连接词拆组，至少覆盖一组 60% 词项才成为候选。过于泛化超过 1,000 段时明确要求缩小范围，不静默截断冒充“未找到”。
- 最多 5 段、每段最多 500 Unicode 码点，并受已有模块预算约束（专业 1,800、反思 900、娱乐 1,200 估算 Token；其他模式沿 R5.1）。估算包含证据 JSON 与引用元数据，不包含固定指令前缀；不是 Provider 计费 Token。完整请求仍执行输入上限检查。
- 无结果不转去搜索私人问题；上下文明确“暂无依据”，不把一般知识冒充查到的材料。没有第二模型裁判、付费重排或额外模型摘要。
- `promptRunRepository.ts` 在事务中锁定会话与按序集合，复核活动分支、模式、文档版本/hash、片段 hash；更正/删除竞争时拒绝本次旧来源调用。事务提交后发生的删除无法撤回已发送请求。

## 来源、更正和删除

引用保存 document/chunk/collection ID、版本、根 hash、行号及本地受限链接 `/memory?document=…&version=…&line=…`。引用必须与其结构化元数据一致，不能借引用插入任意本地地址。聊天历史不重复保存资料 excerpt；标题和定位仍是私人元数据。

更正用 R5.2 原事务替换旧片段，删除级联清理；下一次检索只读当前版本，没有跨请求正文索引或缓存待清理。打开旧引用只允许其原版本：已更正/删除返回提示，不把新版冒充旧版。手动从文档列表打开可查看最新版。

**删除资料不会删除历史 AI 回答中已引用的文字**，也不会清除其他客户端已打开的文本、用户导出、旧备份或远端请求。需要另行管理这些副本；不宣称全副本擦除。

Prompt Envelope 的资料层为 `source: knowledge`，仅有资料时 Composer 使用 `r5.3/knowledge-context-v1`，旧请求版本不变。Prompt 导出默认脱敏资料/个人记忆；显式勾选“包含个人记忆上下文（含私人资料）”后可导出完整请求。注意用户消息或 AI 历史本身也可能含原文，脱敏资料层不等于自动清理整个会话。

新增 `prompt_runs.knowledge_retrieval` 只存策略/集合/来源版本、rank/score、耗时/预算等审计元数据，不存问题、标题、片段正文。迁移 `0029_knowledge_retrieval_audit.sql`，历史行 NULL，不改旧迁移；down 只移除新审计列，但会丢该列审计，生产回退仍需先备份和批准。

## 检索效果与后续

固定 80 合成查询在 100 篇/1,000 段和 10 倍压力层总体 Recall@5 均为 90.91%；改写类 8/12，另 4 个隐含语义问题未命中。无答案 0/12 误召回，越域/旧版反例未检出错误来源。它是人工编写、开发中已查看的工程回归集，**不是盲测或真实模型正确率**。真实 SQL、纯排序、网络耗时分开报告。

Embedding/混合召回保留待开发；当前漏检证明仍有需求，但本轮未发送私人材料、未安装向量依赖、未声称向量方案无收益。下一阶段按主线进入 R5.4 分支摘要，与 R1.3 共用实现；不默认开启付费调用。
