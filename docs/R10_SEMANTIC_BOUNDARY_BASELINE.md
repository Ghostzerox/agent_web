# R10.1：语义与边界基线

状态：2026-10-19，语义规范、现状审计与离线基线已建立。本文定义后续实现必须遵守的语义，不宣称新 DTO、创作系统、人物隔离或抽卡已经上线。任务拆分见 [R10规划](ENTERTAINMENT_CREATION_AND_CHARACTER_PLAN.md)，排序只看 [产品主线](PRODUCT_MAINLINE_GUIDE.md)。

## 1. 本期交付边界

本期固定创作 / 游玩术语、输入类型、数值策略、知识来源和调用权限，审查现有路径，并通过真实服务 / Prompt / 生成器代码将合成请求送到注入的离线 Provider，检查实际消息。仅 Repository 和 Provider 边界使用测试替身，不读取生产数据。

不提前新增生产 Schema、API、表、空 Provider 或并行引擎。后续功能在实际接入消费者时实现本文契约，替换现有单一实现；不是增加一套长期兼容的备用协议。

## 2. 数据契约：定义、实例与事实

以下为**目标语义规范，不是当前 HTTP 请求字段**。现有接口仍只接受当前严格 Schema；新增字段在接入对应功能前应拒绝，不允许客户端以额外 JSON 偷渡权限。

| 对象 | 必须区分的内容 | 何时生效 |
|---|---|---|
| 创作意图 | `kind`（world / item / character / event / draw_pool）、原始粗描述 / 关键词、绑定世界修订、用户硬约束、锁定字段 | 仅创建或更新草稿，不改游玩状态 |
| 设计草稿 | 草稿 ID / 版本、结构化候选、来源标记、冲突 / 待确认项、预览 | 用户编辑 / 局部重生成；明确确认才发布 |
| 世界定义 | 世界 ID / 不可变修订、公开简介、主持隐藏设定、规则字典、数值策略、区域与内容引用 | 发布后用于创建存档；不追溯更改已有局 |
| 道具 / 材料定义 | 世界修订、类别、品质 / 等阶、背景、效果 / 限制、可选数值属性、堆叠 / 唯一性 | 发布定义不等于发放物品 |
| 道具实例 | 定义引用、数量、持有者、装备状态、获取来源 | 宿主在合法动作 / 确认奖励结算时入库 |
| 人物卡 | 世界约束、身份 / 控制者 / 重要性、动机与表达；作者完整卡与人物运行投影分开 | 人物运行只获得必要的自己信息及已获知内容 |
| 事件计划 | 起因、条件、参与者、可见性、选择、成本 / 后果、确认状态 | 计划不是已发生事实；确认规则并满足条件后宿主结算 |
| 回合与世界事实 | 父回合、实际发生的动作 / 结果、来源事件与可观察范围 | 在宿主结算成功并原子 append 后成为分支事实 |

“用户明确描述 / AI 补充 / 待确认假设”是内容来源；“草稿 / 已确认 / 已发布”是创作生命周期；“世界事实 / 传闻 / 推测”是证据性质，三者不能用一个布尔字段混合。用户在设计视图确认了秘密设定，不表示每个 NPC 已经知道。

确认必须对应用户看过的草稿版本和目标存档版本，不能确认旧预览后应用新的生成结果。失败保留草稿；不为了满足规范重写历史存档或提前设计不被消费的全套存储。

## 3. 输入语义契约

下一步采用显式判别类型，不靠关键词猜测“我想……”一定是台词或私密想法。目标是一个回合可携带有序语义片段，但先实现已有界面的真实需求，不引入任意嵌套脚本。

| `kind` | 必要语义 | 人物能获得什么 |
|---|---|---|
| `dialogue` | 发言者、接收对象、地点 / 通道、台词 | 真实听见 / 收到的台词；不能附赠该玩家的私密字段 |
| `action` | 行动者、意图、目标；结果由宿主产生 | 只有可观察到的行为 / 结果，不是未表露动机或自动成功 |
| `world_narration` | 旁白 / 世界变化的来源、内容、作用范围 | 依感知分发；用户提出的变化是建议，不能自报为权威世界事实 |
| `private_thought` | 所属人物、内容 | 默认仅本人和必要主持上下文；其他人物不可读取 |
| `ooc_instruction` | 场外设计 / 管理意图 | 转入对应创作流程，不作为游戏内发言、感知或既成事件 |

片段身份、可见性和世界状态的权威由服务端验证；客户端不能把自己标成任意 NPC 或把私密内容声明为全世界已知。原有自由文本未明确分类时不自动写成台词；含关键歧义时确认含义，不做无依据的“读心分类”。

结构化动作与语义片段分工：前者决定合法状态改变，后者解释玩家在说 / 做 / 想什么。后续贯通输入、持久化、人物记忆、摘要、检索和导出；仅在 UI 加下拉框而存储仍写“玩家说”，不算完成。

## 4. 数值策略

| 策略 | 允许内容 | 不允许的自动补全 |
|---|---|---|
| `qualitative`（无属性数值） | 特性、效果、限制、品质 / 等阶标签；数量、钱币、时间仍可作为宿主操作数据 | 强制等级 / 战力 / 血量 / 伤害或伪装成文字的属性数值 |
| `light`（轻数值） | 世界明确声明的少量属性字段，逐项约定含义、单位、类型、上下界 | 自动补成通用战斗面板、从品质推导成功率 |
| `numeric`（指定数值） | 世界声明的属性 / 等级及约束，遵守相同字段校验 | 未声明的字段、越界值、模型自行新增计算公式 |

每个世界修订固定策略，生成器不能因关键词或抽卡品质改变策略。评级、品质、等阶分别来自所属字典；不能相互代替。非数值策略不代表禁止背包数量或抽卡概率，它限制的是人物 / 道具的能力属性体系。

当前 `worldItemSchema` 仍要求 `level`，`worldRanksSchema` 仍要求 `levelsPerTier`，没有上述策略判别；R10.3–R10.4 再改为一个有实际消费者的规范结构，不能现在声称无数值生成已支持，也不能仅通过隐藏面板来实现。

## 5. 人物知识与调用范围

目标知识记录至少包含：世界 / 修订、存档、持有知识的人物、内容、证据性质、来源定义或来源事件 / 回合、获知方式、获知时点。获知方式区分亲历观察、实际告知、阅读资料和有依据推理；传闻与推测始终保留来源及不确定性。

检查顺序：同世界与修订 → 同存档 → 来源在选定父回合的祖先路径且未晚于当前时点 → 此人物实际获知 → 本次调用确有需要。静态初始知识需有定义来源和人物初始授权；不得因没有来源回合便把全部世界定义当成公共知识。

| 调用目的 | 服务端允许构建的范围 | 关键禁止项 |
|---|---|---|
| 创作 | 粗描述、锁定约束、待设计对象与必要世界资料 | 草稿直接写游玩状态 |
| 主持 / 事件 | 当前分支的权威状态、相关隐藏规则 | 全局资料作为工具结果直接转发给人物 |
| 单个人物 | 自己的必要人物卡、实际感知、已获知信息和当前合法交流 | 玩家想法、其他角色秘密、未观察的世界变化、兄弟分支或未来 |
| 宿主结算 | 已确认动作、规则、定义、请求回执和版本 | 执行模型任意状态补丁、让模型决定抽样概率 |

隔离发生在请求进入 Provider 之前，并覆盖正常与预算降级路径、历史、摘要、检索和 `lastResult` 等工具 / 宿主结果。目标 ID 无效时必须拒绝，不能退回权限更大的主持上下文。相同 Provider / API Key 可以复用；不同 URL 或多个模型不是知识隔离保证。

## 6. 抽卡边界同步冻结

固定内容池只引用当前世界允许获取的道具 / 材料，宿主抽样、校验、结算，模型调用为零。关键词池由宿主先确定类型 / 品质 / 数量，再让道具设计器补全；生成器无权重新抽签。

抽样回执应绑定请求 / 卡池修订 / 世界修订 / 存档父回合 / 抽样结果，生成草稿另有待处理状态。确认后以同一结算边界检查虚构资源并写入定义、库存和回执；生成失败或取消不产生半扣款 / 半发奖，已有真实 API 消耗仍记账。具体抽样 / 持久化实现留给 R10.4.1，不在本期新建空表或发奖通道。

## 7. 当前调用路径审计

| 路径 / 文件 | 已有保证 | 缺口与归属 |
|---|---|---|
| `GamePlayPanel` / `ExplorationPanel` → `createGameTurnSchema` | 明确的结构化动作 / 目标，探索请求 ID，不混用骰子等其他工具 | 自由文本没有五种语义片段；“你的行动或台词”混合。R10.2 |
| `gamePlayApi` → `GameTurnService.create` → `applyExplorationAction` | 输入严格校验；服务检查版本，动作先验证目标与在场；无 `narrate` 不调用模型 | 不能因此认为完整语义或所有知识来源已经校验。R10.2 |
| `explorationMessages` 目标分支 | 不传玩家历史 / 私有背包 / 无关人物卡；已有预算与局部角色投影 | 目标找不到时函数自身退回主持；当前动作服务先拦截，但上下文边界尚未独立防御。R10.2 |
| `explorationMessages` 的历史 / `trustedResult` | 主持路径限制历史数量，服务只选祖先回合 | 无人物感知元数据；原样结果 / 复用历史可能成为未来旁路。需要按来源过滤，不声称当前所有结果已经泄密。R10.2 |
| `GameTurnService` 人物对话记忆 | 记忆有长度上限，跟随父状态产生分支 | 所有 `content` 统一写“玩家说”，模型回应也只是叙事记录而非经验证事实；缺类型、来源和获知方式。R10.2 |
| `publicWorldCharacterSchema` / `engine` | 已区分玩家 / NPC / 重要角色；已有初始知识、话题和关系 | `knownInformation` / `memories` 是字符串，当前是公开投影卡，不是完整作者卡 / 运行卡与逐人物认知系统。R10.2 / R10.4 |
| `contracts` / `templateTypes` / `catalog` | 当前模板版本固定，物品定义 / 实例分开，宿主校验数量 / 唯一性 | 用户世界草稿发布、数值策略、材料类型和抽卡获取尚未实现。R10.3–R10.4.1 |
| `gameNarrativeGenerator` | 复用 Provider、用量归因，探索输出需空 `statePatch` | 创作 / 主持 / 人物尚无独立用途 DTO；不能用不同 API 替代权限设计。R10.2 起按消费者接入 |

这是一份现状审计，不通过复制调用链或新造框架来“预留”。旧 d20 玩法保持独立现用语义，本规范先针对 R7 探索路径落地，不静默改变所有娱乐玩法。
