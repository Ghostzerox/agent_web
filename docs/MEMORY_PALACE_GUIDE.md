# R5.5：模块记忆与记忆宫殿 MVP

2026-10-16。入口：导航「记忆」→「记忆宫殿」→「打开记忆导航与学习助记」。Web 与本地 React Client/APK 共享页面，数据仍在服务端 PostgreSQL；离线不能新建、读取或提交训练。不是 3D 场景，也不是新建一套事实数据库。

> R5.6工程首期已于2026-10-17交付：按模式开关、范围记忆包/只读预演、来源使用说明及跨端结果见 [控制与验收指南](MEMORY_CONTROL_AND_ACCEPTANCE_GUIDE.md)。真实学习跨端因当前插件授权不足跳过，真机待确认；本文件保留R5.5功能与历史范围。

## 两种用途

### AI 记忆导航

1. 创建「AI 记忆导航」宫殿，添加房间，并选定所属模式。保存后模式不可改；需要别的模式时新建房间。
2. 点击「读取本房间来源目录」，显式选择已确认个人记忆或同模式知识资料。专业/陪伴/反思可关联个人记忆；陪伴不读知识集合，游戏不读现实个人事实。目录不是后台生成权限，也不会自动把全部资料发送给模型。
3. 给位置命名，如门口、书桌、窗台，填写自己的联想；保存的只是来源 ID、版本指纹与布局。可编辑、上移/下移、解除关联，或删除房间/宫殿。
4. 点击来源查看当前正文、版本/原文入口。个人记忆显示现有回答使用次数与最近使用时间；看一眼宫殿不会增加「用于回答」次数。资料预览最多5000字符，完整内容到原文页查看。
5. 来源更正、过期、删除或不可访问时，旧绑定不返回正文；需核对新版并显式重新关联。不会自动把新版当作原先已确认的内容。

同模式知识集合的手动管理/查看沿用现有资料库权限；宫殿引用**不会替你勾选聊天 RAG 集合**，不增加插件私有记忆能力。点击模式卡可前往该业务模块，但不是把其全部业务状态自动转换成可关联位置。

### 学习助记

1. 在「学习 → 背书」导入材料，校对并保存知识单元；背书复习库提供宫殿入口。任意知识库文档不会自动转换成背书材料。
2. 创建「学习助记」宫殿，添加背书房间。读取来源目录、选材料与单元，关联位置、写下联想。学习宫殿只关联单元，不混入现实个人事实或游戏剧情。
3. 选择「按位置路线 / 可复现随机 / 弱项优先 / 到期优先」，设种子并开始。种子用于重复训练顺序，不是密码学随机；未练习单元优先进入弱项/到期路线。
4. 根据位置、联想和提示作答。原文默认隐藏，可以主动显示；这不是防作弊考试，原文已经由授权接口送达客户端。
5. 提交逐字检查，查看错漏/拼写位置与下次复习时间，再进入下一位置。原始复习记录写回背书插件，宫殿没有第二套答案、评分或任务表。

逐字检查确定性执行，**不调用模型**、不评价语义理解；逐次最多2000个有效字符，较长材料先拆分。语义复述仍去背书活动。沿用既有简易间隔规则和最近最多40次历史；不声称已采用 FSRS 或证明学习效果。服务可能返回任务草稿，但本页面不自动创建提醒，需要时从背书页操作。

材料/单元改动后绑定失效；练习时不把旧答案判成当前答案。复习次数/得分变化不改变单元来源指纹。训练路线在当前页面临时保存，刷新需重开；已成功提交的复习记录仍在服务器。重复点击/丢失响应后以材料版本拒绝重复评分，提示核对现有日志，不自动重试。

## 模块特化：新增与复用

| 模块 | 真实来源与策略 | 本轮新增 / 保留边界 |
|---|---|---|
| 专业 | 证据版本、当前分支、相关确认事实；个人最多5条/约500 Token，同域知识预算6条/1800 | 摘要强调数字/否定/事实与推断；宫殿关联来源，不替换既有显式检索 |
| 陪伴 | 相关确认偏好/事件与当前分支；最多4条/约400 Token，无知识集合 | 相关候选中偏好/画像加权；摘要保留当时情绪与时间线，不固化诊断或承诺 |
| 反思 | 已确认目标、当前行动/反馈；最多4条/约450 Token，知识3条/900 | 相关目标加权；摘要分开目标、建议、决定与已执行事项 |
| 新闻 | 事件/发布时间、实际来源、已发来源去重；知识预算6条/1800 | 复用现有简报与去重服务，宫殿可导航同域资料；不把旧简报当最新新闻 |
| 阅读 | 显式画像、已读/想读/不喜欢、书目来源与反馈；知识5条/1500 | 复用已有画像/反馈，不推断全局喜好；可导航阅读资料，不自动同步章节进度 |
| 任务 | Task/Run/Inbox结构化状态；知识3条/900 | 复用既有执行账本；摘要/联想不是完成任务的依据 |
| 背书 | 授权材料/单元、原始尝试/下次复习；知识4条/1200 | 新增宫殿位置训练闭环，经原 Gateway 读写，不直接偷读插件表 |
| 解题 | 授权题库/尝试/误区/复习卡；知识4条/1200 | 复用题库搜索与复习卡；可导航同域资料，不把错题定成永久能力诊断 |
| 娱乐 | GameSession当前分支、角色、检查点与可信随机状态；知识4条/1200 | 复用独立游戏状态；娱乐聊天摘要专门隔离虚构与现实，不混入兄弟分支 |

个人预算是本轮保守默认值，不是测得的最优点；相关性、TTL、来源与模块过滤先于加权。其余知识预算沿用 R5.1，**有预算不代表独立新闻/书单/任务/插件/GameSession 已自动接入 RAG**。这些工作流现继续使用自己的可信状态，自动资料绑定仍待后续显式设计。Inbox、语音、配置、导航、维护等7个辅助域继续沿用原策略，不为凑齐16个域制造无意义模型调用。

普通聊天的摘要生成现在按**服务端存储模式**使用 `branch-summary/r5.5-v1` 模板。R5.4旧摘要不再复用，但可能仍留在派生表，可手动清除；原消息完整保留。不会因升级自动重新收费生成，也不会把独立游戏/任务/学习状态硬塞进聊天摘要。

## 数据与约束

- 新表 `memory_palaces`：owner、标题、用途、房间/位置 JSONB、版本与更新时间。最多10宫殿、每宫殿6房间、每房间24位置、总布局128KB；单次修改请求30KB。没有新增向量库、数据库服务或 npm 依赖。
- 每个位置只存来源种类/ID、单元ID（如有）、修订指纹及**用户自己的联想**；不复制原文。若你把私人正文粘贴进联想，它就是另存的一份用户内容，删来源不会自动清除此联想，需自己删除位置/布局。
- 布局修改与删除采用版本校验；冲突不覆盖其他端新版。授权读取在短布局事务之前完成；布局 CAS 绑定所读房间/用途，实际查看和评分再次校验来源。材料写入仍以插件存储 CAS 保证不重复记分。
- 同房间禁止重复来源，以规范化字段序列比较，兼容 PostgreSQL JSONB 重排键序。跨房间可有同一来源，用于不同联想路线。
- 先检查 owner/模式/TTL/修订，再返回正文。同一条路线同一材料仅做一次授权读取，节省 Gateway 存储配额；不跨请求缓存材料。下次查看/评分仍重新检查插件启用、授权与额度。
- 解除关联/删布局不删事实、资料或复习记录。删原文后旧引用仅显示失效，不返回旧正文；无级联误删。已打开页面、联想、导出文件/旧备份或在途请求不可能被瞬时撤回。
- 宫殿不新增长期记忆自动写入、AI自动生成联想、通用语义矛盾检查、3D/VR、知识图谱或向量召回。
