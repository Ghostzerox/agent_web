# 事件创作与生成

R10.5 工程实现。用户世界和当前存档共用事件契约、生成器和原探索引擎，不引入第二套世界模拟。自然语言的因果、动机和角色一致性仍须人工审阅；自动校验不等于模型质量签收。

## 入口与流程

1. **设计世界事件**：娱乐 → 我的世界 → 所选世界创作工作台 →「事件设计」。输入想法后点“创建事件”直接进入编辑，不调用模型。
2. 分字段编辑名称、作用范围、地点、参与者、触发条件、起因 / 知情范围、行动 / 后果；已满意字段可锁定。选择生成范围后确认可能费用，生成只保存草稿；审阅后“加入世界事件 / 加入当前分支”，不混淆生成与生效。显示用户 / AI来源，JSON未应用时不能假保存或生成。
3. 「预览与确认事件」检查所有阶段、隐藏起因、条件和实际后果。勾选审阅并确认，只纳入世界草稿。**发布新修订、创建新存档后才采用**，旧局继续原修订。
4. **当前局事件建议**：游玩页「事件建议 / 创作 →」，绑定当前所选父回合。相同编辑与审阅流程，确认只向本分支加入规则，不替玩家选择、不领奖。
5. 确认后若条件已满足可立即触发；否则在后续宿主动作 / 确认获取物品后检查。进入「事件与史诗」处理已发现事件，选择后由宿主原子结算，结果进入原背包、关系与历史。

编辑和预览是独立子页；流程和高级结构可折叠。基础表单支持回合 / 旗标 / 物品门槛、成本、钱币变化和首项物品奖励；关系 / 已学史料、多奖励、传播条目和增加阶段使用当前字段高级 JSON，不另建平行规则编辑器。切字段与离页有草稿保护。

## 状态与边界

| 状态 | 实际含义 |
|---|---|
| 草稿 / AI 建议 | 保存在独立表，不触发、不扣虚构资源、不发奖，不写为已发生历史；显式AI生成仍可能产生API费用 |
| 已纳入世界草稿 | 后续发布的新修订消费，原发布版本和旧局不变 |
| 已纳入分支 | 存一个明确确认的规划回合，只允许该回合的后代继承规则引用 |
| 已触发 | 所有前置满足，进入第一阶段；不自动选择或发奖 |
| 玩家已发现 | 当地事件需到场；参与者可见模式须明确包含 player；远处已触发不等于玩家已经知道 |
| 已解决 / 已拒绝 | 当前阶段到达终点，无循环重开或重复奖励 |

六类事件：探索发现、社会互动、交易 / 委托、人物个人事件、世界变化、史诗。首期均为有限无环的选择流程，人物事件跟随首位 NPC 的实际地点；“世界事件”不表示全体人物自动知情。每个未结束阶段必须提供无前置、无消耗、空后果的拒绝 / 替代行动。史诗须有非空门槛，不能无条件强塞主线。

条件支持旗标、已学史料、持有物品、最早探索回合、指定人物关系门槛，全部同时满足。`minTick` 是探索时刻，不是真实日期、定时提醒或离线世界时钟。

后果仅支持宿主已经实现的旗标、发现、史料揭示、虚构钱币、状态、合法物品奖励和人物关系 / 移动 / 未竟事项。物品只引用本世界或本分支已有定义，不执行生成的脚本、不临时制造未定义属性、不创建真实任务。自由文本的效果描述不能越过结构化动作执行。无超自然世界不能新增声明超自然的事件；任意自然语言设定是否一致仍须人工判断。

## 知识与分支

- `details.cause` / `authorNotes` 仅供创作与相关主持请求；公共探索快照和导出不包含完整规则 / 主持秘密。人物请求不接收事件全图、主持因果或全局结算文字。
- 只在真正触发或选项执行时，消费 `onTriggerKnowledge` / `choice.knowledge` 的明确消息。每条有 `text`、`evidence`（fact / rumor / legend / opinion）、`recipients`、`reason`，写入原有感知日志，附请求、回合、世界修订及获知方式。
- 参与者身份和人物在场本身不等于读到整个事件。未配置的 NPC 不收到秘密；远方人物若要知道，必须明确配置合理的消息和获知方式，不做全局广播或自动传播模拟。传闻不会自动变成事实。
- 人物请求只使用本人可见、来源仍在所选祖先链中的记录；回到旧检查点不会带回未来规则、奖励或知识。人物诊断面板只展示玩家也在受众中的条目，不把 NPC 私密消息公开。
- 状态只存 `eventPlanIds`，服务端根据当前父回合及祖先中的确认回合解析，拒绝兄弟分支规则引用。奖励和唯一性以当前分支为准，不承诺跨分支全局防读档。

## 一致性、失败与费用

草稿和来源都带版本。世界更新、活动分支 / 回合操作导致来源变化时，生成与确认拒绝继续；草稿不丢，用户须明确适配并重新审阅。已应用草稿只读，不能追改结局。

事件确认、规划回合写入及应用标记在同一事务；选项成本、消耗、奖励、后果、历史和回合通过原探索事务提交，任一步失败均不半写入。稳定请求回执与结束状态阻止重复提交 / 并发重复领取。事件和抽卡共用 `grantInventoryItem`，材料正确堆叠、不自动装备，分支内永久唯一发放标记防止消耗后再领。

生成沿用现有游戏 ModelProvider / 用量统计，用途 `r10/event-design-v2`，不是每个 NPC 一套模型。一次只补请求且未锁字段；每个字段是完整替换，嵌套阶段 / 选项必须保留全部必填键，不把省略当递归合并。用户消息和模型输出各限 30,000 字符；上下文超过预算直接保留原稿并提示，不截断半份 JSON。上下文取固定世界规则、必要参与者目标 / 关系、所选分支当地近期年表及库存，不发兄弟原始对话或玩家内心。

模型调用前在数据库认领请求，每稿最多 32 次不同尝试；同请求刷新 / 跨服务重放不再次调用。失败 / 取消保留原稿、无自动付费重试；进程中断可重读或明确停止接收，迟到输出不能覆盖。新尝试可能再次付费，已发生 API 费用不退。手动编辑、确认、触发和选项结算均不调用模型。

## 代码与数据

- `web/lib/game/events/`：结构化契约、语义引用校验、局部生成、明确知情传播。
- `gameEventDesignRepository` / `/api/v1/game-events`：来源快照、版本、认领、适配和原子确认；客户端 DTO 不返回私有 `sourceSnapshot`。
- `EventDesignWorkspace` / `EventDesignEditor`：Web / 本地 React 同一套 UI 和传输，入口归属娱乐，不新增全局导航。
- `gameWorldRepository.resolveSessionTemplate`：固定世界修订 + 当前祖先链计划；`worlds/compile` 消费已确认世界事件。
- `exploration/engine` / `turn` / `inventory`：原引擎触发、选择、库存与感知；`gameDrawRepository` 在入库后复核物品门槛。
- 新迁移 `0037_game_event_designs.sql`，当前 **38 对迁移 / 回滚**；独立 JSONB 草稿和私有来源快照，世界 / 存档所有权外键，旧 37 份 SQL 不变。仅追加新表和新状态可选字段，不重写历史回合。已存在新事件 / 唯一奖励数据时拒绝有损降级；不用真实库试回滚。

专项 `eventDesign.test.ts` 验证 P13、真实内存 SQL、条件 / 发现 / 拒绝、固定修订、版本适配、源过滤、持久认领、迟到输出、重复 / 并发、SQL 失败原子回退、检查点和共享奖励。`e2e/event-design.spec.ts` 用合成数据覆盖世界创作 → 发布 → 触发 → 领奖，以及当前分支建议 → 拒绝 / 刷新；Web 与共享 React 均按 360 / 1440px 检查。

不做无界后台 NPC 模拟、自动改写既有结局、跨世界热迁移、自动生成任意新规则或完整图形流程编辑器。R10.6 仍负责整段创作 / 游玩旅程与质量 / 成本综合验收；本轮合成测试不证明真实模型的动机一致性、自然度或费用收益。手机仍合并 [D10](DEVICE_ACCEPTANCE_BACKLOG.md)，不把桌面移动视口 / Bundle 构建写为真机通过。
