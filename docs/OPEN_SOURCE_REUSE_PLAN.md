# R11：模块级开源调研与复用决策

- 登记日期：2026-10-21，按用户要求新增。
- 状态：**R11.1–R11.4调研交付完成（2026-10-21）**：11模块 / 24仓库地图、重点源码核验、FSRS / rrule两个隔离实验、采用决定及有界后续提案。证据与限制见 [R11报告](reports/R11_REPORT.md)；未把候选接入生产，不把README、Star或算法实验当长期效果验收。
- 排序事实来源：[产品主线](PRODUCT_MAINLINE_GUIDE.md)。R10首期之后，在继续深化相关模块前优先调研；具体阶段由用户指令启动，不自动替换现有功能。
- 目的：避免重复实现已有成熟能力，降低维护成本；保留自用、学习与作品集目标，不为接入开源而推倒现有项目。

**长期规则立即生效**：按用户2026-10-21补充要求，每个新任务先检索GitHub，优先学习经典或高Star的相关实现，并核查兼容性；不必等R11启动或完成。轻量执行方法以 [开发手册](DEVELOPMENT.md#新任务先查github长期规则) 为唯一详细规则；R11负责系统性模块盘点，不把每次小任务扩成全量调研。

## 1. 范围与模块清单

不能只找“另一个完整AI助手”，也不能只关注语音和角色。先将现有实现、用户体验缺口、可替代的最小能力列清，再搜索成形应用、可独立使用的库或服务。

| 本项目模块 | 优先调查的问题 | 复用边界 |
|---|---|---|
| 语音 / 音线 | TTS、音色控制、分句流式合成、取消 / 播放队列；必要时另评估ASR | 区分TTS引擎、音频播放与陪伴机器人；不默认加入语音克隆或双向通话 |
| 陪伴 / 人格 / 主动联系 | 自然表达、何时回复 / 沉默、时间感知、主动发言与打扰控制 | 陪伴机制不能进入专业模式；角色虚构日程不等于真实执行的用户任务 |
| 娱乐 / 世界 / 人物 / 事件 | 角色卡、世界书、认知隔离、持续叙事、事件与角色自主性 | 不把全局世界书当所有人物知识；保持宿主确定性结算、分支、修订、用户选择权 |
| 记忆 / 资料 / RAG / 压缩 | 索引、检索、分域记忆、来源引用、摘要与失效处理 | 不重复引入事实数据库；个人 / 学习 / 游戏域和祖先分支过滤先于检索注入 |
| 学习 / 背书 / 宫殿 / 解题 | 间隔重复、抽背、文本差异 / 拼写、题库、数学工具 | 先评估独立算法 / 库，不为复习算法重建完整学习平台或盲目增加模型评分 |
| 任务 / 打卡 / 提醒 | 复发规则、时区、行动记录、调度与可靠投递 | 保留任务和执行记录的职责区分；消息送达不等于用户完成，现有Worker不无理由重写 |
| 新闻 / 书籍 / 内容 / 反思 | RSS / 正文抽取、去重、书目数据、来源质量与问题筛选 | 不把抓到网页或模型推荐当已核实事实；保留来源、日期与用户偏好 |
| 专业问答 / 搜索 / 工具 | 搜索适配、公式 / 代码渲染、结构化工具、回答校验 | 优先现有实现或单项依赖；不让另一套Agent运行时接管全部请求 |
| UI / 导航 / 编辑器 | 可访问的折叠、移动交互、世界 / 角色编辑与预览 | 延续R8模块归属与共享React，不复制整套外部前端、不增加平行导航 |
| 插件 / 模型接入 / Token成本 | 插件生命周期、受控工具、Prompt分层、缓存与用量 | 外部插件不能直接当现有插件加载；不绕过授权、Vault或现有费用统计 |
| APK / 平台能力 | Capacitor生态中的通知、文件、播放与后台能力 | 优先原有薄桥接；区分Android与HarmonyOS兼容层，不默认重写另一套客户端 |

每个有真实缺口的方向优先找2–3个候选；查不到、候选过重或现有实现更简单时，允许记录“保留现状及理由”。不为满足数量收集几十个无人使用的仓库。

## 4. 每项复用决策记录的最小格式

1. **需求与重叠**：本项目模块 / 现有文件、当前不足、候选解决的最小问题；已经有合适依赖时优先复用现有依赖。
2. **身份与成熟度**：仓库 / 上游、版本 / 提交、最近维护与发布、测试 / CI、文档、重要未解决问题和复现步骤；没有证据标“未知”，不只按Star排名。
3. **许可与来源**：实际引用的文件、代码 / Prompt / 权重 / 数据各自许可、来源与署名、分发方式需核查的条件；不默认“公开可见”就能复制或重新许可，不将研究设计与复制代码混淆。
4. **接入代价**：Node / Python / 原生依赖、额外数据库与服务、CPU / GPU / 内存、笔记本部署与未来云迁移、APK边界、升级与退出成本。轻量库优先；跨语言能力可评估独立服务，但不提前创建空Provider或工厂。
5. **质量与成本**：固定合成场景、现有实现对照、实际效果 / 延迟 / 用量与资源，清楚区分估算、运行测量和用户评价。真实模型测试仍用[跨阶段累计预算](PAID_TEST_BUDGET.md)，不在每个候选上重置额度。
6. **决定与退出**：选用方式、为什么不选其他候选、保留 / 替换哪些代码、最小接口、失败策略与回滚、待用户选择事项。实际替换时不长期保留两套同功能默认实现。

## 5. 不改变的产品边界

- 不因为开源项目主打拟人，就牺牲专业回答的准确性或编造真实生活 / 已执行任务。陪伴机制有独立模式、用户控制与打扰限制。
- 不让世界知识、其他人物秘密、兄弟 / 未来分支、个人记忆跨域混入角色请求；不给外部机器人直接写生产库或执行宿主结算的权限。
- 不为“避免造轮子”引入更重且难维护的重复系统；简单现有实现通过验收时可以保留。R9的去冗余、单一事实来源、总分UI与共享双端原则继续有效。
- 本轮只将两个固定npm发布包下载至忽略的实验目录；不安装生产依赖、不下载语音模型、不改数据库、不调用收费模型。后续缺少本机环境、下载软件或可能产生费用时，明确告诉用户，而非默默把硬件 / 云服务当既有条件。
