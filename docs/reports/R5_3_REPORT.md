## 用户可见功能

- “记忆 → 知识资料库”可按当前集合检索，显示片段/版本/行号/耗时，无模型调用。
- 聊天显式勾选同模式集合后，把命中片段加入真实 Prompt，回答沿用 `[S1]` 引用卡片；刷新聊天保留引用，点击打开指定版本原文并高亮相应分段。Web/APK 共用组件。
- 选择资料时不调用网络搜索、不把私人问题交给搜索服务；配置的模型仍可能是远端服务，界面明确片段会发送给它。未选集合的原行为不变。
- 文档更正/删除后不再召回旧片段；旧引用明确提示失效，不拿新版本冒充旧依据。无命中说明暂无依据，候选过多要求缩小范围，不假装全部查完。
- Prompt 导出默认脱敏个人记忆与资料上下文，可显式包含；旧 Composer/导出兼容，只有实际加入资料层才使用 R5.3 Composer。

独立 GameSession、后台任务/新闻书单生成和学习插件尚未自动选资料，留 R5.5 逐流程接入；本阶段没有新插件权限或模型自主循环。

## 实现与审查重点

1. Repository 从真实会话/问题解析模式，先按 owner/模式/显式集合过滤，再查询当前文档分段；不接受客户端 query/mode 作为聊天读取授权。原始兄弟分支消息不是资料文档，不能混入召回。
2. 中文分词/有限别名、SQL 60% 词项覆盖粗筛、标题/段落/正文加权与轻量稀有度排序；去重、最多 5 段、每段 500 码点，预算计算包括稳定证据 JSON/引用元数据。查询/候选/完整输入上限有明确失败，不无限扫描回传正文。
3. PromptRun 事务锁集合并复核模式、分支、根版本/hash 与 chunk hash；旧来源竞争失败不调用模型、不留半成品 Run。提交后的源删除不能撤回已发远端请求。
4. 引用元数据与本地 URL 严格匹配；资料文字不执行 HTML。历史引用不重复存 excerpt，审计新列也不存 query/title/body。历史模型回答仍可能包含原文，删除资料不自动删除回答/导出/旧备份。
5. 无新的模型、Embedding、索引缓存、依赖或 PostgreSQL 扩展；SQL 读取权威当前版本。现有单用户身份不冒充多人认证，R5.1 的最小分域边界保留。

审查中修复 APK 同页 hash 查询变化不重载原文的问题，并将手动检索结果点击纳入 Web/本地 Bundle 端到端验收。新 E2E 的引用可访问名称/命中行号预期，以及旧 E2E 对新增知识接口的模拟响应形状也已修正；没有放宽业务断言或延长测试超时。

## 80 查询与压力测量

固定人工编写合成语料：100 个逻辑文档、1,000 段；80 查询：中文直问 16、改写 12、中英缩写 8、多来源 8、无答案 12、旧版/删除 8、隔离 16。金标固定为源 ID/版本/锚点，不用模型自评。**开发中查看过全部题目，虽然 fixture 保留 split 标签，也不是盲测/独立人工签收或真实回答正确率。**

| 项目 | 首轮原型 | 最终基础层 | 最终 10 倍压力层 |
|---|---:|---:|---:|
| 逻辑文档/片段 | 100 / 1,000 | 100 / 1,000 | 1,000 / 10,000 |
| 有答案 Recall@5 | 79.55% | 90.91% | 90.91% |
| 个人记忆算法同语料参考 | 68.18% | 68.18% | 68.18% |
| 无答案误召回 | 0/12 | 0/12 | 0/12 |
| 隔离错误/旧删源错误/定位失败 | 0 / 0 / 0 | 0 / 0 / 0 | 0 / 0 / 0 |
| 首查询 / 后续 P50 / P95（ms） | 11.53 / 3.34 / 10.57 | 6.87 / 1.54 / 6.84 | 15.74 / 5.42 / 9.96 |
| 证据最大估算 Token（最终含元数据） | 旧口径不比较 | 752 | 752 |

这是 Node v24.15.0、Windows x64、i9-14900HX 上的纯排序+等价粗筛测量，**不是数据库/网络/Provider 延迟**。首查询只测一次，不冒充冷 P95 或 WASM/进程启动时间；仍需后续并发、真实规模和更多冷启动测量。参考算法是将现有个人记忆算法应用到同语料，不是声称 R5.2 原本存在知识库检索。

通用问句词处理提高首轮召回；压力首测出现三项过宽候选，Recall 84.09%，保留原始记录。SQL 粗筛从泛 OR 改为与排序一致的分组覆盖门槛，复测达到 90.91%，不是修改题目/金标。最终分组直问、中英、多来源均 100%；改写 8/12，4 个隐含语义问题仍漏检，Embedding 待开发，未测其收益，不能据此断言不值得实现。

真实 Repository 的隔离 PGlite SQL 测量：94 篇存活文档/940 段（逻辑库排除已删源及非文档分支原始源），同 80 查询 Recall 90.91%、无答案/隔离/旧删源样例错误命中 0；首查询 23.61ms、后续 P50 7.69ms/P95 15.61ms。这包含 SQL 与排序，但仍不是 Docker/网络延迟。生产 Docker 只对独立合成集合验证 HTTP→SQL 生命周期，不冒充 100 篇私人资料规模评测。

原始证据在 `web/evals/r5/`：`baseline-first-run.json`、`retrieval-stress-initial.json`、`retrieval-final.json`、`retrieval-stress-final.json`、`retrieval-sql-final.json`；语料/金标见同目录 `retrievalCorpus.ts`。所有测量模型/Embedding 调用 0，预算估算不是账单 Token 或实测净节省。
