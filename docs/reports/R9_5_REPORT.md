## 1. 本轮交付与数据验证

新增 `web/tests/releasePersistence.test.ts`，不是第二套测试平台：复用现有 Vitest、迁移适配器和真实 Repository，以一个合成数据库保存聊天树、较早节点重新生成分支、确认记忆、知识材料、定时提醒结果、用户完成行动、加密凭据及探索检查点。

执行 PGlite 的 `dumpDataDir → close → 新引擎 loadDataDir` 后，重新运行全部迁移应为空操作，逐项核对数据及版本不变、资料仍可检索、假凭据仍可解密；再次扫描不得重复提醒，过期版本写入仍须拒绝。普通提醒与宿主探索不调用模型，网络和生成器均设为禁止并断言零调用。最终清理测试引擎，不写文件或触及真实数据。

这是**当前规范格式的持久化 / 冷重启检查**，不是读取用户数据库的副本，也不是支持任意已退役格式的迁移器。生产仍使用 PostgreSQL；PGlite 检查不冒称真实 PostgreSQL 容器的完整灾备恢复。

真实库另在容器内以 `repeatable read read only` 事务核对：

- `transaction_read_only=on`；34 条已应用迁移、容器 SQL 与本地仓库 SHA-256 全部一致。R9 起正式 up / rollback SQL 的 Git 差异为空。
- 已有会话 / 消息仍存在；父消息与活动叶没有跨会话归属、悬空或错误叶节点。
- 当前生产游戏会话与快照为空。没有执行格式转换，也不以空集断言“真实旧游戏存档迁移已通过”；相应非空规范存档由上述合成检查覆盖。
- 不输出正文、私人标识、配置值或密钥；不清空 localStorage、数据库或原命名卷 `agent-web_postgres-data`。

## 6. 复盘、保留问题与回滚

本轮主要收益是减少维护概念和重复事实，而非大幅缩减全部业务代码：客户端死代码原本可能不进包，源码净减只有约4.3%；较明显的运行收益来自不再把整套开发工具塞进生产镜像。新文件数略增是职责拆分，不代表重新建设了第二套业务。

仍有1,532行Schema、729行GameSessionRepository和571行插件授权Repository等较大模块；R9没有把所有大文件拆碎，也未引入通用解耦框架。现用事务、错误语义和真实平台差异有必要保留；后续按具体修改成本再决定是否调整，不自动启动“第二轮全面重构”。

仍未完成的边界不得被封版覆盖：

- **发布安全**：R9.4在2026-10-18查询的npm告警19项（4低 / 4中 / 8高 / 3严重），本轮锁文件未变、不重复审计或自动强制升级；当前无登录鉴权，只能localhost / 可信Tailscale私网使用，不能公开到公网。
- **手机 / 声音 / 通知**：系统清理后的通知、返回 / 键盘、卓易通与真机视觉、Huawei Push、签名发布按 [统一待办](../DEVICE_ACCEPTANCE_BACKLOG.md) 继续暂缓。没有设备变更，不新增重复真机任务。
- **真实质量与收益**：R1长期缓存 / 净费用、人工语义与情感体验、长期学习 / 行动收益未签收。Embedding / 自动资料绑定、通用恢复写入等不在R9完成承诺内。
- **旧设备遗留**：旧localStorage不读不清；若曾存明文旧Key，它可能仍在原浏览器，物理擦除 / 轮换需要另行明确操作，不能声称删除清理器就清掉秘密。

收费模型 / Embedding调用0，测试费用¥0；原共享预算余额下界¥2.826501434不重置。自动测试与私网可用并不等于完整产品、公开发布或真机验收完成。

R9没有新增数据库迁移：需要回退时，回退应用代码 / 配套客户端或本轮测试文档，数据库保持原34份Schema，不为回退R9执行down或down -v。历史材料从 [固定Git索引](../HISTORY.md) 只读查阅；真实数据灾备仍按 [自托管](../SELF_HOSTING.md) 和 [数据库手册](../DATABASE_OPERATIONS.md) 操作，不能把合成引擎快照当生产备份。

R9封版后回到实际使用与原有发布完善顺序，由用户决定下一项；不自动展开安全升级、手机适配或新功能。
