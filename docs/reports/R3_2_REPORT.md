# R3.2：对话模式与主动问候模板交付

日期：2026-10-15。结论：实际模板、版本兼容与工程验证已交付；真实模型质量/自然度/费用与手机真机体验仍待用户验收，不宣称已经通过模型质量对照。

## 1. 改动与边界

- 自动：按当前任务选表达方式，先答能答的部分，不机械追问或心理分析。
- 专业：先结论，必要时解释假设、推导、证据和核验方法，不能假装搜索/运行代码。
- 陪伴：回应具体感受，用户只想倾诉时不急给计划；温和不同意，不为安慰改变事实。
- 反思：一次一到两个具体问题，承接已回答内容；用户要直接建议时先回答。
- Persona：明确本次任务/格式/篇幅优先于默认风格，不必每轮问句结尾，只承接提供的上下文。
- 主动联系：只润色规则模板正文，原因解释保留在 rationale；用户关闭/暂停与原有触发限制全部不变，无新增模型调用。
- Composer 为 `r3.2/mode-prompts-v1`，Mode/Persona 层各自版本化；旧 Composer 导出兼容保留，历史内容不重写。主动问候版本是源码常量，没有新增通知版本字段或迁移。

详细使用、实现文件与预算取舍见 [MODE_PROMPT_GUIDE](../MODE_PROMPT_GUIDE.md)。新闻/书籍/定时任务/学习/独立游戏模板没有在本轮修改，下一步 R3.3 处理。

## 3. 部署中的换行问题

新 Windows 工作树的 SQL 为 CRLF，而本机已应用的迁移来自原工作区的 LF 文件；严格 checksum 校验阻止了新 Web/Worker 启动。没有绕过保护、重写历史 checksum 或清空数据库。

逐一核对全部 56 份 up/rollback SQL：仅换行不同，规范化 LF 后 SHA-256 与原工作区字节完全一致。机械格式化恢复同样字节，再重建启动成功；Git 中 SQL 内容无差异，新增 `.gitattributes` 的 `*.sql text eol=lf` 与测试固定后续工作树行为。迁移实现和历史 SQL 内容保持不变，也未新增迁移。

构建时 npm ci 审计输出 19 项告警（含 3 项 critical）；本轮未新增/升级依赖，也未运行自动 audit fix，不能将所有告警都归因于 Next.js。现有依赖问题仍需发布前单独审查，不因功能测试通过而忽略。
