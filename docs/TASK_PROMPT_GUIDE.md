# R3.3：任务、学习与独立游戏提示词

日期：2026-10-15。本文描述已实现的模板和工程契约，不代表真实模型已通过质量评测。R3.2 的聊天模式、Persona 和主动问候保持不变。

## 1. 用户可见变化

| 任务 | 本轮实际修改 | 仍由代码执行的约束 |
|---|---|---|
| 定时 AI | 到期直接交付独立可读结果；条件缺失时给有前提的安排，不等待追问、不假装发邮件或创建提醒 | 调度、Run、Inbox、取消、租约和投递，不由模型决定 |
| 新闻简报 | 精确标题；不混淆报道日/事件日，证据不足不凑数；国内外有材料才覆盖，事实与影响判断分开 | 搜索/新颖性过滤、来源编号和标题校验、代码附来源；可选反思仍为原先独立调用 |
| 书籍推荐 | 精确四标题；匹配显式画像，避免重复译名凑数；估算投入、可操作试读、不编章节或版本 | 每本引用、2–3 本和标题校验；不足数量仍显示失败，未放宽为无证据推荐 |
| 思考问题 | 3–5 个不同角度的候选，一题一个焦点、一个问号、12–120 字；风格与禁区适配，不替用户诊断 | 禁区/重复/长度/负担筛选、历史去重与最终数量；模型不声称看过未提供历史 |
| 背书复述 | 先核关键概念/关系，再看遗漏；允许等义改写，不照抄 localScore；分段评分参考和具体下一步 | 输入/输出 Schema、权限与本地评分回退；仍是语义复述，不是严格默写/拼写工具 |
| 解题 | hint/guided/check/explain 深度明确；提示不从其他字段泄露答案，缺条件/图片不清先澄清；空作答不诊断错因 | 图片附件、注册操作、结果 Schema、既有算术核验；数值核验不等于完整证明 |
| 复习卡 | 一张卡聚焦一个可迁移概念；可脱离原对话作答；未知错因不固化，控制字段长度 | Schema 与待确认草稿；生成文本不等于已保存或已排期 |
| 独立游戏 | 区分扮演/跑团/互动故事节奏；尊重玩家控制权，最新状态优先；未提供检定不编结果，叙述与补丁一致 | 分支祖先链、宿主骰子/检定、状态补丁校验与版本提交；没有新增抽卡工具 |

新闻模型正文的二级标题只能是 `## 今日重点`、`## 为什么值得关注`。书籍只能是 `## 本次推荐`、`## 为什么现在推荐`、`## 阅读门槛与投入`、`## 试读与判断`。章节解释放在独立说明中，不再拼进标题行。代码附加来源后的最终成品可以包含来源章节。

引用编号存在，仅证明引用契约满足，不证明来源确实支持每句断言。提示深度、真实评分合理性、书目信息准确性、角色自然度仍需真实模型人工对照；提示词不能替代事实核验或工具实现。

## 2. 调用与版本

```text
Task Worker / 内容生成器 / 受控学习操作
  → AgentPromptGenerator
  → 按 business 选择稳定 System 前缀 + 本次材料/图片
  → Measured Provider → 原有验证器 → 原有业务保存/交付

GameTurnService → 世界/角色 + 所选分支 + 宿主状态/工具结果
  → GameNarrativeGenerator → Measured Provider
  → 补丁验证/应用 → 版本化提交
```

- `web/lib/ai/taskPromptProfiles.ts`：七种任务前缀与版本；不再把所有前台学习标成定时任务。无 business 的旧调用仍默认为 `agent-task`；文本/图片选用同一任务前缀。其他业务值只获得中性前缀，不表示新增了上下文摘要能力。
- `web/lib/tasks/{agentPromptGenerator,personalBriefingGenerator,bookRecommendationGenerator,reflectionQuestionGenerator}.ts`：实际任务/内容调用与模板。
- `web/lib/plugins/hostCapabilityAdapters.ts`：三种已注册受控学习操作；未新增插件协议、权限或自主模型循环。
- `web/lib/game/{gameTurnService,gameNarrativeGenerator}.ts`：独立 GameSession 的实际提示和传输，区别于旧娱乐聊天。

版本分别为 `agent-task/r3.3-v1`、`news/r3.3-v1`、`books/r3.3-v1`、`reflection/r3.3-v1`、`memorization/r3.3-v1`、`problem-solving/r3.3-v1`、`review-card/r3.3-v1`、`game/r3.3-v1`。版本同时随真实 Provider 请求传入，并作为可选 `promptVersion` 存入现有用量 JSONB；不向模型 API 添加非标准请求字段、不存 Prompt 正文/Key。

旧用量记录不含该字段仍可读取；本轮无 SQL 迁移、无历史数据重写，也没有新增任务 Prompt 导出功能。原聊天 Prompt Envelope/导出兼容不变。

## 3. 基线与成本

- 原 `baseline.json`（R3.1，31 例）和 `baseline-r3.2.json`（51 例）原样保留。
- 当前 `baseline-r3.3.json`：67 例，21 个源码指纹；新增八类任务各两个待人工评价场景。
- 与 R3.2 相比：旧 51 例输入/判定定义不变，20 个原任务/游戏请求变化；聊天请求没有变化，无样例删除。
- `web/evals/r3/taskQualityScenarios.ts` 覆盖缺条件、虚假执行、新闻日期/证据、书籍章节/预算、提问负担、复述关系错误/评分注入、无工具、复习卡独立性与未决检定等。

在 `web` 执行 `npm run eval:prompts` 检查漂移与 R3.1/R3.2 差异；`-- --review-sheet` 输出待填写的人工评审表。命令禁止网络调用、不读取真实凭据，模拟输出仅验证实际拼装、版本归属和格式校验。

既有可比较请求增加 70–599 个文本字符，例如新闻 +212、书籍 +229、反思 +350、背书 +376、解题 +599、复习卡 +344、游戏 +400。这是表达清楚任务规则的开销，不是 Token/缓存/费用测量。稳定前缀仍在动态材料之前，未填充无用缓存文本、未新增第二模型裁判或自动修复重试。

## 4. 生效与保留项

Docker Web/Worker 更新后，新执行的任务、学习评价和游戏回合使用新版；历史结果不重生成。已有任务无需重建，仍按原排期执行。此次客户端代码不变，已有本地 React APK 连接新版服务器即可使用这些服务端模板，无需专门重打 APK。

建议后续用同一 Provider/模型与相同输入，人工检查：新闻日期和来源、书籍真实性与试读价值、等义复述/事实颠倒、仅提示与详细解答的区别、模糊图片、无作答时的评价、未决游戏检定。真实模型测试会产生费用，需先确认预算；不要为验收额外开启主动联系或创建长期定时任务。

下一步 R3.4：补齐每类至少五个正常/边界任务样例、集成回归及质量/成本对照。逐字/拼写检查、抽背/抽卡等实际工具仍在 R4，资料库/RAG/摘要/记忆宫殿仍在 R5；华为通知、移动真机、R1 收益、R2 视觉和发布前依赖/安全验收继续保留。
