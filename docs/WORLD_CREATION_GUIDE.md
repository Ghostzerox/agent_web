# R10.3：世界创作闭环

2026-10-19。R10.3实现可玩起始区域的创作、持久化、发布和存档绑定；后续[R10.4设计指南](ITEM_CHARACTER_DESIGN_GUIDE.md)已补充道具 / 人物设计、指定属性和初始放置，当前新能力与容量以该指南为准。本页保留世界基础操作与R10.3交付证据。与内置雾港共用同一探索引擎。不改变普通聊天、旧 d20 游戏或已存在的故事。

## 如何使用

1. 娱乐 → 我的世界。输入粗略描述，“世界规则与限制”中可选择超自然与数值策略、填写硬约束。已有世界可直接继续编辑。
2. “创建世界”只保存描述，成功自动进入编辑，不调用AI。选择“手动开始”载入空白表单，或“生成草稿”；后者在确认面板显示范围、当前模型与可能费用，点击“开始生成”才请求模型，取消不调用模型。
3. 桌面按世界设定 / 地图 / 人物与社会 / 道具与事件 / 检查分组，手机用“当前分区”选择。普通分区切换保留未保存内容；道具、人物、事件设计进入独立子页，离开工作台仍保护草稿。
4. 保存更改后可局部重生成。锁定以“部分”为单位，锁定部分仍可手动编辑，但生成器不能修改；不是逐字段锁定。原始描述和政策始终由用户控制，AI 来源按部分标注，手动修改后改标用户编辑。按钮禁用会说明未保存、已锁定等原因。已有道具时不允许整稿覆盖，改用各部分生成与道具设计入口。
5. 预览检查通过后，勾选“我已审阅”再发布。发布产生不可变修订，不创建存档、不推进剧情。发布后直接点“开始新旅程”，确认创建所选版本的独立存档，再“打开新旅程”并“开启探索世界”；旧版本仍可在折叠历史中选择。
6. 新局可移动、了解环境、与遇见的人物交流；有预设事件时可参与或拒绝，没有也能自由行动。移动 / 调查 / 事件结算不调用模型；明确发送自由行动 / 人物台词、请求主持建议或确认“行动中自然相遇”才调用模型。调用处的AI用量条自动展示已返回的实际Token数据，详见[Token指南](TOKEN_COST_GUIDE.md)。

## 自由行动与结果恢复（2026-10-23）

当前世界创作为`world-authoring-v6`：起始区域不等于整个世界，不把地图做成必须依次解开的关卡；非用户指定或世界级必要的人物默认不预写，功能性职业不自动升格为带隐藏剧情的重要人物。已有世界不自动删除人物 / 事件，模型是否实际遵守题材仍需审阅。

游玩时选择“自由行动”，输入休息、练习、观察或自己选择的尝试，发送后以一次模型调用产生场景结果；不必接任务、触发事件或选择预设剧情。合法结果进入当前分支的完整回合正文、场景摘录与历史，时间推进一次，刷新可读，兄弟分支不继承。取消、坏JSON、非空状态补丁或持久化版本冲突不保存新回合，不自动重试。Prompt为`world-free-action/v1`，沿用原Provider与用量条，无默认输出Token配额。

这是**场景级开放行动**，不是完整无界世界模拟。地图移动 / 新地区、具名人物、库存、交易、关系与事件的结构变动仍走对应工具；旁白不能冒充已结算奖励。场景结果仅给玩家，不直接广播为所有NPC的知识。纯行动输入才裁决；旁白建议及混合输入仍按建议处理，私人想法 / 场外指令单独发送不调用模型。现有剧情是可选背景，不是行动的前置条件。近期上下文使用有界摘录，完整正文保留在回合中，不代表无限长期记忆。

**恢复完整生成文本，不必再次调用AI**：对应世界 → 更多 → 从文件恢复草稿 → 选择`.txt` / `.json`或粘贴 → 检查并放入表单 → 审阅 → 保存更改。文件只在本机读取和检查；保存才发到自己的服务端，不自动发布或更新旧局。恢复世界生成部分，独立道具 / 卡池 / 事件设计保留，已有道具不能用空items覆盖。改动受保护部分会被阻止，先核对保护设置，不自动解锁。

旧ID限制24字符，可能拒绝正常的描述性英文ID；当前统一50字符，预留运行时60字符ID中`-discovery`等后缀空间，保留引用 / 保留字检查，不截断或重命名。JSON语法与字段结构分开报告：移除BOM / 外围空白、完整围栏或解开一层JSON字符串是无损处理；不补造遗漏字段，不修成看似完整的半段世界。解析器有位置时显示行列；重检后的横幅跟随最新分类，不滞留旧“JSON格式”结论。

本次附件是合法JSON，并非括号不完整；旧契约拒绝其中一个26字符史料ID。修正后本地结构 / 引用检查通过并可编译为6地点定义；正文没有入库、提交或上传。仅凭附件不能确认之前原始API正文是否带包装或与附件一致，历史语法错误没有被复现，不能混同这两种问题。

参考[SillyTavern世界资料](https://github.com/SillyTavern/SillyTavern-Docs/blob/main/Usage/worldinfo.md)的按需世界上下文；[ink](https://github.com/inkle/ink)用于对照预写分支与自由模拟，不迁入脚本引擎；阅读[jsonrepair](https://github.com/josdejong/jsonrepair)后仅借鉴区分包装与内容损坏，不引入依赖或自动补齐缺失事实。无新增依赖或数据库迁移。

## 同一描述重新设计与覆盖（2026-10-22）

已有草稿确认“生成”表示：依据已保存的粗略描述重新设计所选部分，而非把第一版当成必须复述的事实；描述无需改变。生成范围为“全部未保护部分”时重新设计全部可生成分区，单部分则只替换当前部分。已锁定、未选分区及独立道具 / 卡池 / 事件的边界仍保留，已有道具时仍不允许世界整稿覆盖。

`world-authoring-v5`明确区分create / regenerate，Prompt仅发送用户描述、约束和不可改动的其他分区；待替换的旧文本不再反复喂给模型作为底稿。实际数据库合并仍保留其他分区，不会因精简Prompt而删除它们。生成结果全部未变时明确提示“与原稿完全相同”，不增加版本、不声称覆盖成功、不自动再次收费；有改动时显示保存版本和实际变化分区。页面底部常显草稿版本。

相同描述不能保证模型每次输出完全不同，也不要求空人物、空事件等合理空值为了“不同”而强加剧情。最新结果仍需人工审阅；不会自动重新生成用户现有世界或影响已发布修订 / 旧旅程。排查时只读版本和用量元数据不足以复原首版正文，不能冒称已经比对过用户两次完整输出。

参考经典开源[Vercel AI SDK持久化与稳定ID](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-message-persistence)区分新生成、持久化和重放；保留既有requestId幂等去重，仅相同请求重放已有回执，每次成功后的新生成仍使用新请求ID。不安装SDK、不变更存储结构或增加旧版兼容轨。

离线评测随当前版本同步：世界生成清单登记v5，R10合成旅程按当前版本分发应答；R3只更新世界Prompt及共享差异比较助手的源码指纹，不改原80项请求 / 夹具。真实模型的新设计质量仍需用户实际审阅。

本轮验证：`npm run check`的171文件 / 742项单元与SQL、80项离线Prompt通过；生产Web与本地React各10项浏览器用例通过（`world-regeneration` / `world-authoring` / `r12-interaction`），涵盖同描述连续整稿替换、立即展示 / 刷新持久化、完全未变、锁定 / 幂等、发布与草稿保护。全部使用合成世界与假模型，不计入真实模型质量签收，不产生测试API费用。Docker健康，原PostgreSQL卷与报错世界版本保留；容器只读核对v5、精简上下文及无变化检查均已部署。

同次重新生成Debug APK：`web/android/app/build/outputs/apk/debug/app-debug.apk`，5,732,772字节，SHA256 `118139ABB464702AF99CE7CC6A58BA0CA98E6DC3A49B5B8625A16F76232D195A`；本地Bundle / 既有Tailscale Origin / 无`server.url`与v2签名校验通过。未安装手机，真机仍统一暂缓；没有为验证修正而发送用户原始世界或自动替用户生成。

## 开放世界，而非默认剧本杀（2026-10-21）

v4默认按用户题材构建生活、旅行、经营、修行、建设、生存、社交或冒险环境；只有用户要求时才偏向悬疑 / 解谜，不默认安排谜案、失踪、阴谋、档案线索链或固定结局。`characters`允许0–8项，优先只预设用户指定 / 世界观必要的重要人物，普通NPC不必提前写满。`hook`可为null，不再强制至少一个NPC与初始事件。手填起始表单默认空人物 / 空事件，区域观察也不再一律叫“调查线索”。已有世界、人物和故事不自动删除或重写；旧的具体剧情模板仍是可选内容，不拿它替代通用默认。

普通人物可在探索的地图 / 人物子页展开“行动中自然相遇”，描述在**当前地点**的活动，确认一次模型调用。结果可以是一个符合当地环境的普通NPC，也可以无人；不强行使每次活动都遇到人或引出故事。此入口是显式行动，不是后台持续模拟或每步移动自动收费。重要人物的既有定义不能被相遇生成覆盖；不预写NPC的完整故事弧、未来关系、玩家思想或结局。

结果经严格字段、重名、地点和显式超自然政策检查，成功后写入当前回合的公开人物卡与`encounters`来源；复用已有树形快照、乐观版本与请求回执。它不会回写发布模板、改其他存档或其他分支；回到相遇前的分支，此人物不在该分支。以后可以通过同一人物入口对话、赠送已有物品或在当前分支事件中引用，不凭空开放交易 / 奖励或秘密。

相遇生成只给世界公共规则 / 社会背景、当前地点、在场者简要信息与活动，不读取作者秘密、主持备注、玩家私人想法或全局聊天记忆。生成卡只有公开背景，没有另造私密人物档案；其后单人调用仍使用来源与感知隔离，初始知识目录为空。每分支最多20个相遇人物且共用50人物容量，这是存档容量 / 引擎约束，不是Token省费配额。取消、坏JSON或约束失败不保存人物，不自动重试；API可能已收费。

参考[SillyTavern动态世界资料](https://github.com/SillyTavern/SillyTavern-Docs/blob/main/Usage/worldinfo.md)的“世界背景与按需上下文分开”，没有迁入角色卡协议或整套世界引擎。结构检查不能证明全部自然语言符合世界观或叙事质量，仍需实际使用审阅；本轮仅离线 / 合成测试，不发送用户原始世界。

初始手动表单只是结构示例，不是AI已理解创意。请完善名称、背景和当地环境后审阅。R12已为地点、预设人物、史料与档位提供普通表单增删；删除被引用的对象会先提示处理引用，不偷偷清空关系。未保存移除可在未继续编辑时撤销。高级JSON保留为专家入口。

工作台以三阶段提示、当前分区和底部“保存更改 / 检查与发布”连接步骤，不再依赖顶部长说明。高级JSON先“应用修改”，再“保存更改”；尚未应用时不能编辑普通字段、换区或假保存，也可放弃JSON编辑。“更多 → 重新加载”只有弃稿时才确认。AI生成仍自动保存到草稿，发布 / 加入世界 / 获取入包仍分别显式执行。

## 数据与代码

```text
描述 / 政策
  → game_world_drafts（可编辑内容、来源、锁定、乐观版本、生成回执）
  → 校验 + compileWorld
  → game_world_revisions（已发布 WorldTemplate，只追加）
  → game_world_saves（存档 → 固定修订，创建请求幂等）
  → 既有 GameSession / 树形回合 / 检查点 / 探索引擎
```

- 迁移 `0034_game_world_authoring.sql` 只增加上述三表，配套回滚；迁移总数35。前34份既有迁移不改写，不删除用户故事、浏览器存储或 Docker 卷。
- 草稿为 PostgreSQL JSONB，不是浏览器 localStorage。UI 状态只有未保存编辑；保存 / 刷新与其他设备通过同一 API 重读。
- `lib/game/worlds/contracts.ts`：当前 DTO 与容量边界；`compile.ts`：可执行定义编译；`generation.ts`：显式、可取消的整稿 / 局部生成；`blueprint.ts`：手动起始结构。
- `lib/repositories/gameWorldRepository.ts`：所有者范围、版本冲突、事务发布、创建存档与固定修订解析。
- `/api/v1/game-worlds`：GET列表 / POST创建；`/:id`：GET详情 / PATCH保存；`/:id/generate`、`publish`、`saves`：显式 POST 操作。发布必须同时有当前 `expectedVersion`、`confirmed: true` 和 `constraintReviewConfirmed: true`；不接受客户端提交已编译定义。
- `components/game/WorldCreationWorkspace.tsx` / `WorldSectionEditor.tsx`：Next 与本地 React 共用界面，不增加全局创作模式或第二套移动业务。

存档只引用已发布修订。每次回合从数据库加载本局固定定义，再传给同一个同步引擎；不依赖进程内临时登记。发布 r2 不会把 r1 的地图、人物或过去改写。当前没有旧局原地升级功能；选择新版需新建存档。新世界存档的旧“世界设定”编辑表单改为指向创作工作台，避免以为编辑简介就改了运行定义。有存档引用的定义受数据库外键保护；当前不提供删除世界 / 修订的入口。

## 校验与公开范围

- 草稿限制为2–8个地点、0–8个预设人物、最多12条史料和至多一个初始可拒绝交互（可为空）。检查 ID、引用、地图可达和可返回、人物位置、知情者、事件地点和字典。
- “禁止超自然”与显式 `usesSupernatural` 冲突会阻止发布；`conflicts` 非空也会阻止发布。任意中文硬约束的语义不能由结构校验证明，必须人工审阅。通过不等于证明每段故事自洽。
- 定性世界真实省略 `progress.level`、物品 `level` 与 `levelsPerTier`；轻数值世界保留有界等级。既有雾港继续遵守自身轻数值契约，不改写旧快照。当前不是任意属性数值系统，也不是完整道具设计。
- 时代、技术与能力规则是共同世界约束；文化、势力、历史和世界前提随固定定义进入主持上下文，不因此成为每个 NPC 的完整知识。
- 公开史料可通过当地调查发现；作者秘密不自动进入公开状态。作者备注与秘密只进入主持范围。基础人物只收到其 `knownBy` 明确授权的初始资料及实际感知记录，保留 fact / rumor / legend / opinion；作者可在设计视图审阅知情者。
- “作者秘密”不是对作者本人的访问控制。若你明确设定某人物知道秘密，它可以在人物请求中出现；系统保证不因加载整个世界就向所有人物发送秘密，不保证模型永不猜测或转述。
- 上下文保持14000字符预算；先缩减次要内容，不静默删除硬约束 / 作者秘密来换取成功，必需资料仍超限则明确报错。请精简草稿后发布新修订。

## 费用、失败和并发

复用当前模型、Provider和用量记录，业务仍为`game`、世界生成Prompt为`r10/world-authoring-v6`，相遇为`world-encounter/v1`，自由行动为`world-free-action/v1`。**整稿、单部分和普通游戏均无应用默认输出Token配额**；不再用16384 / 8192 / 6144等固定值省费。仅用户显式配置或已授权付费测试可设置上限，详见[Token指南](TOKEN_COST_GUIDE.md)；供应商自身仍有限制。

世界创作恢复模型默认思考能力，不强制非思考来适配低配额。新提示词从实际Zod字段契约生成所选部分Schema，说明required字段与类型；稳定协议 / Schema前置、用户资料后置，删除重复完整example。参考[Zod内置JSON Schema](https://zod.dev/json-schema)、[DeepSeek JSON输出](https://api-docs.deepseek.com/guides/json_mode/)及[SillyTavern结构化输出问题](https://github.com/SillyTavern/SillyTavern/issues/5569)；没有引入新依赖、切换API或照搬容错修补代码。

历史故障分两类：先有6144输出 / 6143思考导致截断，之后有3530输出、正常`stop`却未通过结构校验。后者不能靠加预算解决。校验区分JSON格式、部分范围、字段结构和体积，显示具体路径（如`characters.0.profile.privateBackground`）；当前接受完整对象及上述无损包装，不补括号、不猜缺失设定、不丢弃越权字段来伪装成功。

结构失败时返回本次结果与最多24条字段问题给当前请求者，不写日志、生产草稿或浏览器存储；工作台出现“检查与修正生成结果”，可展开JSON、手动修正并“本地检查并应用到草稿”。此操作不调用模型 / 不收费，结构通过才放入当前表单，仍须手动保存和预览规则检查，不自动发布。版本或锁定范围变化时不允许直接应用；保存冲突仍保留本地编辑。失败结果仅在当前页面内，刷新前应先复制，需要时明确丢弃；不是跨端恢复库。旧版已经丢弃的失败回复无法事后恢复。

截断仍视为失败，不把半段JSON作为有效世界；首次完整生成之后可单独重生成一部分，不自动生成多个候选或循环纠错。没有模型配置也可以手工保存 / 发布 / 游玩确定性动作。50,000字符草稿容量、引用 / 字段校验和锁定规则是数据 / 引擎边界，并未冒充Token优化取消。

无效 JSON、额外改写其他部分、取消、模型失败或生成期间出现新版本，都不覆盖原草稿或运行中的故事。版本冲突时保留本地表单；复制需保留内容，再明确“从服务端重读”。生成期间禁用编辑，避免结果覆盖尚未提交的输入。
