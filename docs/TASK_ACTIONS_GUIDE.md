2026-10-17。入口为任务模块内“行动与打卡”；“定时任务”保留原 TaskManager，已有 `?task=…&edit=1` 深链仍打开原调度视图。

## R6.1：行动事实

- 已实现手动待办、备注、截止日、完成 / 撤销、编辑、暂停 / 恢复与归档。归档保留历史，不删除提醒。
- `action_items` 保存独立行动 / 习惯 / 目标与版本；`action_entries` 保存每个事项 / 业务日唯一的当前行动记录；`action_events` 保留每次操作和结果用于审计与重试幂等。原 Task / TaskRun / Inbox 不充当用户完成记录。
- 新增迁移 `0033_task_actions.sql`，回退会删除上述三张表及其行动数据；不影响旧任务表。生产应用前必须先备份，隔离验证迁移 / 恢复。当前仅本地测试，尚未更新运行中的 Docker。
- `/api/v1/actions` 的 GET 读取上海业务日和指定日期范围快照；POST 接受严格 create / update / record / rule / link 命令。用户由服务端固定，不允许自填 owner。
- 每个写操作携带 `mutationId`；相同操作重放不重复保存，复用编号提交不同内容拒绝。编辑和完成操作还需 `expectedVersion`；跨端冲突不覆盖原值，页面保留编辑草稿，刷新后需核对再重试。
- 日期按 `Asia/Shanghai`；不允许未来打卡，补记最多365天且不能早于开始日。普通待办只有一个实际完成日；要更正日期，先撤销原完成。
- 读取最多1000事项、指定最多366天 / 20000条当期记录，超限报错而非静默截断；首期使用同用户事务锁，适合个人使用。当前不支持离线写入、硬删除或自动认定已完成。

R6.1定点测试20项通过（含旧任务和通知映射），类型与定点 lint 通过；没有收费模型调用或真机测试。

## R6.2：习惯与实际打卡

- 任务行动区可创建每日、指定星期或每周 N 天达标的习惯；每日量与单位可表达勾选、单词数量或分钟时长。
- 打卡填写当天总量，不是累加；再次保存是显式更正。支持过去365天补卡、跳过、请假、撤销和备注；请假与跳过的统计语义不同，后续统计分别处理。
- 规则修改只从未来且晚于最后规则版本的日期生效；历史打卡还保存当日规则副本。暂停立即禁止新记录（撤销允许），计划分母从次日暂停，恢复对应保留历史；需要请假可在暂停前记录。
- 打卡与规则编辑携带打开表单时的版本，刷新不把新版本自动当作旧草稿的保存依据。归档保留全部历史，可恢复。
- 新增真实 SQL 测试覆盖数量更正唯一性、历史目标、指定星期、补卡标记与暂停版本；行动仓储7项、类型和定点 lint 通过。R6.3统计 / 目标、R6.4提醒联动仍在开发，运行 Docker 尚未更新。
