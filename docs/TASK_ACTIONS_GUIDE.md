2026-10-17。入口为任务模块内“行动与打卡”；“定时任务”保留原 TaskManager，已有 `?task=…&edit=1` 深链仍打开原调度视图。

## R6.1：行动事实

- 已实现手动待办、备注、截止日、完成 / 撤销、编辑、暂停 / 恢复与归档。归档保留历史，不删除提醒。
- `action_items` 保存独立行动 / 习惯 / 目标与版本；`action_entries` 保存每个事项 / 业务日唯一的当前行动记录；`action_events` 保留每次操作和结果用于审计与重试幂等。原 Task / TaskRun / Inbox 不充当用户完成记录。
- 新增迁移 `0033_task_actions.sql`，回退会删除上述三张表及其行动数据；不影响旧任务表。本轮已备份、隔离恢复 / up / down，并更新本机 Docker（当前34份迁移）。
- 若未来回退，必须先备份并配套回退应用版本；仅删除新表却运行新版应用会使行动接口及提醒复核不可用，不能直接在生产照抄隔离测试的 down 操作。
- `/api/v1/actions` 的 GET 读取上海业务日和指定日期范围快照；POST 接受严格 create / update / record / rule / link 命令。用户由服务端固定，不允许自填 owner。
- 每个写操作携带 `mutationId`；相同操作重放不重复保存，复用编号提交不同内容拒绝。编辑和完成操作还需 `expectedVersion`；跨端冲突不覆盖原值，页面保留编辑草稿，刷新后需核对再重试。
- 日期按 `Asia/Shanghai`；不允许未来打卡，补记最多365天且不能早于开始日。普通待办只有一个实际完成日；要更正日期，先撤销原完成。
- 读取最多1000事项、指定最多366天 / 20000条当期记录，超限报错而非静默截断；首期使用同用户事务锁，适合个人使用。当前不支持离线写入、硬删除或自动认定已完成。

R6.1定点测试20项通过（含旧任务和通知映射），类型与定点 lint 通过；没有收费模型调用或真机测试。

## R6.2：习惯与实际打卡

- 任务行动区可创建每日、指定星期或每周 N 天达标的习惯；每日量与单位可表达勾选、单词数量或分钟时长。
- 打卡填写当天总量，不是累加；再次保存是显式更正。支持过去365天补卡、跳过、请假、撤销和备注；请假与跳过的统计语义不同，后续统计分别处理。
- 规则修改只从未来且晚于最后规则版本的日期生效；历史打卡还保存当日规则副本。暂停立即禁止新记录（撤销允许），计划分母从次日暂停，恢复对应保留历史；需要请假可在暂停前记录。
- 打卡与规则编辑携带打开表单时的版本，刷新不把新版本自动当作旧草稿的保存依据。归档保留全部历史，可恢复。
- 新增真实 SQL 测试覆盖数量更正唯一性、历史目标、指定星期、补卡标记与暂停版本。后续涉及每周 N 天的规则切换 / 目标调整限定周一生效，避免同一周混用两个目标。

## R6.3：日历、统计与目标

- 月历可切换月份、查看每日记录、完成量、补记标记和操作时间；加载失败不把旧月份显示为成功。行动表读取最近365天用于补卡核对，月历另外读取所选月份及相邻完整周。
- 每日 / 指定星期：截至今天的计划日为分母，请假排除、跳过计未完成、撤销恢复未完成；今天尚未结束时不提前断连续。累计 / 连续 / 最长均明确限定本次区间，不冒充终身收益。
- 每周 N 天按周一到周日单列，首尾周含相邻月；每周目标不超过实际可执行且未请假的日数，未结束的周不判失败。周频连续与日频连续分开。
- 目标可填写完成标准，将已有待办 / 习惯关联或解除；一次性里程碑按真实完成显示，长期习惯另列，不混成虚假的100%。目标不能嵌套，归档目标不删除或自动完成其子任务。
- 可编辑目标名称与完成标准；普通待办支持“今日跳过”，不会被模型或系统自动判成完成。

## R6.4：提醒、导出与跨端

- “提醒关联与数据导出”中先读取现有提醒，选择一个行动 / 习惯和一个自己的普通提醒后确认绑定。一个提醒只绑定一个事项；不能绑定 AI 生成任务或目标本身。新提醒仍在“定时任务”中创建。
- 用户完成、当日跳过 / 请假、习惯当日不在计划或周目标已满、行动暂停 / 归档时，服务端在 Inbox 最终写入边界复核并跳过该次提醒；对应 Run 记为 skipped，不伪造已完成行动，也不创建新 Inbox / Push。此判断与行动写入使用同用户事务锁。
- 撤销、更正规则、恢复或解绑影响后续执行，不补发已跳过的旧 Run；已保存的 Inbox / 已送达通知不撤回。删除提醒不会删除行动历史，原关联显示不可用后可显式解绑。
- Task API 的 `localActionReminder` 是设备调度建议，不改原 Task 的 `nextRunAt` / status。关联事项的 APK 提醒改用下一次有效时间的一次性快照；非关联提醒仍沿用原重复调度。写行动成功后先撤销受影响旧缓存，再读取新计划；刷新失败显示明确警告，不恢复旧重复提醒来冒充成功。
- **离线边界**：关联提醒不是永久离线习惯调度器。后续快照需要手机在线启动 / 恢复、通知同步或任务刷新；另一端更改不能瞬间传到离线手机。长时间离线、系统强行停止与华为兼容层清理后的送达仍未验证。既有普通提醒离线能力不变；不新增 Huawei Push 或常驻保活。
- 导出格式 `ai-study-companion.actions` v1，包含全部事项定义 / 规则、所选业务日期的当前记录，以及所选操作日期的更正历史；最多366天、5000个操作、4MB，超限拒绝，不静默裁剪。包含私人备注，需勾选确认。Web 下载 JSON，移动端复用文件分享适配器；打开分享不等于实际保存。
- 文件不读取模型凭据、原始聊天或其他模块数据库；自己写在备注里的秘密不会自动识别脱敏。不是完整灾备，不提供自动覆盖恢复或导入。
