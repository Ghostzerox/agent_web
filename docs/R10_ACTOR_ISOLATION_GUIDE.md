# R10.2：主持 / 人物隔离

2026-10-19。R7 探索路径现已接入语义输入、人物感知记录与独立模型请求；不会改写旧 d20 玩法。[R10.3世界创作](WORLD_CREATION_GUIDE.md)已交付基础闭环，[R10.4道具与人物设计](ITEM_CHARACTER_DESIGN_GUIDE.md)已接入独立私有资料，[R10.4.1抽卡](ITEM_DRAW_GUIDE.md)入库本身不自动广播；后续[R10.5事件](EVENT_CREATION_GUIDE.md)可在门槛满足时按明确接收者传播有来源信息。规范起点和原有缺口见 [R10.1基线](R10_SEMANTIC_BOUNDARY_BASELINE.md)。

## 使用方式

- 探索存档下方选择“探索输入类型”：台词、行动意图、旁白建议、私人想法、场外创作指令。
- 台词选择回复人物与定向 / 公开范围。只允许当前地点的非玩家人物；定向内容只给对方，公开内容给当前在场人物，但仍只调用一位回复者。
- 人物卡里的“自由 AI 对话”也使用同一流程；折叠区可附带私人想法，单独保存但不进入人物请求。失败保留两份草稿。
- 行动意图 / 旁白建议由主持回应，但不是已完成动作或角色台词。真正移动、交易、发奖、关系与事件变化仍用结构化按钮结算。
- 私人想法 / 场外创作指令单独发送时，只保存本局记录，不调用模型、不推进时间、不更改世界。需要世界编辑 / 发布请进入已实现的 [R10.3工作台](WORLD_CREATION_GUIDE.md)，不会把一条场外意图自动变成已发布世界。
- 人物公开卡中可折叠查看“有来源的交流与感知”，含类型、证据性质、时刻和来源请求。故事记录 / Markdown 导出保留输入类型；完整 JSON 另保留结构化片段与感知数据。

不要把私密想法混写在“台词”文本里：系统按照显式类型处理，不尝试读心重分类。公开 / 定向是信息传递选择，不是改变人物动机的命令。

## 一个请求，一套实现

沿用 `POST /api/v1/game-sessions/:id/turns` 和现有 Provider，不增设第二个模型供应商或多 Agent 框架。新增可选 `semanticInput`：1–8 个有序片段，单片最多 2000 字，正文合计最多 8000 字；使用时必须有 UUID `requestId`，不可混用旧骰子 / 牌堆工具。

```json
{
  "content": "用于非语义客户端显示的输入摘要",
  "parentTurnId": "22222222-2222-4222-8222-222222222222",
  "expectedVersion": 4,
  "requestId": "55555555-5555-4555-8555-555555555555",
  "semanticInput": [
    { "kind": "private_thought", "text": "我先不透露铜钥匙的位置" },
    { "kind": "dialogue", "text": "晚上好", "targetId": "keeper", "channel": "direct" }
  ]
}
```

其他四类片段只有 `kind` / `text`。不接受客户端提供的发言者、世界真相、可任意覆盖的 audience、人物知识、完整上下文或权限范围。服务端将发言者固定为玩家，并验证目标 / 在场；同一回合只选一位回复人物、台词范围一致，防止私聊内容被一份公开回复转述出去。

正文与结构化语义并存时，存档和模型均以语义片段为准，不能借 `content` 额外塞入人物输入。当前人物请求从已验证的感知记录中提取本次台词，忽略传入 Prompt 构建器的原始文字和主持历史。

旧无类型自由文本仍是主持输入，不猜成角色说话。`narrate: true` 的人物动作必须带语义片段；旧 APK / 客户端应更新，不建立旧格式自动猜测链。

## 感知、来源与作用域

探索 JSON 快照新增可选 `cognition`：绑定存档 ID、世界 ID / 修订，保存当前语义输入和最多 200 条感知记录。没有新 SQL 表 / 迁移，既有回合、事务 append、请求回执、检查点和 JSON 导出仍是同一条路径；旧不可变快照不重写。

每条记录保存来源请求、时刻、地点、说话者、接收者、内容类型及证据性质。世界历史不全局广播：

| 来源 | 人物何时获得 |
|---|---|
| 初始世界知识 | 只取当前模板中此人物明确授权的 lore，保留设定来源与 fact / rumor / legend / opinion |
| 玩家台词 | 服务端计算定向对象或实际在场接收者；保存为 statement，不是已证实事实 |
| 宿主交互结果 | 只给已验证交谈 / 询问 / 承诺 / 协助 / 交涉 / 赠送 / 交易的参与者，不读取全局上一条结果 |
| 话题透露的 lore | 合法话题明确揭示的内容，保留原有证据性质 |
| AI 人物回应 | 只给此回合的合理接收者，仍是 statement，不自动成为世界真相 |
| 私人想法 / 场外指令 / 行动意图 / 旁白建议 | 原始输入先保存给玩家；不自动变成 NPC 已观察到的结果 |

构建人物请求时再次检查：同存档 / 世界修订 → 来源请求属于选定祖先或本回合 → 时刻匹配且不晚于当前 → 人物实际收到 → 有界选取。无效来源、兄弟分支、其他世界 / 修订和未来记录在发送前排除。角色身份与发言范围由服务端决定，不能由客户端自报。

人物上下文不接收全局 `lastResult`、原始主持历史、玩家背包、其他人物卡或无来源摘要。预算不足时仅在同一人物的授权投影内缩减记录 / 字段，不能回退为主持；目标无效 / 不在场 / 玩家角色时，动作服务和上下文构建器都明确拒绝。

角色提示词前缀固定，人物资料放到后面的动态上下文；最多选取 20 条近期授权记录，并将上下文 JSON 控制在 14000 字符。没有新增付费总结步骤、全 NPC 每回合调用或人物向量数据库。

R10.6的真实探针表明，请求隔离不能消除模型自己编造证据。当前 `r10/exploration-v3` 进一步限制虚构档案、调查、目击与本人经历，自己的旧台词不能自动成为证据；只有实际收到的传闻可以带来源转述。合成复测的获知前 / 后差异与剩余幻觉风险见 [集成报告](reports/R10_6_REPORT.md)，不承诺零幻觉或完整长期记忆。

## 旧记录与当前限制

旧的 `knownInformation` / `memories` 字符串完整保留在原快照和公开卡中，但不直接导入人物模型记忆，因为没有可靠类型和获知来源，无法无损区分“玩家说”和夹杂的内心 / 旁白。不是删除用户数据；必要信息可重新明确告知人物。新的合法交互使用有来源的记录，之后不再统一写成“玩家说……”字符串。

本期是保守的感知模型：有明确接收者的交流和宿主交互优先，不对全部调查、远处变化、新闻传播自动推断目击者；事件感知扩展随 R10.5 落地。当前工作快照保留 200 条，模型近期窗口最多 20 条；更早记录仍在不可变回合 / 导出中，但尚无人物长期自动压缩、向量搜索或通用世界模拟，不冒称“无限记忆”。

禁止把主持生成的建议再次当作权威事实灌回人物。隔离证明的是没有发送未授权内容，不保证模型永不凭空猜测；自然度、合理推理和角色一致性仍需后续人工语义验收。
