## 1. 产品主线

AI Study Companion 首先是供项目作者长期使用的个人 AI 助手，而不是通用 Agent 框架、专业聊天基础设施或移动端技术演示。它需要把以下体验连接成一个连续闭环：

```text
了解用户
  → 专业地回答
  → 记住经确认的重要信息
  → 按任务与兴趣持续工作
  → 通过 Inbox / 通知主动联系
  → 提出少而精的思考问题并根据反馈调整
```

产品主线按用户价值分为五项：

1. 任务与时间：可靠提醒、AI 定时任务、可追踪结果。
2. 专业问答：搜索、引用、公式、事实与推断边界。
3. 思考与成长：结合目标和上下文提出高质量问题。
4. 新闻与书籍：有来源、去重、有推荐理由的主动内容。
5. 记忆与陪伴：用户可控记忆、稳定人格、自然且克制的主动联系。

学习插件与娱乐模式是后续扩展主线。数据库、Docker、Prompt 审计、评测、Web/APK/HarmonyOS 都是承载或保障能力，不能单独取代用户体验主线。

## 2. 当前判断

Phase 0–2 已完成稳定聊天、服务端数据与可靠任务闭环。Core 3.1–3.5 已完成模式、Prompt Envelope、受控搜索、引用、可见规则检查与轻量回归基线。这些基础可复用于新闻、书籍、记忆与主动联系，但最近连续交付偏向工程保障，产品的“个人、长期、主动、有人味”仍然不足。

因此从 Core 3.5 起执行以下约束：

- 不再继续横向扩张专业回答基础设施。
- Mobile Track 保留现有 APK 与真机清单，只修阻断日常使用的问题。
- Core 3.5 已用轻量、确定性的回归基线封版，不接入第二模型裁判或复杂评测平台。
- 封版后立即转向新闻、书籍、思考问题的可用闭环。
- 随后建设用户可控记忆、Persona 与主动联系，使陪伴建立在连续上下文上。

## 4. Core 3.5 精简边界

Core 3.5 的目的不是证明模型回答正确，而是防止已有契约在后续开发中被意外破坏：

- 固定 25 个样例，覆盖 Mode/Policy/Persona/Memory 顺序和模式边界。
- 覆盖自动/强制/关闭搜索、证据隔离、引用完整性、时效与推断提示。
- 输出 `mode-boundary`、`professional-answer` 和总分。
- 默认基线为 100%；契约变化导致降分时测试失败，必须明确更新样例或修复回归。
- 不请求真实 Provider、不消耗 Token、不访问网络、不写数据库。
- 分数只表示确定性契约保持，不表示事实正确率、帮助度或情感质量。

运行方式：

```bash
cd web
npm run eval:core
```

## 5. 防偏移规则

每个新 Sprint 开始前回答四个问题：

1. 它直接改善哪一项主线用户体验？
2. 用户完成后能看见或感受到什么变化？
3. 是否已有足够的基础能力，仍在继续建设框架而没有形成闭环？
4. 是否挤占了新闻/书籍/思考、记忆、陪伴等尚未落地的核心体验？

如果任务只改善内部架构，必须说明它阻断了哪一个紧邻的用户功能；不能回答时，任务默认后移。每完成一个 Phase，重新评估排序，不机械执行旧路线图。

## 6. 当前主线

Phase 4.1–4.4、Phase 5.1–5.5、Phase 7.1–7.5 与 Phase 6.1–6.5 已完成。GameSession 已提供世界、角色属性与生命、模型回合、树形分支、结构化场景/物品、可信骰子、服务端检定、命名检查点和跨端导出。轻量冒险通过冻结的 Plugin API v1 保存配置并生成待用户确认的游戏草稿，验证新增规则包无需修改核心回合循环。

主要可见功能的阶段交付已齐备，R1 首轮与 R2 实现/自动验证已交付。按最新需求，后续增加 R3 提示词、R4 全模块工具、R5 分域记忆增强，先以现有模式的可见流程逐项推进；R1 收益/摘要验收、R2 视觉确认及移动真机检查继续保留。之后再完成语音/移动发布需求评估、发布前 Phase 5.6 和 Phase 8 作品集交付；不自动扩大第三方插件、完整桌游规则或新 Agent 框架范围。Phase 6.5 的使用、实现与限制见 `GAME_RULE_PACKS.md`。
