# Token、缓存与成本

最近更新：2026-10-01。当前为 R1 实施记录；真实费用/命中收益须以正常使用后的统计或另经同意的收费对照测试为准。

## 用量查看

Web/APK 共用模型配置页面 `/api-key`，点击“查看/刷新用量”，读取 `/api/v1/model/usage` 最近七天的服务端记录。点击本身不调用模型。最多展示最近 5000 次，超限时注明截断；空白历史不补造数据。

`model_usage_calls` 保存每次实际 Provider 调用的最小元数据：业务类型、Provider Origin/Model、状态、请求尝试次数、输入/输出/缓存/推理 Token、延迟、结束原因，以及当时配置的价格与费用估算。DNS 重试计入请求尝试，不重新生成 Prompt；取消/失败若缺少 usage 则费用未知。数据不含 Key、对话、Prompt、模型回复或上游错误正文。

生产入口共用 measured Provider：聊天、AI 任务、新闻、书籍、反思、背诵评分、解题/图片题、复习卡及游戏。Mock 单元测试不写运行数据库，也不请求模型。Provider 用量写入失败或超时只记录无敏感信息的警告，不阻断回答；因此记录不是具有账单完整性保证的计费系统。

缓存命中率按已知缓存的输入 Token 加权计算；同时显示统计覆盖率。缺失字段显示未知，已知 0 才显示 0。推理 Token 是输出用量明细，不额外重复计价。取消/失败和异常终止可能仍产生服务商费用，未收到 usage 不能当作免费。

## 配置价格

服务端 `AI_TOKEN_PRICES_JSON` 默认为 `[]`，不写死任何模型的当前价格。配置对应 Provider Origin/Model 后，未来每次调用快照当时的价格；配置改变不追溯修改历史费用。金额为估算，最终以服务商账单为准，不混合不同货币。

以下数字仅用于说明格式，**不是 DeepSeek 的实际价格**；请按实际模型官方报价填写，并记录来源与日期：

```json
[
  {
    "providerOrigin": "https://api.deepseek.com",
    "model": "your-model",
    "currency": "CNY",
    "inputPerMillion": 2,
    "cachedInputPerMillion": 0.2,
    "outputPerMillion": 3,
    "source": "https://api-docs.deepseek.com/quick_start/pricing",
    "asOf": "2026-10-01"
  }
]
```

自托管配置写入本机 `.env.selfhost`，通过 Compose 同时传给 Web/Worker，随后重启相应服务；本地 npm 开发可放入 `web/.env.local`。不提交真实 Key 或本机环境文件。字段不合法时价格视为未配置；缓存/输出 usage 缺失导致费用无法可靠计算时仍显示未知。

## Provider 缓存兼容

实现前核对 [DeepSeek 缓存文档](https://api-docs.deepseek.com/guides/kv_cache/) 与 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。官方缓存自动管理并匹配前缀，不能保证每次命中；实际字段以请求返回为准。

只对核验过的官方 `api.deepseek.com` 自动发送 `stream_options.include_usage`；任意兼容端点不自动假设支持。解析 `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens` 与兼容的 `prompt_tokens_details.cached_tokens`，校验非负数、输入上限和合计一致性；usage-only SSE chunk 不作为回答正文。不读取或持久化 reasoning_content。

不创建人工预热请求、不填充无用 Prompt、不缓存整段个性化回答。首次冷请求、缓存过期或缓存统计不可用均不影响正常调用。

## 数据迁移

`0027_model_usage_calls.sql` 只新增用量表与索引，不改变原有业务表。`db:rollback` 在本迁移为最后一项时只删除用量表，其历史统计不可恢复，聊天/任务不受影响；必要时先备份。

自 0018 起已采用人工版本化 SQL；R9.4 正式退役滞后的 Drizzle 生成器 / 元数据检查。当前维护 ORM Schema 与前向 / 回滚 SQL，正确性通过迁移 / 回滚集成测试和升级审查验证，见 [数据库手册](DATABASE_OPERATIONS.md)。

## R1.2 缓存友好的装配

- 游戏静态世界/角色规则和已选分支的历史保持前缀；当前状态快照与骰子/检定后置到最新玩家输入之前，既保留可信结果又不提前打断共同历史。未改变回合持久化和工具权限。
- 新闻、书籍和反思先放固定协议，再放必要日期、主题、画像/偏好和外部上下文；新闻日期不删除，来源与事实边界不降低。
- 结构化记忆、检索材料和游戏状态采用稳定紧凑 JSON；对象键排序，数组顺序和用户文本不改写。
- 检索的完整 `fetchedAt` 留在服务端 Retrieval/引用元数据，模型仅接收粗粒度的检索日 `retrievedOn`；来源 `publishedAt` 仍保留用于时效判断。同日重复检索不因秒级时间打断缓存，跨日信息会自然改变前缀。审计 Run ID/时间/标题原本就未发送给模型，继续保持该边界。
- Composer 升级为 `r1/cache-friendly-v1`，Prompt 导出仍支持原有 5.2/5.3 版本与哈希校验。模式/Persona/Memory 的优先级不变；修改配置或记忆下次立即生效，不保留旧前缀来提高命中数字。

相关 42/42 测试与 Core 固定 25/25 回归通过；这验证装配和隔离，不证明真实命中率增加或模型质量提高。

## R1.3 首轮预算与输入精简

自动预算仅对官方 DeepSeek 端点启用 `max_tokens`；未知兼容端点默认不发送不确定参数。可设置服务端 `AI_OUTPUT_TOKEN_PARAMETER=max_tokens` 或 `max_completion_tokens` 显式适配，`off` 关闭参数。输出上限不是每次实际生成量，更不保证节省相应百分比。

| 业务 | 默认输出上限 |
|---|---|
| 聊天、AI 任务 | 8192；最新输入明确要求详解时提升至 16384 |
| 新闻 | 3072 |
| 书籍、娱乐回合 | 6144 |
| 反思、复习卡 | 2048 |
| 背诵评分 | 1536 |
| 解题 | 8192 |
| 世界创作（整稿 / 多部分，`world-authoring`） | 16384 |
| 世界创作（单部分，`world-section`） | 8192 |

推理模型的预算如何覆盖思考和正文以实际服务商定义为准。仅DeepSeek官方的分支摘要提取、世界整稿 / 单部分结构化生成显式关闭思考，避免思考用量挤占完整JSON；普通聊天 / 游戏 / 人物对话不自动切换，兼容Provider不发送未知的思考参数。可用 `AI_OUTPUT_TOKEN_BUDGETS_JSON` 按业务覆盖上限（256–131072）；如模型允许的最大值更低，应按该模型规范自行调整，不自动重试被拒请求。自托管示例：`AI_OUTPUT_TOKEN_BUDGETS_JSON='{"chat":16384,"game":8192,"world-authoring":16384,"world-section":8192}'`。世界专用键优先于显式`game`键；不配置专用键时仍尊重已有`game`覆盖。实际预算继续写入同一用量记录，不新增平行费用系统。

`AI_MAX_INPUT_CHARACTERS` 默认 160000，只是文本字符护栏，**不是精确 Token 限额或模型上下文窗口**。不会把图片 base64 算成 Token，不涵盖视觉输入的实际费用。超限在调用前明确拒绝，提示调整预算或新建会话，原始历史保留；不静默删除消息。模型实际窗口仍由 Provider 校验。

流式/JSON 的 `finish_reason=length` 视为未完成，记录已有 usage，明确报错且不自动重复请求；游戏和学习不会把截断 JSON 作为有效状态。没有完成标记且没有结束原因的断流也不假装成功。消费者退出时取消上游 Reader。

检索仅去除完全相同的重复证据（忽略引用编号与抓取时间），保留不同摘要、发布日期和有效原编号，不做未经验证的有损摘要。已有关联记忆预算、新闻去重和普通提醒零模型调用继续复用；没有新增整段回答缓存，避免过期/跨模式/跨分支结果复用。

运行 `cd web; npm run eval:cost` 可复现七个无网络、无模型结构样例：短问答、长对话、历史重新生成、联网证据、定时新闻、学习、娱乐。报告只给字符数、共同 JSON 前缀长度和配置预算，真实输入 Token/缓存 Token/费用均为 null。不能把这个报告当作模型分词或计费实验。

## R1 尚未完成的验收与后续

R1.1/1.2 的实现与 R1.3 首轮预算已交付，但 **R1 整体尚未按原规划封版**：

1. 真实短/长/分支/搜索/任务/学习/娱乐场景的费用与质量对照未执行。可先通过正常使用积累 usage；如做额外付费实验，先核对实际模型价格与用户允许的总费用上限。
2. R5.4已交付同一套“用户审核分支摘要 + 近期原文”，源节点/hash、模式/模型/策略和个人依赖失效、清除/分支隔离及完整原文回退已实现。一个高重复合成真实对照保留预算/期限/待办，成功首用¥0.018618高于原文¥0.013384；同条件约2次复用摊薄成功生成，计入首轮失败则约6次，不能外推真实长期净收益。默认关闭/不自动收费，使用及证据见 [摘要指南](BRANCH_SUMMARY_GUIDE.md)、[报告](https://github.com/Ghostzerox/agent_web/blob/ebaeecbf67dfc03e34065d25e68d51f005177095/docs/reports/R5_4_REPORT.md)。
3. 精确分词、额外应用检索缓存按基线显示的收益再选；当前不能承诺所有兼容 Provider 的缓存命中率、固定节省比例或完全相同的自然语言答案。

R1 阶段当时的验证：全量 125 文件/427 项测试、Core 25/25、TypeScript、ESLint、生产构建通过；新增预算/装配/审计复测 28/28，Docker 生产服务 Edge E2E 26/26，Debug APK 构建通过。完整历史证据见 [历史索引](HISTORY.md)；当前验收边界和排序以产品主线为准。华为手机的声音与通知不是本次验收对象。
