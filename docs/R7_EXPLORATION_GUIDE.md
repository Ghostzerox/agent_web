# R7：叙事探索实现指南

状态：2026-10-18，R7.1–R7.7 首期工程已交付；真实模型的叙事体验和华为真机仍待用户集中验收。此版本是一个完整可玩的区域，不是无限世界、多人游戏或开放世界 3D 引擎。

用户粗描述驱动的世界 / 道具 / 人物 / 事件创作及完整人物认知隔离，已登记为 [R10待排期规划](ENTERTAINMENT_CREATION_AND_CHARACTER_PLAN.md)，不属于本页已交付能力。

R10.2现已交付语义输入和主持 / 人物请求隔离；本页记录R7基础玩法，人物调用、记忆和输入的当前规则以 [R10.2指南](R10_ACTOR_ISOLATION_GUIDE.md) 为准。[R10.3世界创作](WORLD_CREATION_GUIDE.md)已可发布单区域新世界；[R10.4道具 / 人物设计](ITEM_CHARACTER_DESIGN_GUIDE.md)已接入，抽卡 / 复杂事件设计与完整事件知识传播仍待后续阶段。

## 进入与游玩

1. 打开 `/entertainment` → “世界与存档” → “大世界探索 · 选择模板” → 选择模板，阅读背景、玩家定位、玩法侧重与内容规模 → “确认创建探索存档”。浏览简介和切换选择不会创建存档。旧 `?session=…` 链接仍直接进入对应存档。
2. 点击“开启探索世界”。创建、启动和所有普通结构化动作不调用模型。
3. 在地图点击相邻地点；调查兴趣点会开放线索、地点或一次性物品。未知地点不会提前显示名字；并非地图上所有已知节点都能从当前位置直达。
4. 背包可以装备 / 卸下、消耗、按数量交易或赠送。赠出剧情物品不可自动收回，可能影响选择；按钮会要求确认。交易前显示钱币费用，装备槽不能重复占用。
5. 人物页可以直接交谈、选择已解锁话题、明确承诺、协助与交涉。NPC 可以拒绝；有些回应和个人卡内容需要先建立条件。玩家卡、NPC 与重要角色分别标记。
6. “自由 AI 对话”展开后输入台词并发送才调用模型。底部“你的行动或台词”是自由主持叙事，也会调用模型；普通聊天没有付费模型配置不妨碍地图、交易、事件等确定性玩法。
7. 事件页显示阶段、条件与成本；关键决定确认后保存。可以拒绝参与故事弧，结局不强制唯一。检查点或“从此处分支”可尝试另一条路线，不覆盖原记录。
8. 历史页的近期年表可按关键词和人物查询更早祖先记录；结果保留来源，查询结果的“查看来源回合”滚动到对应回合，不修改当前存档。JSON / Markdown 导出仍用原文件适配器。

首个模板 `fog-harbor@1.0.0`：1 世界 / 1 区域 / 6 相连地点、3 名 NPC（其中一名可晋升重要角色）、另列玩家、4 种物品定义、2 个装备槽、3 类事件各 1 个、1 个故事弧与 3 种明确不同的结局。更多内容可作为新模板版本注册，不让旧局自动切换。

## 兼容契约（R7.1）

`GameState.exploration` 是可选的 `exploration.v1` 扩展，内部 `schemaVersion: 1`；模板另用语义版本固定。旧 `game-state.v2` 规则包、d20、树形回合和 JSON export v3 不变，不对历史快照批量写回或悄悄转换规则。新玩法通过显式开启操作进入。

评级（危险 / 能力档位）、品质（物品制作）、等阶（世界位阶）使用三个独立有序字典，等级是等阶内 1–10 的有界进度，不等于成功概率或经验公式。普通移动 / 查看 / 对话不要求掷骰。

静态模板仅在服务端注册；快照只保存运行状态与已发现的公共投影，不保存主持秘密。重要性与控制者分别建模，玩家不当作 NPC。探索道具、承诺、任务和历史不接入现实 Task / Persona / Memory；真实提醒仍需原有草稿确认。

地图、库存、事件结算由宿主确定性执行；AI 只处理局部叙事 / 对话，不可直接改探索状态。快照沿父回合产生，CAS 和请求回执复用已有原子 appendTurn，检查点不删除历史。

## 数据、模块与调用路径

```text
娱乐工作区 / 本地 React
  → 既有 POST /api/v1/game-sessions/:id/turns
  → 严格 explorationAction + requestId + expectedVersion + parentTurnId
  → GameTurnService：重放回执 / CAS / 分支父状态
  → exploration/engine：校验相邻、持有、数量、条件、成本、事件阶段
  → 可选一次局部 AI 对话，严格空 statePatch；失败不保存任何候选变化
  → 原 appendTurn 事务：回合 + JSONB 快照 + activeLeaf + version
```

没有新增数据库表或迁移，生产仍为 34 份迁移。运行态在后端 PostgreSQL `game_turns.state_snapshot.exploration`，检查点保留对应快照，不在浏览器充当数据库。沿用 `game_sessions` / `game_characters` / `game_checkpoints`；旧 `game_events` 继续只表示骰子 / 规则检定，探索事件和年表带来源回执存入探索快照，不伪造旧事件类型。

| 文件 / 部件 | 职责 |
|---|---|
| `web/lib/game/exploration/contracts.ts` | 严格动作 / 状态 / 人物 / 物品 / 字典 DTO |
| `templateTypes.ts` / `characterFactory.ts` | 通用模板契约与中性人物初始值，不包含雾港剧情 |
| `templateRegistry.ts` / `validateTemplate.ts` | 通用版本注册、隔离副本、启动配置与交叉引用校验 |
| `catalog.ts` / `templates/fog-harbor/world.ts` | 前者只组装服务端注册表，后者独立保存雾港地图、角色、开场、钱包与事件规则 |
| `engine.ts` | 纯状态归约、公共投影、库存守恒、NPC 交互、事件和史诗推进 |
| `templateCatalog.ts` / `templates/fog-harbor/public.ts` | 客户端可读目录与无剧透简介；不导入私有世界定义。`preset.ts` 仅保留旧名称兼容导出 |
| `prompt.ts` | 局部 NPC / 主持上下文与 `r7/exploration-v1` 提示词 |
| `history.ts` | 从祖先快照合并去重、按人 / 地点 / 类型 / 来源 / 关键词查询，保留首次出现回合 |
| `ExplorationTemplatePicker` / `GamePlayPanel` / `ExplorationPanel` | 通用选择器、动态简介、局部五页签、明确动作与费用提示、草稿、分支和来源定位 |
| `gameTurnService.ts` | 复用幂等 / CAS / 事务；可选模型输出验证后才提交 |

地图、物品、人物、事件 ID 及模板版本必须存在，唯一物品不能复制，独立装备不能堆叠，消费不能为负，已结束事件不能再奖励。交易的钱币转入 / 转出商人钱包，事件奖励另作有来源的模板发放；商人库存仅到场后生成一次，不因刷新或消耗复活。

NPC 的重要性独立于 `user / ai / shared`；晋升保留 ID。公开卡包含身份、阵营、外貌、性格、表达、目标、价值、边界、能力、关系与原因、已交流信息、承诺、近期记忆、未解事项和个人线，只有达到模板条件才开放更深内容。NPC 的移动与态度由行动 / 事件驱动，没有定时模拟服务。

## 历史、分支与模型预算

- `history.kind` 区分 `fact / rumor / legend / opinion`，`origin` 区分 `setting / play`，保留地点、相关人物、事件、原始来源 / 请求回执。既往史料被发现不等于当下才发生。
- 当前工作年表最多 200 条，完整记录仍在不变的祖先回合快照中。`POST /api/v1/game-sessions/:id/exploration/history` 是只读查询，不新建回合；仅沿指定 `parentTurnId` 的祖先检索，不能读兄弟分支。最多 20 条 / 6,000 序列化字符，默认 15 条，超出范围明确报 `omitted`，属于关键词检索而非向量 RAG。
- 主持动态公开上下文最多 14,000 字符，超出按完整结构降级，不从 JSON 中间截断；近期最多 6 对对话，每对玩家 800 / AI 1,200 字符。字符预算不是实测 Token 或费用。
- 指定 NPC 的 AI 对话不传玩家私下史料、其他人物卡或全世界目录，只传此人公开卡 / 已交流信息 / 记忆和本次主动告知。模型不能访问模板隐藏内容。
- 普通动作、等待、地图展示、事件推进和历史查询均无需模型。模型只回 `narrative` 与空 `statePatch`，任何非空补丁拒绝整个回合；本次失败不会扣除候选物品 / 成本或升级关系。付费请求若已发出，输出不合格也可能已计费，不自动重试。
- 模型自由文本不能创建模板未支持的新物品、交易或事件；涉及确定状态的意图需要在结构化动作中确认。叙事质量、NPC 自然度不由契约测试证明。

## 兼容、扩展与明确限制

### 通用框架与具体模板分层（R7 调整）

- 引擎负责动作、库存、公共投影和分支状态；开场、初始玩家 / 钱币 / 档位、商人钱包、等待文案和承诺完成时要消除的未解事项由模板声明。通用界面从当前人物的公开 `offeredPromise` 读取承诺，不再固定提示“寻找镜片”。
- 公开介绍和私有世界定义分开维护；简介可展示背景、扮演身份、玩法、规模与特色，不展示隐藏人物线索、未发现地点或结局答案。创建请求只提取原有会话字段，不把简介元数据发给严格创建 API。
- 新增世界时，在 `templates/<id>/world.ts` 实现 `WorldTemplate` 并注册到服务端 `catalog.ts`；在同目录 `public.ts` 实现 `ExplorationTemplatePresentation` 并加入公开 `templateCatalog.ts`。正常情况下不需要修改引擎或在界面添加世界名称判断。
- 启动按选择时保存的 `templateId@templateVersion` 解析，不自动升级旧局；旧客户端省略启动版本时从会话标记补齐。已有快照保持 `schemaVersion: 1`，新增承诺展示字段可选，无数据库迁移。增加版本时必须保留仍被存档引用的旧定义；缺失版本会明确报错而不覆盖存档。
- 目前正式目录仍只有“雾港与旧灯岬”一个模板；不同世界 / 多版本隔离由纯测试用的“风铃营地”验证，测试世界不在用户目录发布。这不是第三方模板上传、热加载或插件市场。

- 旧 d20 和 `quick-adventure` 插件仍使用原 `game-state.v2`；新探索是宿主注册模板，声明 `exploration.v1`，**不是已开放第三方上传世界包或新的插件权限**。Plugin API v1 不变。以后可按验证器约束注册更多模板，或再设计明确的安装 / 迁移流程。
- JSON 导出外壳仍为 v3，探索扩展自行带状态 / 模板版本；Markdown 增加探索记录并保留完整分支快照。导出不是一键导入恢复接口，也不包括服务端未揭示的整个静态模板。
- 现有玩家基础卡在探索启动时复制到分支；修改基础卡不追溯改写探索快照。探索“从开头分支”从世界起点节点开始，不把空根变成旧规则混合局。要采用不同的初始卡，创建新局并在开启前修改。
- 首期的拒绝、条件、贸易和结局由可审查的模板规则约束，AI 做自然对话，不是自主生成无限新区域 / NPC 的模拟器。复杂战斗、制造、多人、离线游玩 / 离线同步均未实现。
- 当前 Repository 仍整局加载回合；工作上下文有限，但超长局的数据库分页 / 冷归档留待实际规模需要，不宣称无限存档无成本。
- Web 与本地 Capacitor React 共用此界面，历史来源滚动不改 hash 路由。本轮不重新打 APK、不进行真机；原生分享 / 系统返回 / 键盘 / 跨设备操作进入 [统一真机待办](DEVICE_ACCEPTANCE_BACKLOG.md)。
