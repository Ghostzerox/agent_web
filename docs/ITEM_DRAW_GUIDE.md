# R10.4.1：抽卡与材料获取

2026-10-19。固定池与关键词生成池共用已发布世界、原探索引擎、背包、回合树及Provider，不新建材料背包或游戏服务器。

## 怎么使用

1. 娱乐 → 我的世界 → 所选世界。先完成世界结构；固定物品先在“道具设计”纳入世界定义，不必配置初始实例。
2. “卡池配置”子页添加卡池和固定 / 生成条目，可混合。填写来源解释、地点、最早探索回合、虚构钱币成本、分支次数上限、是否放回、权重和数量。
3. 生成条目预先指定类别、品质、等阶、评级及轻数值世界的等级。类型与品质的联合权重由每条配置表达，不让模型决定概率。只有非唯一材料允许一次多份；其他生成类别每次一件。
4. 审阅概率与规则，勾选确认后保存。再从“预览与发布”确认发布，创建新存档并开启探索。**旧局不会自动获得新卡池**；改变旧局的世界修订不在本期范围。
5. 存档内“获取 / 抽卡”进入独立子页。可先选历史父回合，形成新剧情分支；页面标明来源回合、世界修订和余额。
6. 查看本分支有效概率，填写可选关键词，勾选单抽 / 成本确认，再点击“抽取一次”。此时只保存抽样回执，**不调用模型、不扣游戏资源、不发奖**。
7. 固定池可直接审阅入库。生成池可先手动填写并保存设计，也可明确接受API费用后补全；公开背景、用途 / 限制与高级JSON折叠编辑。品质、数量、类别等宿主抽样不可改写。
8. 勾选审阅确认，执行“确认获得”：在同一事务中发放 / 堆叠、扣除虚构钱币、写入来源回合与结算回执。装备不自动穿戴，材料与其他物品共用背包。返回链接直接打开背包；后续移动、装备、消耗、赠送仍走同一引擎。

当前自定义世界初始钱币为0，可先用0成本池体验；也可通过后续交付的[事件设计器](EVENT_CREATION_GUIDE.md)明确设置虚构钱币奖励，再按卡池成本扣款。这不代表新增充值或完整经济系统。

## 概率、库存与唯一性

- 权重必须为非负整数；0不参与，至少一个正权重。先排除不可用条目，再按剩余权重归一，因此界面同时给出当前条件概率，不伪称固定永远不变的概率。
- 数量在上下限内均匀抽样，使用已有 `fnv1a-mulberry32-v1` 随机工具；服务端生成种子并保存结果。工具用于可复现的个人虚构游戏，不用于博彩或安全随机。
- 不放回：本分支同一卡池的条目只结算一次；放回仍受卡池总次数上限约束。唯一条目不会因放回获得副本，已消耗 / 转赠的唯一物品也不能借重复抽取复制。
- 固定池获取的是明确允许的定义，不是偷走NPC库存或读取任意世界物品。世界中已配置初始实例的唯一定义不能再复制，即使初始实例尚未出现在玩家视野。
- 品质、等阶、评级、等级必须属于该世界字典；禁止超自然、有界属性、装备槽和使用前置复用道具设计校验。自然语言的工艺 / 背景一致性仍须人工审阅，不把结构校验当语义证明。
- 本期只给玩家发放；无自动装备、合成、拆解、保底、充值、现实付费抽卡或批量抽取。每世界至多8池、每池20条、每次至多99份、每池每分支至多100次；分支生成目录至多50项、获取回执至多200项，满额不静默删除审计记录。

## 刷新、失败与恢复

数据库保存请求ID、指纹、所属存档 / 父回合、抽样时会话版本、固定池规则 / 世界修订、种子和结果。重复请求只读取原回执，同ID换内容会拒绝；页面提供固定链接和历史恢复入口。

```text
抽样 → 固定条目就绪 ───────────────────┐
     → 生成条目待设计 → 手动保存 / AI补全 → 就绪 → 确认 → 同事务入库 + 扣款 + 新回合
                         ↓失败                    ↓取消
                   保留抽样，显式重试 / 手动修复      无发奖 / 游戏扣款
```

模型调用前先持久认领尝试ID，跨服务实例的同次请求也不能重复调用。每抽最多三次**明确确认可能费用**的尝试；失败不会自动换ID、重抽品质、降级伪造成功或循环重试。实际费用沿用原模型用量账本；游戏资源未扣除不代表API退款。

若服务在已认领后中断，结果可能未知，保持“生成中 / 等待回执”，刷新不接管重试。可继续重读或明确取消；取消后迟到结果也不会发放。取消 / 停止等待不保证已经到Provider的请求免费或立刻停止计算。确定失败的草稿可手动修复，不必重新抽样。

会话在抽样后发生任何版本变化（包括其他设备推进、暂停、创建 / 恢复检查点）会阻止旧回执结算 / 再生成，保留查看或取消。此为保守并发边界，不悄悄将待处理草稿移到另一个分支。若只在本页刷新而存档未变化，原回执仍可继续。

分支与检查点只恢复所选祖先快照。生成物品定义和使用效果保存在该分支的获取目录；未写回全局模板，其他分支不会继承库存 / 扣款 / 定义。回执的来源链接仍保留，不承诺跨分支全局唯一或防读档。关键词、抽卡记录和道具背景不会自动写入NPC感知或现实记忆。

“来源回合的请求记录”是该起点的操作审计，可保留从同一父回合开出的不同结果回执；“所选分支已入库记录”则只按当前快照实际继承的回执列出。查看曾经结算的回执不代表恢复检查点后仍持有该物品，实际持有以所选分支背包为准。

## 代码与数据归属

| 部分 | 位置 / 职责 |
|---|---|
| 配置与共享契约 | `web/lib/game/draws/contracts.ts`；世界草稿可选 `drawPools`，明确确认后保存，编译到不可变修订 |
| 宿主随机 | `draws/pools.ts` 复用共享随机源，资格筛选、条件概率、加权与数量抽样 |
| 设计 / 验证 | `draws/items.ts` 复用 `worlds/assetContracts.ts` / `assetValidation.ts`；`draws/generation.ts` 只为已抽定内容拼装有限公开世界上下文 |
| 持久回执与事务 | `repositories/gameDrawRepository.ts` + `game_item_draws` JSONB；锁顺序为会话→回执，复用原 `appendTurn` 事务 |
| 分支目录 | `exploration/contracts.ts` 的可选 `acquisitions`；`runtimeItems.ts` 将已确认公开定义合入原引擎的本次解析，不改变发布模板 |
| UI | `DrawPoolWorkspace.tsx` / `DrawSessionWorkspace.tsx`；创作配置与存档实际获取分开，Web / React共享 |

API均为 `no-store`：`GET /api/v1/game-draws?sessionId=…&parentTurnId=…`，`POST /api/v1/game-draws` 抽样，`GET /:id` 恢复回执，`PATCH /:id` 保存手动设计，`POST /:id/generate` / `settle` / `cancel` 显式操作。客户端不能提交任意世界模板、抽样品质、数量或库存补丁。

0036只追加抽卡表与会话所有权关联索引，不更新原世界、回合或旧设计稿。发现已有卡池 / 抽取 / 分支获取数据会拒绝有损降级；升级前备份，恢复流程见 [数据库手册](DATABASE_OPERATIONS.md)。本期没有新增依赖。
