## 怎么使用

1. 在聊天输入区上方展开“分支摘要”。默认关闭，不自动生成或收费，查看时才请求摘要状态。
2. 默认当前分支至少 16 条消息后，可点击“生成/更新摘要（收费）”，确认向你配置的模型发送较早分支原文。保留最近至少 6 条原文，覆盖在 AI 回答边界结束，避免切半个回合。原始消息不删除。
3. 生成后查看目标、约束、决定、未决事项、历史陈述、不确定项，以及各点的逐字证据。核对是否遗漏数字、否定、更正和待办；模型/代码不能替你证明摘要忠实。
4. 点击“已核对，允许本页使用”。摘要在数据库保存审核状态，但是否复用由本页会话开关控制，刷新默认关闭；也可手动打开开关复用已审核的有效摘要。
5. 后续发送/重新生成按当前所选用户节点校验，使用“摘要 + 未覆盖原文 + 最新问题”。界面展示最近请求的使用/回退说明及估算上下文变化；Prompt 导出准确标记 compressed 和覆盖元数据。
6. “清除摘要”删除本对话所有派生摘要，不删除消息、不退回已经发生的模型费用。摘要生成中断后若保留 pending，不会自动重跑收费；明确清除后再生成，晚到的旧结果不会写回。

摘要只接普通聊天树（含娱乐聊天）；R5.5对其按模式特化，独立 GameSession/后台任务/插件仍使用各自可信结构化状态，不自动共用这份摘要。它不读取其他会话或兄弟分支补故事，也不自动修改Persona或创建长期记忆。

## 什么时候能复用

- 完整覆盖节点必须是当前真实祖先路径的连续前缀，节点 ID、parent、role、status、正文 hash 全部一致；公共祖先可跨新分支复用，包含旧兄弟回答的摘要不可以。
- 模式、策略版本、生成模型/Base URL、摘要设置及 Persona/个人记忆版本元数据均参与指纹与有效性校验。记忆到期也改变有效性；娱乐聊天不读取个人记忆/Persona 元数据。
- 数据库消息正文/父节点/角色/状态编辑或删除，通过触发器清除该对话的全部摘要文本；删整个对话级联清理。模式/配置变化拒绝使用旧摘要，用户仍可清除派生记录。
- 在未覆盖消息中遇到“更正/纠正/撤回/取消之前”等明确措辞时保守回退。它不是通用矛盾检测：表达隐含更正时请关闭/清除旧摘要，近期原文仍优先。更正仍在近期窗口时，重复生成可能返回相同覆盖记录，不能假装已总结那条新更正；继续用完整历史即可。
- 用户必须审核 draft 才能使用。无有效摘要、摘要不更短时回完整分支；输入超预算则明确拒绝并保留历史，不默默删除消息。源在调用前变更时返回冲突，不自动再花钱重试。

生成每次都从当前原始消息重新计算，不把“摘要的摘要”当权威。摘要中的 evidence ID 是历史消息定位，不是本次网络/知识资料 `[S]` 证据，也不证明内容最新。历史回答若原已包含被删除资料的文字，仍属于历史正文，资料删除不追溯清除这些历史副本。

## 实现与数据

```text
显式生成 → 拓扑元数据选祖先 → 只读祖先正文 → 较早完整回合
  → 指纹去重/生成占位 → 一次限额模型调用 → JSON/逐字来源/长度检查
  → draft → 用户审核 → approved
下一次请求 → 验证覆盖前缀/配置 → 摘要 + 未覆盖原文
  → PromptRun 事务复核 → Provider
```

- `lib/conversation/summary.ts`：策略 `branch-summary/r5.4-v1`、真实祖先/环和长度校验、节点 hash、结构化目标/约束/决定/未决/事实/不确定项及逐字证据检查。证据存在不等于总结语义一定正确。
- `conversationSummaryRepository.ts`：owner 校验、先拓扑后正文、公共前缀复用、生成占位/失败/版本/审核、事务复核、清除。每对话最多保留 24 份，超限明确要求清除；不建立新 Agent/向量/摘要服务。
- `conversationSummaryApi.ts`：GET 查看、POST 显式收费生成、PATCH 带 expectedVersion 审核、DELETE 清除，路径 `/api/v1/conversations/:id/summary`；旧客户端不传 useSummary 继续原流程。
- POST settings 可设 threshold（10–100）、recent（4–20）、maxCharacters（1,000–12,000），且 threshold > recent+1；UI 首期采用默认 16/6/5,000。单条点最多 600 字、证据最多 3 条、总点最多 12；输入沿现有预算、输出沿 `context-summary` 预算默认 2,048 Token，90秒超时，不自动多轮生成。
- 官方 DeepSeek 摘要调用使用 JSON Output + 非思考；只针对摘要，不改变普通聊天，也不给其他兼容接口强塞厂商参数。首测确有思考占满预算导致截断，依据 [官方参数说明](https://api-docs.deepseek.com/api/create-chat-completion/) 修复，并保留失败费用。
- 新表 `conversation_summaries` 保存原始节点 ID/hash、模型/策略/模式/设置/依赖指纹、结构化摘要和审核状态；原文仍在 messages。它是私人派生数据，不加密成无法查看的黑盒，也不记录到默认日志。
- `prompt_runs.summary_usage` 仅记 ID/指纹、覆盖条数和估算前后 Token，不重复存摘要正文。Prompt Envelope 的 `source: summary` 默认导出脱敏，显式包含私人上下文才导出摘要。
- 迁移 `0030_conversation_summaries.sql` 增表、审计列和源变更触发器；当前完整迁移清单以正式 SQL 为准。已备份/隔离恢复/up/down 演练；down 会删除摘要数据，生产需先备份并单独批准，不用 `down -v` 清库。
- 旧首尾截取与 contextCompressor 空兼容壳已退出；真正的摘要只有本套实现，不新增第二套 R1 压缩器。

## 成本和质量限制

离线手写摘要仅估算 Token，不证明真实质量。真实模型对照使用一个固定合成长对话：摘要和原文两种回答均答对预算/期限/待确认项，且保留“不创建真实任务”限制；并非盲测、全部语义保真或用户体验签收。

按 [2026-10-16 官方人民币高峰价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 和真实 usage 保守核算：成功摘要 ¥0.012352，原文回答 ¥0.013384，摘要回答 ¥0.006266；首用合计 ¥0.018618，高于仅原文回答。若后续条件相同，约复用 2 次可摊平成功生成成本；计入首轮失败则约 6 次。缓存命中、输出长度、重新生成、价格都会改变结果，不是省钱保证。

本轮累计 ¥0.057700（包含失败及对照调用），总预算余额见 [台账](PAID_TEST_BUDGET.md)。真实探针凭据留在 Docker，只发送合成文本；普通单元/浏览器测试全为模拟模型。R1 整体生产净收益仍未封版。

不自动清除已导出文件、旧备份、其他客户端已打开摘要或已发远端请求；事务提交后的删除不能撤回请求。更复杂长对话、隐含更正、高密度约束和真实使用收益仍需持续验收。R5.5宫殿与R5.6用户控制工程已交付；后续顺序见 [产品主线](PRODUCT_MAINLINE_GUIDE.md)，真机继续统一暂缓。
