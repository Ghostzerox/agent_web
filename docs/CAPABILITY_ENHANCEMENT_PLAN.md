## 1. 基线与本轮边界

代码检查显示已有：

- `web/lib/agent/modeRegistry.ts`、`promptBuilder.ts` 与 `web/lib/ai/promptEnvelope.ts`：模式、分层 Prompt、版本/导出基础。
- `web/lib/search`、`web/lib/ai/responseVerifier.ts`：受控搜索和引用/规则检查。
- `web/lib/game/dice.ts`、`checks.ts`、`state.ts`：可复现骰子、检定与分支状态；不是从零新增骰子。
- `web/lib/memorization`、`web/lib/problemSolving`：材料/复述评分、简单复习间隔与算术校验；需要增强数据组织、抽背与拼写，而不是复制一套学习系统。
- `web/lib/memory/memoryRetrieval.ts`：正式记忆的关键词/中文二元组检索，默认最多 5 条、估算 500 Token；不是已接入向量 RAG。
- `web/lib/agent/contextCompressor.ts`：旧式首尾片段截取，不能视为已完成分支感知、可验证的长期摘要。
- `web/lib/plugins`：插件隔离存储、受控生成与任务草稿三个能力；声明了工具名称不等于存在可调用、已获授权的工具。

新增范围分为 R3 提示词、R4 工具、R5 记忆。每个模块都要完成能力盘点，但不要求为每个按钮增加模型调用。不能确定性完成的语义任务才使用模型；设置、通知投递、概率计算、数据查询等优先普通业务服务。

保留已有凭据保护、用户确认、插件授权和虚构隔离。系统性的发布前安全评测仍在 Phase 5.6；这里不新增独立安全平台，也不把这些最小边界推迟到上线后。

## 3. R3：按任务优化提示词

### 3.1 设计与技术规范

1. 建立 Prompt 清单：实际调用入口、任务目的、输入来源、输出格式、允许工具、记忆策略、失败回退和固定案例。审查生成器、插件模型适配与后台任务，不能只改聊天模式说明。
2. 版本化保存紧凑的任务模板与少量高价值例子；沿用当前优先级和结构：不可覆盖规则 → 模式/工具/人格稳定层 → 本次授权记忆/证据/摘要 → 当前分支近期消息/任务。不为统一模板而打乱角色、引用和工具结果语义。
3. 将“表达风格”和“任务执行规范”分开：陪伴影响语气，不降低专业性；反思不能把所有回应变成追问；娱乐虚构只在游戏边界内成立。
4. 写明成功标准、缺失信息处理、必要澄清和可执行下一步，不要求模型输出隐藏思维过程。结构化结果继续走 Zod/领域校验；不以“提示词要求遵守”替代代码执行。
5. 自己编写优先；借鉴公开工程指南/开源模板须记录地址、许可证（复制代码/模板时）、固定版本或日期、适配理由和修改。不复制与当前工具不符的整套角色卡/超长 System Prompt。
6. R3/R4/R5 配置、工具描述、检索策略与 Composer 版本要关联，导出准确反映实际发送内容；不将完整 Prompt 或用户资料新增到默认审计日志。
7. 复用 R1 用量/费用元数据与稳定前缀；只提供当前任务相关的工具/示例/记忆，禁止为缓存命中率填充无用内容。

## 4. R4：全模块工具补全与优化

### 4.1 实现约定

沿用模块化单体、TypeScript/Zod、现有 Repository 与 Capability Gateway。宿主业务服务、模型可请求工具、插件 Capability 是三种接口，不等同；工具接入不意味着开放任意代码或任意网络。

候选最小描述符示意（不是已存在接口）：

```ts
type ToolDescriptor = {
  id: string; version: string; description: string;
  inputSchema: unknown; outputSchema: unknown; // 实现时绑定类型化 Zod schema
  allowedScopes: string[]; // 模式/模块范围，服务端再次校验
  effect: "read" | "compute" | "draft" | "write";
  timeoutMs: number; maxResultBytes: number;
};
```

实现时为执行上下文补齐 owner、plugin/session/branch、request/run ID；写入需 expectedVersion 与幂等键。默认不记录正文，返回结构化错误及是否可重试。随机结果、调度结果与评分计算由工具产生，模型负责解释，不得自造骰子点数、抽牌结果或已保存状态。

- **确定性与事务**：随机抽背在同一抽测批次不重复；抽卡保存牌堆/弃牌堆和每次抽取事件，明确放回/不放回、权重、耗尽/重置与规则版本。重复请求不能重新掷骰或重复扣资源；并发靠事务/版本保护。
- **随机性边界**：现有骰子是用于回放的种子伪随机；训练/娱乐可复现不等于可用于博彩或安全用途。生产抽样与测试种子策略分别说明，概率/洗牌用代码验证，不由语言模型决定。
- **学习规则**：逐字、允许同义复述、英文大小写/标点/音标等规则可配置；展示插入/删除/替换与原文定位。拼写差异不等于语义评分，模型建议与确定性结果分别显示。
- **工具可发现性**：先提供用户显式操作或既有工作流内的工具。模型驱动执行是后续受限增量：仅开放当前模式允许的工具，限制步数/费用/失败重试，不因为新增工具默认启用自主循环。
- **插件兼容**：先复用 v1 的三个既有 Capability；新增能力需要单独兼容审查/ADR 与明确授权，不能假装已对 v1 插件全部开放，也不默默把写操作塞进读取接口。

## 5. R5：记忆库、记忆宫殿、RAG 与摘要

### 5.1 记忆不是一个大文本框

```text
原始事实来源：消息 / TaskRun / 学习记录 / 书籍笔记 / 游戏事件
  ├─ 个人记忆库：用户确认的资料、偏好、目标和事件
  ├─ 知识资料库：用户选择导入的材料、章节、题目、规则与来源
  ├─ 模块记忆：学习掌握度 / 推荐反馈 / 游戏分支状态等
  └─ 派生索引与摘要：分块、关键词/向量、压缩摘要
       → 按授权范围检索 → 去重/限额 → 带来源上下文 → 本次任务

记忆宫殿：领域/房间/位置 → 可解释的记忆与来源导航
          位置/联想/路线 → 学习知识点和抽测记录
          不替代上述事实来源、检索索引或模型上下文。
```

记忆宫殿兼顾两种用途：为用户提供分领域、可追溯的 AI 记忆导航；为背书提供位置联想与路线回忆训练。两者共用关联视图但数据范围不同，必须区分人类的记忆训练与 AI 的上下文管理。“把全部记忆放进虚拟房间”不会自动解决模型记忆容量，也不代表掌握了材料。

### 5.2 分域与数据设计

默认按 owner → 模块/数据集 → 会话/分支过滤；未来多人迁移不得仅在 UI 筛选。个人已确认偏好可按任务授权复用；游戏虚构、学习错误推断、网页指令默认不能成为全局用户事实。

| 数据层（候选） | 内容与关键字段 | 生命周期 |
|---|---|---|
| 现有 Memory / Candidate / Usage | 继续复用确认、类型、有效期、版本、来源及实际使用记录 | 编辑/过期/删除立即影响下一次检索，不放宽自动保存 |
| KnowledgeCollection / Document / Chunk | scope、来源/位置、内容 hash、材料版本、分块方式、解析状态、引用锚点 | 导入/更新可增量处理；失败显示原因，原文可追溯，不把全文放入单条 Memory |
| MemoryLink / 目标与事件关系 | 两端 ID、关系类型、证据/用户确认、所属域 | 不用一次建设图数据库；关系随源变更失效或重新确认 |
| RetrievalIndex / Embedding | 源 ID/版本、模型/维度、索引代次、处理状态、更新时间 | 可重建的派生数据；换模型/维度需新代次，不能混合比较 |
| ConversationSummary | 会话/分支、覆盖节点与内容版本、来源 hash、策略/模型版本、待办/未知、Token/费用 | 沿当前分支验证；编辑/重生成/源删除后失效，原始消息保留 |
| Palace / Room / Locus / Route | 用途、所属域、房间/位置/顺序、记忆/资料引用、联想说明、版本与作答关联 | 首期普通列表/卡片和路线，不做 3D；空间隐喻和联想不保存为现实经历事实 |

这些是设计候选，不是已建立的表。R5.1 决定哪些直接复用现有字段/插件存储，确需 Schema 时才分别交付 Drizzle 迁移、备份和回滚，不一次创建全部表。

### 5.3 RAG 检索设计

1. 先建立授权资料导入、分块、来源与中文查询基线。初期文本/Markdown；PDF/OCR/网页解析按实际需求另拆，保留位置/页码与解析失败信息，不承诺导入任意格式。
2. 查询先确定任务和可信作用域，再检索；在数据库/检索层过滤 owner、数据集、模块和活动分支，不能先跨域召回再靠 Prompt 隐藏。
3. 先增强现有词项/中文分词与元数据检索；PostgreSQL FTS 的中文分词能力需实测，不假设默认配置解决中文。用同义改写、缩写、无答案、旧版本与越域问题建立基线。
4. RAG 不等于向量库。语义召回确有漏检、收益可测后再接 Embedding；优先评估在现有 PostgreSQL 中加 pgvector，而非默认另起向量数据库。Docker 扩展安装/镜像兼容、迁移与回退须单独验证。
5. 向量适配器记录 Provider/模型/维度/价格与版本；Embedding 服务可选本地或外部，发送用户资料和新增费用前明确征得同意。不假设当前聊天 Base URL 提供兼容的 Embedding 接口。
6. 可采用词项 + 向量的混合候选合并、去重和轻量重排，再按模块预算选择片段；付费重排器不是默认必需依赖。相似不等于可信，可信来源/版本与相关性独立判定。
7. 生成仅引用实际选中的有效片段；无相关证据明确说明，个人资料检索不足时不自动上网泄露查询。索引不可用时降级词项检索并提示，不伪造“已查到”。
8. 记录选中来源 ID、检索版本、耗时/预算及回退，不默认复制敏感正文到日志。用户可查看本次用了哪些资料；删除/更正需同步处理索引、缓存和派生摘要，旧索引在完成清理前也必须不可检索。

### 5.4 压缩与总结

- 与 R1.3 共用一个分支摘要实现，不另做竞争性压缩器。R1 是成本验收，R5.4 是数据/失效与连续性验收，最后互相引用同一份交付证据。
- 输入结构是“可验证的当前分支摘要 + 近期原始消息 + 本次相关记忆/证据 + 工具状态”。保留用户最新问题、关键约束、未决事项与来源定位；不能截取首尾几句话冒充完整总结。
- 阈值、覆盖范围、最大摘要量、模型/策略版本和调用预算可配置；不每轮收费重写，不递归压缩后丢失原始来源。
- 新分支仅可复用覆盖其祖先且源版本相符的摘要；切换、编辑/删除来源、纠正事实或策略变化时验证或失效，禁止混入兄弟分支剧情/回答。
- 摘要是派生材料而非事实权威；模型推断不自动升级成正式记忆。失败/超长/无法验证时显式回退或请求缩小范围，不静默丢消息，也不盲目自动重试。
- 汇总输入/输出、Embedding/摘要/重排/重试费用、命中与延迟；估算和实测分开，不仅比较主回答 Token。

### 5.5 模块专用策略与记忆宫殿

专业问答偏重证据版本与检索；陪伴偏重经确认事件/偏好和时间线；反思偏重目标/行动/反馈；新闻偏重时效和去重；书籍偏重章节/笔记/进度；任务偏重状态与执行结果；背书/解题偏重知识点和错误历史；游戏偏重可见分支的权威状态与 NPC 信息可见性。不能把一种检索预算或摘要模板硬套所有模式。

记忆宫殿首期有两个入口：

- **AI 记忆导航**：按生活/学习/项目等用户可编辑领域显示“房间”，位置关联已确认记忆、目标事件或授权资料；点击查看来源、实际检索使用与冲突/过期状态。修改布局不修改原始事实，不跨越模块权限，也不改变 RAG 的过滤规则。
- **学习助记**：用户选择已导入材料 → 确认知识点 → 建立房间/位置与联想 → 按路线回忆或随机抽测 → 展示漏点/拼写差异 → 记录复习结果。AI 生成联想是可修改建议，原文始终可打开；材料修订后提示更新关联，不静默把旧答案判正确。

首期不做自动 3D、VR 或泛化知识图谱；采用同一套轻量关联组件，以不同作用域展示两种用途。

## 6. 推荐执行顺序与短长期目标

2026-10-15 初次修订将新任务加入主线；随后按用户指令交付了 R3.1 清单/离线基线与 R3.2 对话/问候模板，其余步骤仍待开发。不要先连续做多个空框架阶段：

1. **短期：可见改进**。R3.1 清单与基线，随后 R3.2 对话模式优化；同步以最小工作流确定 R4.1 工具契约和 R5.1 分域策略，不阻塞提示词先行改进。
2. **下一批：工具闭环**。R3.3 与 R4.2–R4.4 按“专业/任务与内容 → 学习 → 娱乐”小批配对交付；优先材料管理/抽背/拼写和既有骰子增强/抽卡，而非一次安装所有候选库。
3. **中期：连续记忆**。R5.2–R5.4 推进知识库/RAG/摘要，承接 R1 未完成项；根据真实召回决定是否进入 Embedding，不把已规划语义检索悄悄删掉。
4. **后续：特化与收尾**。R5.5 记忆宫殿与模块策略、R4.5 剩余工具盘点，然后 R3.4/R5.6 集成验收；将分批已做的测试汇总，而非到此时才开始测试。
5. 保留 R1 费用验收、R2 视觉/华为真机与移动/语音发布待办；最后仍执行 Phase 5.6 发布前安全封版和 Phase 8 作品集化。新任务不意味着老验收已完成。

长期仅按实际需求评估：更丰富资料格式、语义重排、更多学习方法/规则包、可视化关联。暂不承诺全自主 Agent、第三方插件市场、图数据库或 3D 记忆世界。
