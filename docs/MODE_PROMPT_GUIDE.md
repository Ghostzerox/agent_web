# R3.2：对话模式与主动问候模板

日期：2026-10-15。实现已更新；人工/真实模型质量对照尚未执行。本轮自行编写紧凑的中文任务规范，不复制外部角色卡、不换 Provider、不新增模型调用。

## 1. 改动目的与范围

R3.1 固定了提示词调用清单和离线基线。本轮开始实际修改四种对话模式和共享 Persona，并润色现有规则驱动的主动问候：

| 模式 | 原先不足 | 新的明确要求 |
|---|---|---|
| 自动 | 较抽象地要求调整语气 | 先完成当前请求，简问短答，关键条件才澄清；不强行心理分析或每轮提问 |
| 专业 | 只有“结构化、可核查”原则 | 先给结论/已知部分，按需要补理由和例子；说明假设、不确定性、数学符号与核验方法，不伪造引用/运行/搜索 |
| 陪伴 | “温和、关注感受”缺少互动细节 | 回应具体事情，短轮次；只想倾诉时不急给计划，不猜经历/人格；允许不行动和温和不同意，不能为安慰歪曲事实 |
| 反思 | “少量高质量问题”不够具体 | 一次一到两个贴合情境的问题，检查假设/证据/取舍或最小行动；承接已回答内容，要求直接回答时不再反问 |
| 共享 Persona | 高主动性/详细偏好可能与本次请求冲突 | 明确默认偏好让位于当前任务/格式/篇幅，不必每轮以问句结束；只承接当前分支和提供的记忆 |
| 主动问候 | 正文重复天数/开关设置，较机械 | 正文是简短邀请，允许不回应；触发原因继续单独保存在 rationale 中 |

运行代码：`web/lib/agent/modeRegistry.ts`、`web/lib/persona/personaProfile.ts`、`web/lib/proactivity/proactivityPolicy.ts`。

未改核心事实/高风险 Policy、模式 ID、Persona 配置值、搜索开关、任务调度、插件授权、记忆确认或游戏规则。娱乐聊天的模式指令原文不变，但共享 Persona 更新也会作用于它；独立 GameSession 及新闻/书籍/学习模板留给 R3.3。

Policy → Mode → Persona → 已授权上下文 → 当前分支消息的既有契约保留。R1 的稳定前缀和缓存友好顺序保留，没有额外塞入大型 few-shot 示例或把所有模式一起发给模型。Prompt 版本描述本轮装配协议；旧客户端仍携带其已打包的旧模式文本，因此 APK 需要覆盖安装新版，不能仅更新服务端就宣称旧 APK 的全部模式规则已更新。

## 3. 主动联系为何继续不用模型

主动联系现在由明确的目标/未互动信号和用户设置触发。R3.2 只改已经会发送的文案，不增加开放式 Agent 或收费生成路径：

- 关闭、暂停、静默时段、日上限、冷却、未读联系与原因白名单/当日去重全部沿用。
- 目标跟进只引用现有信号中的已确认目标，不声称知道用户今天的进度或心情。
- 正文允许继续一点或休息，用户不方便/不想回应时无需解释；不使用负罪感、依赖或“为什么不理我”。
- `rationale` 继续解释开关和触发原因，Inbox/通知投递逻辑不变。

这也明确了 R3.1 的 G3：先优化确定性模板；如果未来需要个性化生成，另做受控需求，不在这一步悄悄增加后台 Token 开销。

## 4. 基线变化与成本边界

- 原始 `web/evals/r3/baseline.json` 保留不动；新 `baseline-r3.2.json` 独立保存本轮快照。
- `npm run eval:prompts` 默认检查当前快照，同时打印 `comparisonToR31`：原 31 个样例未删除、定义未改；旧请求只有 8 个聊天样例变化，其他任务/学习/游戏请求不变。
- 新增 `modeQualityScenarios.ts` 的 20 个正常场景，四种模式各 5 个，涵盖同一事实问题、只倾诉、直接回答、格式约束、资料不足、少量反思问题等。总样例 51 个，其中 38 正常/13 边界；仍是模拟依赖的拼装/合同检查。
- 当前跟踪 19 个源文件，新增覆盖主动联系文案与导出兼容。源码 hash 包含非模板代码，漂移需要审查，不自动等同质量变差。
- 主动联系不新增生成次数；专业等模式的固定规则文本有增加。旧样例的输入文本字符变化如下，不等于真实 Token 或费用：

这是为明确行为边界付出的文本预算，不宣称本轮节省 Token。真实净费用、响应质量/自然度、事实正确率需按 R3.1 的同配置人工评审和预算同意后实测；离线分数不证明模型会准确执行每一句要求。

## 5. 使用与体验检查

网页刷新后，在当前会话选择相应模式，再发送新问题；不会自动改变会话模式或历史回答。APK 的模式模板打包在本地，需要安装本轮 APK；主动问候则由更新后的服务端 Worker 使用新正文。

可以尝试：

1. 在自动/专业/陪伴/反思都问“请直接回答：2+2等于几？不要追问”，看是否简洁一致。
2. 陪伴：“今天很累，只想说说，不需要计划。”检查是否先倾听，而不是给一串安排。
3. 反思：“我每周只有九十分钟，想读书又想练英语，帮我想清楚取舍。”检查是否少问、问具体。
4. 专业：“解释 f(x)=x² 的导数，说明符号和条件。”检查推导和可核验性。
5. 不必为验收主动开启问候；现有关闭/暂停继续有效。若本来启用，观察正文是否自然、是否仍可忽略。

这些属于用户实际体验，不是本轮已测过的真实回答。继续沿用 R3.1 的人工评分口径和未测标记；下一步 **R3.3：新闻/书籍/定时任务/背书/解题/娱乐模板与工具说明**。
