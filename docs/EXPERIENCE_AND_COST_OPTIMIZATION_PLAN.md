## 1. 目标与边界

1. 降低真实模型费用：尽量减少无用输入/输出，提高可复用前缀的缓存命中；不能以丢失重要上下文或降低专业回答质量换取指标。
2. 提升日常使用体验：各模式布局清晰、视觉统一，切换入口容易找到，手机正文获得足够空间。

2026-09-30 的初始交付仅为规划；2026-10-01 起实施 R1，新增 0027 用量元数据迁移，但没有主动发起真实收费基线测试。后续实现沿用小任务自检、审查、测试、提交和推送流程；文档任务做文档检查，业务任务按风险选择测试，不为无关改动重复全量构建与部署。

## 2. R1：Token 与缓存优化

### R1.1 用量观测与基线

覆盖聊天、AI 定时任务、新闻/书籍/反思、背诵评分、解题与娱乐回合的实际模型入口，优先复用现有 Provider 和 Run 审计，而非新增独立监控平台。

- 记录 Provider/Model、业务类型、调用数、输入/输出 Token、首响应和总耗时，以及 Provider 返回的缓存命中/未命中 Token；取消、失败、重试和摘要调用也纳入可观测范围。
- 实现前核对实际使用的 Provider 官方缓存规则、usage 字段、流式 usage 支持与计价口径。不假设 OpenAI-compatible 接口支持相同缓存能力，不擅自发送服务商特有参数。
- 区分服务商实测、客户端估算和缺失值。缺失 usage 不显示成 0；分词未知时只能标为估算，不用固定字符比例冒充精确 Token。
- 缓存命中率仅在 Provider 明确口径下计算，以命中输入 Token 占可比较输入 Token 的比例呈现，同时报告绝对输入量与总费用；不能仅按“有过缓存的请求数”判断收益。
- 费用按可配置、注明来源/日期的价格估算，考虑缓存输入、普通输入、输出及服务商实际计费类别。未配置价格显示未知，不写死当前模型价格。
- 采集不记录 Key 或完整对话/Prompt；记录最小用量元数据。若需修改 Schema，应另交付迁移与回滚。

基线场景至少包含短问答、长对话续聊、历史分支重新生成、联网专业回答、定时内容和学习/娱乐调用。同模型、同配置对照多次运行；真实 API 基线必须明确费用并获得用户同意，日常自动化回归仍以无付费 Mock 为主。

验收：形成优化前基线及数据完整性说明；未测量前不承诺固定节省百分比。

### R1.2 缓存友好的 Prompt 装配

先检查 `web/lib/ai/promptEnvelope.ts`、服务端 Provider 装配以及各业务生成器；只在真正调用处优化，不只修改导出文档。

- 保持 Policy/Mode/Persona/Memory 的语义优先级和专业/陪伴/娱乐隔离。能稳定的规则、模式说明、工具描述采用确定性的文本、顺序和序列化。
- 将频繁变化的检索证据、当前时间、当前消息和临时状态置于合适的动态区域；仅用于审计的 Run ID、时间戳等不注入稳定前缀。确需时间语义的新闻/任务仍保留必要日期。
- 对话的共同前缀尽量复用；不通过移动消息、合并角色或改写历史来制造缓存命中，不把其他分支内容加入请求。
- 配置或 Prompt 版本变化应自然生成新前缀，用户修改 Persona/记忆下一次请求立即生效，不为了缓存继续使用旧配置。
- 不把所有模式合并成巨大 System Prompt；只装配当前所需规则、工具与插件能力。不增加无意义填充，不发送定时“预热”收费请求。
- Provider 特有缓存能力若值得接入，通过小型能力适配进入；不支持时仍能正常回答，缓存过期或首次冷请求均为正常状态。

验收：相同配置的稳定前缀一致性有测试；模式/权限/记忆契约回归通过；支持缓存的 Provider 记录重复请求实际收益，无法观测时明确写“未知”，不宣称命中。

### R1.3 上下文、输出与应用缓存预算

- 按模型窗口和业务建立输入/输出预算，预留回答空间；输入不得直接截掉用户最新问题、关键约束或结构化状态。
- 长对话采用“经验证的摘要 + 当前分支近期窗口 + 相关记忆”。摘要保存覆盖节点、模型/策略版本和失效条件；重新生成、切换分支、编辑/删除来源或相关信息变化时重新计算，不复用其他分支摘要。
- 摘要只在超过阈值且预计收益足够时生成，计入它自己的 Token 与调用费用；保留原始数据以便恢复。摘要失败时安全回退，不静默丢失历史事实。
- 去重和精简检索材料，只保留相关证据及来源关联；不要丢失引用所需证据、新闻时效、书籍依据或娱乐角色/规则状态。
- 为简单问题、新闻简报、背诵评分、解题讲解和游戏回合设不同输出预算；允许用户明确要求详解。不为了节省输出使公式、JSON 或状态补丁被截断；处理长度终止并避免盲目重复生成。
- 普通提醒、规则校验和简单确定性计算继续不用模型；不增加第二模型“每次压缩/每次判分”的固定成本，减少重复检索、自动重试与无必要调用。
- 区分“Provider 前缀缓存”和“应用数据缓存”：后者优先考虑重复读取/检索，不默认缓存整段个性化回答。按 Provider/Model、模式、配置版本、分支、检索条件和所需时效定义适当缓存键、TTL 与失效；Key 更新隔离凭据作用域，不保存原始 Key。
- 用户修改/删除记忆、任务或配置后相关缓存失效；新闻/时效问题不返回过期材料，手动刷新可绕过应用缓存，专业/陪伴/虚构数据不串用。

验收：固定对照场景报告输入/输出、缓存 Token、总调用、摘要/重试费用、总估算费用与延迟；先基于 R1.1 确定量化目标，再验证收益。长对话在可优化场景减少输入和净费用，关键回答/引用/分支正确性不退化；冷请求、缓存失效和不支持缓存的 Provider 也可正常使用。Core 固定回归与真实体验结果分别报告，不以确定性满分证明事实正确。

## 3. R2：全模式 UI 与切换入口优化

### R2.1 导航与统一视觉规范

先梳理现有页面与聊天模式选择器，以及 `web/lib/platform/appNavigation.ts` 的路由/深链契约。专业、陪伴、反思是对话行为模式，学习与娱乐有独立活动；入口统一不代表把它们的数据或后端状态混在一起。

- 提供统一可发现的专业/陪伴/反思/学习/娱乐切换入口，清晰显示当前模式，避免每页堆满所有功能按钮。
- 桌面优先稳定侧栏/分组导航；手机采用紧凑入口、抽屉或更多菜单。先比较导航草图再确定底栏/顶部位置，不预先把所有入口强塞进底栏。
- 手机隐藏历史列表后正文占主要空间；模式切换、历史、新建和设置各自语义明确，常用操作不必返回首页寻找。
- 明确“切换页面”与“改变当前对话模式”的差异：保留会话、游戏和表单草稿；未保存内容有提示；正在生成时沿用安全取消/继续策略，不误把流式结果写入另一会话。
- 保留 Web 浏览器返回、APK Android 返回、通知深链和插件启停后的入口处理。切换不触发新模型请求、创建游戏、保存任务或改动记忆。
- 统一颜色、字体、字号层级、间距、圆角、按钮、表单、卡片、对话气泡、弹层及反馈状态，沿用 React/Tailwind 和共享组件，不另建 Android UI 业务。
- 图标配可理解的标签或无障碍名称；清晰的选中态、焦点与对比度，不只用颜色区分模式。主要触控目标至少约 44×44 CSS px。

验收：桌面与 390/360 px 手机可识别当前模式、到达主要模式并返回；模式切换不卡住、无数据丢失或误调用。提供导航草图和改前/改后截图供用户确认。

### R2.2 按体验逐页打磨

| 页面/模式 | 优化重点 |
|---|---|
| 专业/陪伴/反思聊天 | 阅读宽度、输入区、键盘避让、模式当前态、历史抽屉、来源与检查信息折叠；公式/代码独立横向滚动，不撑宽整页 |
| 任务与 Inbox | 创建/编辑入口、任务时间和周期、循环滚轮、暂停状态、结果预览、通知诊断的主次关系 |
| 阅读与反思设置 | 推荐理由、来源、偏好表单、目标和数量控制；区分内容结果与配置入口 |
| 记忆、Persona、主动联系、语音 | 简化长表单、分组设置、保存/试听反馈，突出用户控制；不改变原有开关默认值 |
| 学习与插件 | 活动入口、启用/授权反馈；背诵材料/复述/评分和解题输入/讲解/复习卡形成清晰操作步骤 |
| 娱乐与规则包 | 区分创建配置和进行中的游戏；叙事为主，角色/状态/骰子/检查点/分支按需展开 |
| 首页、API 配置、通知与通用设置 | 统一入口和表单反馈，Provider/Base URL/Model 保持可编辑；设置页不暴露完整 Key |

所有页面统一处理加载、空状态、未连接服务端、插件禁用、无权限、保存冲突和失败重试；已有错误要可读且可恢复，不能只为了好看把错误隐藏。

验收：逐页检查清单有结果，每批复用组件并附代表截图，不仅优化聊天而遗忘学习/娱乐与设置页面。

### R2.3 跨端回归与封版

- 浏览器桌面及 390/360 px 视口验证；覆盖聊天/公式/树形分支、任务滚轮、Inbox、插件权限与学习、游戏创建/切换、配置保存。
- 检查长文本、分数/复杂公式、代码、空列表、多按钮、加载/错误状态；页面不能整体横向溢出，长公式允许组件内横向滚动。
- 检查键盘导航、焦点、弹层关闭、屏幕安全区与软键盘布局；Web 模拟与真机分别记录。
- 构建共享 Web 与本地 React Bundle/APK，确认路由不分叉；华为/卓易通实际安装后的键盘、返回键、滚轮和通知点击单列验收，不把浏览器模拟等同真机通过。
- 优化完成后记录遗留问题和可接受范围，不扩大为整套新前端框架或 UI 业务重写。
