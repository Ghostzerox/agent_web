# R10：娱乐创作系统与人物认知隔离

- 创建日期：2026-10-19。
- 状态：**R10.1–R10.3 已实现；R10.4–R10.6（含 R10.4.1）待实现**。不改变既有发布 / 真机待办的状态；基线见 [R10.1](R10_SEMANTIC_BOUNDARY_BASELINE.md)，当前使用与限制见 [人物隔离](R10_ACTOR_ISOLATION_GUIDE.md) / [世界创作](WORLD_CREATION_GUIDE.md)。
- 优先级以 [产品主线](PRODUCT_MAINLINE_GUIDE.md) 为准；现有能力见 [R7探索指南](R7_EXPLORATION_GUIDE.md)。

## 1. 目标与现状

让用户从几句话的创意出发，设计可游玩的世界、道具、人物和事件，通过抽卡获取道具 / 材料，同时让人物在世界规则内自然行动：不知道未见未闻的秘密，不读取玩家内心，也不把旁白当成玩家说的话。

R7 已有框架 / 静态模板分离、地图、物品 / 装备、人物卡、局部人物对话上下文、确定性事件结算和分支存档。R10 不是重做这些系统，而是补上创作、确认发布和人物认知的完整链路。现有局部上下文不等于完整的感知 / 知识传播系统；静态模板登记也不等于支持用户生成世界直接运行。

首期只做一个可游玩区域的创作闭环，再扩展多区域；不承诺无限世界、全 NPC 实时模拟或新的通用游戏引擎。继续以叙事、品质 / 等阶和明确交互为主，不自动退回重数值、频繁掷骰的玩法。

## 2. 共用创作流程

粗略描述 → 读取所选世界约束 → 结构化草稿 → 冲突与完整性检查 → 用户编辑 / 局部重生成 → 预览 → 明确确认 → 发布定义或应用到当前存档。

- 区分用户明确设定、AI 补充和待确认假设；保留原始描述。只对影响玩法或世界规则的关键缺失提问，不要求先填长表单。
- 可锁定已经满意的字段；局部重生成不悄悄覆盖锁定内容。取消、失败、费用不足保留原草稿和现有存档，不自动重复付费请求。
- 草稿不是世界事实，发布定义不等于发放道具或触发事件。涉及当前存档的改变须另行确认，并由宿主校验 / 结算。
- 发布时固定世界定义修订号；已有存档仍引用原修订，不因编辑世界设定自动改写过去。当前存档若需采用新设定，应显式预览差异、校验并确认；有存档引用的定义不能直接删除。
- 只支持当前规范的结构化数据，不生成并执行 JavaScript / TypeScript，不新增永久旧格式兼容链。实际升级时设计必要的一次性数据迁移，不清空用户数据。

## 3. 世界观设计系统

输入可以只有一句话，例如“一个靠记忆交换魔法的海港，偏探索，不要战斗数值”。系统补全以下内容，并明确哪些是建议：

| 内容 | 设计要求 |
|---|---|
| 世界基调与边界 | 主题、时代、技术 / 超自然规则、能力代价、禁止出现的设定、内容边界；优先服从用户硬约束 |
| 社会与背景 | 地理、势力、文化、历史因果、经济 / 物品来源；不只堆背景名词 |
| 可游玩区域 | 起点、相连地点、发现条件、交互点、关键人物和初始事件；能进入现有探索循环 |
| 规则字典 | 按世界定义评级、品质、等阶及可选等级，不混淆物品品质和人物能力 |
| 数值策略 | 明确为无数值 / 轻数值 / 指定数值；无数值世界不强加伤害、血量或战力面板 |
| 公开与隐藏内容 | 玩家可见简介、主持秘密、初始人物所知分别保存，不用一个完整设定文本传给所有角色 |

遇到“绝无魔法”与生成的魔法道具等冲突，应指出冲突并提供修改选项，不能为了补全而覆盖用户约束。世界发布前验证地图连通、引用存在和至少一条可玩的交互路径。

实现时需增加用户世界定义的持久化和解析入口，与现有静态模板共用同一领域契约、校验器及引擎。仅保存一段世界介绍或一份未被引擎消费的 JSON，不算完成。

## 4. 道具设计系统

支持用户提供道具的部分描述，也可选择系统提供的半成品创意再补全。必须绑定所选世界 / 修订，生成以下内容：

- 名称、外观、类别、品质、来源、制作 / 历史背景、所属势力或文化关系。
- 效果、使用条件、限制、代价、可交互对象、装备槽或消耗规则；叙事效果也应有明确边界，不生成“万能解决器”。
- 按世界数值策略补属性：定性世界用特性 / 代价描述，数值世界只能用已声明字段、单位和范围。品质高不等于任意越过世界等阶。
- 区分“道具定义”和“库存实例”：设计完成不自动入包、不自动装备、不自动扣款。确认放入世界、分配给角色或作为事件奖励时，才创建相应实例 / 归属。

宿主校验唯一物品、数量、所有权、装备槽及前置条件；重试不能重复发奖。跨世界复用先重新适配并确认，不把不相容属性原样带入。

### 4.1 材料定义与库存

材料作为物品的一种类型，复用道具设计 / 库存契约，补充来源、品质、用途标签、堆叠与数量规则；可以描述用于制作、修复或交易，但本期不因此自动扩大为完整合成系统。已有材料或生成材料都须符合当前世界和数值策略，不另建一套平行材料背包。

### 4.2 抽卡获取道具与材料

新增娱乐内的抽卡系统，支持两种来源，也可在一个卡池中按明确权重混合：

| 来源 | 抽取方式 |
|---|---|
| 世界已有内容 | 从当前世界允许获取的道具 / 材料定义中抽取；定义存在不代表可无限复制，仍检查唯一性、库存、地点 / 剧情解锁和所有权 |
| 关键词生成 | 用户提供或选择关键词，例如“月光、旧时代、炼金材料”；先由宿主确定类别 / 品质 / 数量及约束，再调用现有道具设计流程补全新定义，不另造生成器 |

抽卡是获取机制，不必强加为每个世界的超自然能力。世界可将其解释为寻宝、物资箱、交易补给等，或明确为场外奖励；有设定冲突的关键词先提示修改，不能借抽卡绕过“无魔法”等硬约束。抽中后如何出现在世界中须有已确认规则，NPC 不会自动知道抽卡记录、生成关键词或道具隐藏背景。

- **卡池与规则**：配置世界 / 修订、可用条目或生成主题、类型 / 品质权重、数量范围、是否放回、重复与唯一物品处理、抽取次数和虚构资源成本。规则与概率在抽取前可查看；首次创建 / 修改卡池需确认。不默认引入保底、充值、现实货币或商业化付费抽卡，若以后需要保底再单独规划。
- **随机与生成分开**：服务端按已确认卡池执行抽样，模型只设计抽中的生成内容，不决定概率、改品质或擅自奖励。优先复用现有 [游戏工具](TOOLS_GUIDE.md) 的随机 / 牌堆能力和会话事务，仅补真实缺少的加权抽样 / 物品结算；现有牌堆抽牌不等于已完成道具获取系统。单抽先闭环，批量抽取复用同一流程并限制条目数和模型费用。
- **确认与发放**：抽取前确认次数 / 成本 / 规则，保存请求标识、卡池修订和抽样结果。固定池不调用模型，直接校验后结算；生成池展示待确认草稿，确认后才将生成定义、合法实例 / 堆叠和虚构资源扣减一并落库。材料进入同一背包，装备不自动穿戴。
- **失败与重试**：生成失败、取消或未通过世界校验不扣虚构资源、不发放半成品，但真实 API 已产生的费用不能视为退还。持久化待处理结果，防止刷新 / 重试重新抽品质、重复付费生成或重复领奖；重试有界且提示可能的费用，不悄悄循环调用。创作视图允许另存编辑稿，但不能借局部重生成无限抬高已抽定的品质 / 数量。
- **分支与追溯**：记录来源条目或关键词、已抽定类别 / 品质、生成定义、接收角色和来源回合；同一分支同一请求仅结算一次。沿用当前分支 / 检查点语义，不承诺跨分支全局唯一或防读档；切分支不能把另一分支的库存、成本或未完成抽卡混入。

卡池编辑属于创作工作台；实际抽取与结果 / 入库记录属于所选存档的“获取 / 抽卡”子页，与背包互相链接。详情 / 概率 / 历史折叠展示，不在全局导航增加孤立抽卡入口。

## 5. 人物设计与认知边界

### 5.1 人物必须属于世界

人物生成绑定世界规则，核对年代、地点、能力上限、势力身份、道具来源与历史。区分普通 NPC、重要角色和玩家；重要角色增加经历、动机、价值观、说话方式、需求、关系、秘密和长期目标，不只是加长外貌介绍。

设计者可查看完整人物卡，但运行时给人物的卡片只是她自己的必要部分。人物秘密不是其他人物的公共资料，玩家内心和操作意图也不是 NPC 已知事实。系统不代替玩家确定思想、台词或关键选择。

### 5.2 世界事实不等于人物知道

分开管理世界真相 / 主持秘密、公开可观察结果、各人物的已知 / 传闻 / 推测 / 误解。知识记录至少关联来源事件、获知方式、时间、人物、世界及分支；“听说”不能自动提升为事实。

人物可以通过在场观察、实际交谈、可信记录或有依据的推理获知信息。远处发生的事件不会自动传入所有人物脑中；需要有观察、消息传播或后续告知。允许人物猜错、追问、隐瞒和改变看法，但不能把未知秘密当成确定事实。

### 5.3 输入与记忆必须区分语义

| 类型 | 如何处理 |
|---|---|
| 台词 | 保存说话者、接收对象、场景 / 通道；只有听见或收到的人获得内容 |
| 动作 | 先确定动作结果和可观察范围；看到结果不等于知道动机 |
| 世界变化 / 主持旁白 | 更新相应世界事实或叙事记录，不自动记录为“玩家说了……” |
| 私人想法 | 默认只有所属人物 / 玩家与必要主持上下文可用，其他人物不得直接读取 |
| 场外创作指令 | 进入设计 / 管理流程，不冒充角色发言，也不直接写为游戏内既成事实 |

界面提供清楚的输入类型 / 对话目标；自由输入有歧义时先确认关键含义。存储、摘要、检索和导出都保留类型，不能只在画面上换标签。特别审查现有把自由输入统一写为“玩家说”的对话记忆路径，避免旁白经摘要重新泄漏给人物。

## 6. 主持与人物的调用隔离

**不强制不同 API、不同模型或不同供应商。** 同一模型可以使用独立请求与严格过滤的上下文；换接口但仍发送全部设定 / 历史，不会阻止全知或读心。

| 职责 | 可获得的信息 | 不应承担的职责 |
|---|---|---|
| 创作器 | 用户描述、当前待设计内容及必要世界约束 | 未确认就改变正在玩的存档 |
| 主持 / 事件规划 | 当前分支的权威世界事实、相关隐藏规则和条件 | 把完整世界秘密直接交给人物；替玩家做决定 |
| 人物发言 | 自己的卡、已知信息、可感知结果、当前交流和有权检索的记忆 | 读取其他人物秘密、玩家想法、全局历史和其他分支 |
| 宿主结算 | 规范动作、前置条件、定义引用和当前版本 | 不经校验直接执行模型给出的任意状态修改 |

实现重点是服务端按世界 / 存档 / 当前分支 / 人物构建不同的请求 DTO 和上下文投影。上下文过滤必须在调用前完成，覆盖直接 Prompt、历史、检索、摘要、工具返回和结算结果；不能先把全局秘密送进模型再要求“假装不知道”。角色身份和读取范围由服务端验证，不接受客户端自报的全量上下文。

优先复用现有 ModelProvider 和会话服务，按真实职责拆开上下文构建及调用目的；只有契约确有需要才增设路由。不引入多 Agent 框架、第二套事件引擎或一名 NPC 一套 Provider。默认一次交谈只调用目标人物；主持确定性结算不必再调用模型，不让所有 NPC 每回合各生成一遍。

## 7. 事件生成系统

依据当前地点 / 时间、世界规则、人物目标、关系和已有历史生成事件建议，而不是无条件随机制造危机。支持探索发现、社会互动、交易 / 委托、人物个人事件、世界变化和有门槛的史诗事件，并关联世界年表。

- 结构化草稿包含起因、前置条件、参与者、发现 / 知晓范围、可选行动（包括拒绝）、后果、成本、奖励和失败 / 替代路径。
- 区分“可能发生的事件”“已触发”“已解决”与历史记录。生成建议不等于世界已经发生，也不等于每个人已经知情。
- 不凭空强迫人物违背动机、令物品违反规则、重复发放唯一奖励或推翻已确认结局；冲突先提示修改。
- 用户确认后由宿主检查引用、条件、合法状态变化与当前存档版本，原子写入事件 / 回合 / 后果；重试幂等，分支来源可追溯。
- 已确认的自动触发规则可按条件执行，但规则本身须先确认。首期不做无界后台自主世界模拟，也不把虚构事件同步为现实任务、Persona 或现实记忆。

## 8. 页面归属与技术范围

娱乐 → 世界与存档 → 所选世界的“创作工作台”，分别链接世界设定、道具 / 材料、人物、事件、卡池配置子页；游玩页面通过存档内“获取 / 抽卡”子页抽取，只保留必要入口，不把所有编辑器塞到一个界面或全局设置。

每个子页先展示简介 / 当前版本 / 草稿状态，细节与高级设置可折叠。明确区分设计视图与角色视角、草稿与已发布内容；可预览某人物“目前知道什么、来自哪里”，但诊断用隐藏信息不得混入实际人物请求。

复用现有 Repository、领域校验、JSON 传输、树形回合、确定性工具和 Web / 本地 React 共享业务。新增的设计草稿、世界定义修订、人物知识 / 感知记录与事件计划在实现对应功能时再设计实际持久化结构；不提前建立空表、空 Provider 或重复记忆平台。游戏记忆继续独立于现实记忆，分支检索不能跨到兄弟分支。

成本遵循 [Token指南](TOKEN_COST_GUIDE.md)：稳定规则前缀、相关上下文按需读取、有界输出和局部重生成；不得为了缓存命中率把无权知道的信息拼进人物请求。真实调用须使用合成题并遵守 [累计付费预算](PAID_TEST_BUDGET.md)，不自动追加额度。

## 9. 子任务与完成标准

以下是依赖顺序，已完成项单独标记；其余按用户指令启动。各批次按实际消费者落地，不以空接口或仅增加 Prompt 宣称完成。

| 子任务 | 交付与验收重点 |
|---|---|
| R10.1 语义与边界基线（完成） | [语义规范 / 调用审计 / 合成基线](R10_SEMANTIC_BOUNDARY_BASELINE.md)；交付时15项现状通过、13项目标样例TODO；后续按所属阶段接入 |
| R10.2 主持 / 人物隔离（已实现） | [语义输入 / 感知来源 / 人物请求](R10_ACTOR_ISOLATION_GUIDE.md)贯通回合、存储、导出与双端界面；P01–P08可执行，P09–P13仍TODO；有界近期记忆，不冒称长期总结或完整世界模拟 |
| R10.3 世界创作闭环（已实现） | [工作台](WORLD_CREATION_GUIDE.md)：服务端草稿、整稿 / 局部生成与锁定、连通 / 引用 / 政策校验、确认发布、固定修订新存档；定性 / 轻数值起始区域与现有引擎消费闭环，不含任意指定属性或复杂设计器 |
| R10.4 道具与人物设计 | 绑定世界约束补全、局部重生成、重要角色卡；定义与实例分离，确认后纳入世界 / 存档，并接入 R10.2 认知边界 |
| R10.4.1 抽卡与材料获取 | 在道具 / 材料设计与库存之上增加固定 / 关键词生成卡池、宿主抽样、待处理回执、确认发放与分支记录；复用现有牌堆 / 随机工具 |
| R10.5 事件创作与生成 | 条件 / 因果 / 可见范围 / 选择 / 后果结构化；用户确认、宿主结算、知识传播、分支历史与幂等闭环 |
| R10.6 集成与质量验收 | Web / React 完整创作→游玩 / 抽卡入库链路、真实请求内容检查、语义质量与成本对照；真机仍并入统一待办 |

R10.1 定义边界，R10.2 在当前玩法验证隔离，R10.3 为 R10.4–R10.5 提供用户世界来源；R10.4.1 依赖 R10.4 的物品生成和库存结算，纳入 R10.6 总体验收，不改变既有子任务编号。各步只增加当步实际需要的结构。完整范围封版前至少覆盖：

1. 无魔法 / 无数值等硬约束不会被补全绕过；锁定字段保持；冲突可见；取消或生成失败不改变当前世界。
2. 同一道具在定性 / 数值世界按不同策略设计；未确认不入包，唯一物品和重复回执不重复发放。
3. 私人想法不被 NPC 当成台词；场外指令不成为事件；世界旁白不被记成“玩家说”。
