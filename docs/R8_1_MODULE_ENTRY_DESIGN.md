## 1. 设计结论

全局只保留 **对话、任务、学习、娱乐、内容** 五个业务入口，以及 **收件箱、设置** 两个共用入口。品牌返回首页，首页仅作入口目录，不是第八个业务模块。桌面和手机使用同一份入口定义；不增加全局工具、全局宫殿、全局角色卡或每种聊天行为的独立按钮。

“一个入口”指一个全局主入口，不是一个模块只能有一个 URL。通知直达、引用、模块内页签、返回与原书签继续有效，指向同一归属页面；不因此维护重复编辑器或复制后端服务。首页只列模块入口，不列训练、装备等专属操作。

### 全局与局部层级

```text
品牌 / 首页（模块目录）
├── 对话 /chat                 → 历史、行为模式、资料选择、摘要、导出
├── 任务 /tasks                → 今日、提醒、打卡/习惯、目标、日历
├── 学习 /study                → 背书、解题、学习助记宫殿
├── 娱乐 /entertainment        → 世界/存档 → 当前世界内的剧情及工具
├── 内容 /content [待实现]     → 简报、书籍、思考问题及其偏好
├── 收件箱 /inbox              → 跨模块投递结果、已读、反馈
└── 设置 /settings [待实现]    → 模型、个人记忆/资料、人格、主动联系、
                                语音、通知/设备、插件、高级工具
```

打卡与目标属于 R6；地图、装备、事件等属于 R7，不能在 R8.2 中提前做成功能页或空按钮。R8.2 只展示已可用的入口，文中的未来项仅为布局预留。

## 2. 现有页面逐项归属（19 / 19）

这里的“归属”决定全局选中项、局部导航及返回模块，不改变现有服务权限。所有既有路径保留，不需要因一级导航瘦身而更名。

| 当前路径 | 定稿归属 | 到达位置 / 处理 |
|---|---|---|
| `/` | 共用 Shell | 品牌首页；展示七个入口，不展示各模块业务控制器 |
| `/chat` | 对话 | 主入口；行为模式 / 历史 / 来源等仅在对话内 |
| `/tasks` | 任务 | 主入口；管理所有真实任务和调度，内容页只提供明确跳转 |
| `/study` | 学习 | 主入口；学习活动目录 |
| `/study/memorization` | 学习 | 背书的材料、抽测、拼写、记录与复习草稿 |
| `/study/problem-solving` | 学习 | 题库、解题、错题卡、复习草稿 |
| `/entertainment` | 娱乐 | 主入口；世界 / 存档及其角色、分支、状态、检查点 |
| `/entertainment/quick-adventure` | 娱乐 | 规则包配置 / 预览 / 确认，仍使用原 Activity 路由 |
| `/reading` | 内容 | “书籍 → 阅读画像”；不是新的书籍结果库 |
| `/reflection` | 内容 | “思考问题 → 订阅偏好”；不是反思聊天模式 |
| `/inbox` | 共用收件箱 | 主入口；结果事实源不搬走、不复制成另一套状态 |
| `/memory` | 设置 / 个人数据 | 默认长期记忆管理；子功能和学习宫殿兼容入口见下节 |
| `/persona` | 设置 / 表达与陪伴 | 人格；对话可提供“调整表达”上下文链接 |
| `/proactivity` | 设置 / 表达与陪伴 | 主动联系规则、为何联系；不等于任务打卡 |
| `/voice` | 设置 / 表达与陪伴 | 音线、试听、朗读预览；消息的朗读按钮仍在消息旁 |
| `/notifications` | 设置 / 通知与设备 | Web Push、本地通知权限 / 诊断、静默设置；任务页可给明确设置链接 |
| `/api-key` | 设置 / 模型服务 | Provider / URL / Model / 凭据及用量；不放到每个模块里复制 |
| `/plugins` | 设置 / 扩展 | 集中启用、授权、配额、审计；“打开活动”链接进入所属学习 / 娱乐模块 |
| `/tools` | 设置 / 高级工具 | 保留已有工作台作为高级入口，撤下一级全局导航；九项工具的日常入口回归各模块 |

### `/memory` 的拆分，不丢失已有能力

当前页面同时挂载 `MemoryDataControls`、`MemoryPalaceManager`、`KnowledgeLibrary`、`MemoryManager`、`MemoryCandidateManager`，其中宫殿又包含 `navigation` 和 `learning` 两种用途。不能只把整个组件移到学习页。

| 部件 / 数据 | 日常入口与责任 | 迁移要求 |
|---|---|---|
| `MemoryManager` / `MemoryCandidateManager` | 设置 → 个人数据 → 长期记忆 / 候选审核 | 对话“查看并确认”可直达候选子视图；候选不自动确认 |
| `KnowledgeLibrary` | 设置 → 个人数据 → 知识资料；对话保留同模式资料选择与引用直达 | 跨模式资料共享管理，集合模式与检索授权不变；不把所有资料变成学习材料 |
| 宫殿 `purpose=navigation` | 设置 → 个人数据 → AI 记忆导航 | 保留模块房间与已有引用；不把导航布局误删或转换成学习宫殿 |
| 宫殿 `purpose=learning` | 学习 → 助记宫殿，拟新增 `/study/memory-palaces` | 同一个组件 / 服务按用途过滤，学习页不出现个人事实房间；仍需背书授权 |
| `MemoryDataControls` | 设置 → 个人数据 → 读取控制 / 使用来源 / 导出与预演 | 范围导出可包含显式所选宫殿，属于数据管理，不是另一套训练界面 |

R8.2 拟为 `/memory` 增加 `view=personal|candidates|knowledge|navigation|controls` 子视图，默认 `personal`；这是待实现的选择规则。保留原路径，不假称现有代码已支持。专属子视图按需挂载，避免进入长期记忆页便加载所有资料 / 宫殿；切换先保护未保存草稿，不用卸载来掩盖丢稿。

旧 `/memory?palace=learning` 在 R8.2 作为学习入口别名，解析为学习归属并调用同一学习宫殿视图；不必立即改 URL、不做服务端重定向。别名必须保留查询与返回历史，不能在未确认草稿时自动跳转。无查询的旧 `/memory` 不再常驻全部编辑器，但局部菜单能找到全部原能力。

## 3. 部件归属：共享实现不等于全局展示

| 部件 | 宿主与局部位置 | 全局保留什么 |
|---|---|---|
| `AppShell` / `Drawer` / `AppLink` | 共用布局、主导航、基础弹层 | 七个入口、标题、必要连接状态；不挂载业务编辑器 |
| `SessionSidebar` / `ModeSelector` / `ChatComposer` | 对话历史 / 模式 / 输入 | 不在其他模块显示历史或模式切换 |
| `KnowledgeSelector` / `ConversationSummaryControl` / `PromptExportControl` | 当前对话的工具区 | 不把本次资料选择 / 摘要开关当成全局默认 |
| `MarkdownMessage` / `MessageSpeechControl` / `ResponseVerificationPanel` | 共享渲染实现，操作跟随对应回答 | 不增加全局朗读 / 验证业务面板 |
| `TaskManager` / `TimeWheelPicker` | 任务管理和任务表单 | 时轮可复用，但仅在编辑时间时出现 |
| `InboxManager` | 收件箱；内容模块结果链接指向同一来源 | 保留统一读状态和反馈，不新增内容收件表 |
| `MemorizationActivity` / `ProblemSolvingActivity` | 学习活动内材料 / 训练 / 记录 | 权限失败指向共用插件页，不自动授权 |
| `MemoryPalaceManager` | 按 `purpose` 分成学习训练与设置导航两个视图 | 共用服务 / 校验；不出现全局“宫殿”按钮 |
| `KnowledgeLibrary` / `MemoryDataControls` | 设置的个人数据子页 | 模块仅显示自身选择 / 引用，不复制管理状态 |
| `GameSessionManager` / `GamePlayPanel` | 娱乐内世界 / 当前存档 | 保留当前世界上下文，不把游戏任务变成真实 Task |
| `GameToolkitPanel` / `GameCheckpointPanel` | 当前世界内的牌堆 / 随机表 / 检查点 | 不在普通对话、任务或学习全局出现 |
| `GameSessionDraftConfirmation` | 娱乐创建流程 | 不因进入规则包便创建会话 |
| `NativeTaskNotificationSettings` / `NotificationSettings` | 设置 → 通知 / 设备 | 后台桥接可常驻，权限请求和诊断只在明确操作时出现 |
| `PluginManager` / `ModelCredentialSettings` / `ModelUsagePanel` | 设置 → 扩展 / 模型 | 模块显示缺少能力的提示及链接，不复制凭据 / 授权控制器 |
| `ReadingProfileManager` / `ReflectionPreferenceManager` | 内容 → 书籍 / 思考问题 | 不等于聊天模式选择；关联任务编辑仍进任务模块 |

### 九项工作台工具的日常归属（9 / 9）

`/tools` 现为 JSON 参数工作台，并能显式确认行动草稿创建提醒。R8.1 不删它，也不改现有创建行为。R8.2 保留高级兼容入口，模块内逐步使用同一执行函数 / 校验器；不因新包装而改变 `allowedScopes`、扩充插件能力或把“运行计算”变成写入。

| 工具 ID | 唯一主归属 / 日常位置 | 允许的上下文复用 |
|---|---|---|
| `reflection.action-draft` | 任务 → 目标 / 行动草稿 | 反思 / 陪伴 / 主动联系可发起草稿，保存提醒仍需明确确认 |
| `voice.preview` | 设置 → 语音 → 朗读预览 | 按原 scope 复用文本策略，不自动播放 |
| `plugins.inspect` | 设置 → 插件 → 高级检查 | 仅检查兼容性，不安装或授权 |
| `maintenance.import-preview` | 学习 → 背书 → 导入校验 | 设置高级工具可诊断；不恢复或覆盖材料 |
| `tasks.preview` | 任务 → 时间 / 冲突预览 | 学习 / 主动联系可显示本次草稿的预览 |
| `content.sources` | 内容 → 简报 → 来源检查 | 专业问答 / 阅读按原 scope 复用，不冒充已联网核实 |
| `reading.bibliography` | 内容 → 书籍 → 书目整理 | 不因 ISBN 校验成功声称书目真实 |
| `professional.calculate` | 对话 → 专业工具 | 学习复用，不作为整题证明 |
| `professional.locate-evidence` | 对话 → 资料工具 | 学习 / 阅读复用，原文定位不是事实证明 |

高级工作台属于设置的技术入口例外，不成为第六个业务模块；不通过隐藏它来删除既有工具。日常模块 UI 包装、结果回填和任务草稿流转在 R8.2 / R6 中实施，不在本阶段假报完成。

## 5. 路由、引用与返回契约

- R8.2 拟新增 `/content`、`/settings`、`/study/memory-palaces`，Web 与 MobileApp 同步登记。均为宿主页面，不为此添加伪插件 Activity 或放宽现有 Activity 路由 / 授权约束。
- 全局选中项通过“路径 → 模块 / 局部区”解析，不能只靠当前 `isWorkspaceRouteActive` 的同路径 / 子路径匹配；`/reading` 等也须选中内容，`/persona` 等须选中设置。
- 兼容 `/chat?mode=…` 的用户确认语义及 `session`；`/tasks?task=…&edit=1` 的定位 / 编辑；`/entertainment?session=…` 的选中存档。地址变化不新增消息、回合或任务，导航不视为切换游戏分支。
- **知识引用继续生成原样** `/memory?document=<id>&version=<n>&line=<n>`。`isKnowledgeCitation` / `isLocalKnowledgeUrl` 对 URL 有严格约束，不能给历史引用批量加 `view` 或换前缀。有 `document` 时优先解析为设置的资料原文视图，仍验证保存版本，不用新版内容代替旧版；与 `palace` / `view` 冲突时显示参数冲突提示而不打开其他域。
- 无 `document` 时，`palace=learning` 是学习别名；与不兼容 `view` 并存时提示冲突，不猜测并写入。普通 `view` 仅使用明确白名单。无效或重复关键参数不得扩大读取范围；旧未识别参数不触发写操作。
- `/inbox?highlight=<id>` 已由主动问候链接生成，但当前 `InboxManager` **没有消费 highlight**；列为 R8.2 的定位兼容缺口，不宣称已高亮。实现时按现有可访问结果定位，缺失明确提示，不将导航自动标为已读。
- Web 保留 path / query，APK 使用 `appHref` 的 hash 路由；局部页签用 query，不用第二层 `#anchor` 破坏 APK 路由。同一路径 query 改变也要更新局部视图，沿用草稿确认与浏览器 / Android 返回；原生先关弹层，再处理草稿。
- 模块内“返回学习 / 返回当前世界”与系统历史返回区分。直接打开旧链接时应有所属模块入口；有真实历史时用既有返回。外部 / 任意 `returnTo` 不信任、不成为开放跳转；本阶段不新增携带私人正文的 URL。

## 6. 后续实施边界与验收

R8.2：小型静态模块描述表与归属解析器、七入口导航、三项宿主路由、`/memory` 分视图、学习宫殿用途过滤、旧 query / 引用兼容、Inbox highlight 补齐及高级工具入口回收。接口 / 数据库继续复用；导航描述不是授权服务，不让 Registry 取代插件 Gateway。

R8.2 实施时检查：七个全局入口唯一、19 条旧路径可达且归属正确、3 条新宿主路径双端登记、9 工具不丢失 / 不越 scope；`document` 版本引用、学习别名、模式确认、任务深链、游戏存档、查询切换 / 草稿保留、断线与无授权反馈均有用例。未来页面新增时更新同一清单；不能以本设计清单通过替代运行测试。
